Git, GitHub & GitLab
Từ cơ bản đến nâng cao

Hiểu cách Git quản lý lịch sử, làm việc với remote, branch, merge/rebase, code review, xử lý conflict và xây dựng CI/CD.

1. Tổng quan Git, GitHub và GitLab

Git là hệ thống quản lý phiên bản phân tán, lưu lại lịch sử thay đổi và cho phép nhiều người phát triển song song. GitHub và GitLab là các nền tảng lưu trữ Git repository và cung cấp chức năng cộng tác như code review, issue, CI/CD.

2. Cài đặt và cấu hình Git

Tải Git tại git-scm.com/downloads. Trên macOS có thể dùng Homebrew; trên Ubuntu/Debian dùng apt:

# macOS
brew install git

# Ubuntu / Debian
sudo apt update
sudo apt install git

# Kiểm tra
git --version

Thiết lập danh tính commit

git config --global user.name "Nguyen Van A"
git config --global user.email "your-email@example.com"
git config --global init.defaultBranch main
git config --global --list

Muốn đặt tên/email riêng cho một repository, bỏ cờ --global và chạy trong thư mục repository đó. Email commit không phải mật khẩu.

Kết nối GitHub/GitLab qua SSH

# Kiểm tra khóa hiện có
ls -la ~/.ssh

# Tạo khóa Ed25519 nếu chưa có
ssh-keygen -t ed25519 -C "your-email@example.com"

# Ví dụ cho Linux / Git Bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# Copy PUBLIC key
cat ~/.ssh/id_ed25519.pub

# Kiểm tra kết nối
ssh -T git@github.com
ssh -T git@gitlab.com

Thêm nội dung id_ed25519.pub vào mục SSH Keys trong cài đặt tài khoản GitHub/GitLab. Xác minh fingerprint của máy chủ khi kết nối lần đầu. Cách khởi chạy SSH agent có thể khác giữa các hệ điều hành.

Bảo mật: Không chia sẻ private key ~/.ssh/id_ed25519. Chỉ cung cấp public key có đuôi .pub.

4. Các lệnh Git cơ bản

Khởi tạo và kiểm tra trạng thái

mkdir git-demo
cd git-demo
git init -b main

git status
git status -sb

git status cho biết branch hiện tại, file được sửa, file chưa theo dõi, file đã stage và tình trạng conflict.

Stage và commit

git add index.html             # Một file
git add index.html style.css   # Nhiều file
git add .                      # Thay đổi trong thư mục hiện tại
git add -A                     # Tất cả thay đổi, kể cả xóa
git add -p                     # Chọn từng phần

git commit -m "feat: implement login API"

Quy ước commit message thường dùng: feat: tính năng, fix: sửa lỗi, docs: tài liệu, refactor: tái cấu trúc, test: kiểm thử, chore: bảo trì.

Xem lịch sử và so sánh

git log
git log --oneline
git log --oneline --graph --all --decorate
git log -5
git log -- src/app.js

git diff                    # Chưa stage
git diff --staged           # Đã stage
git diff abc123 def456      # Hai commit
git diff main..feature/login
git diff -- src/app.js

.gitignore

# Nội dung file .gitignore cho Node.js
node_modules/
dist/
coverage/
.env
.env.*
!.env.example
*.log
.DS_Store

Nếu file đã được Git theo dõi, thêm vào .gitignore không tự động ngừng theo dõi:

git rm --cached .env
git commit -m "chore: stop tracking env file"
Nếu secret từng bị commit, cần thu hồi/thay thế secret. Xóa file ở commit mới không xóa secret khỏi lịch sử Git.

5. GitHub, GitLab và remote repository

Tạo repository trống tại GitHub hoặc GitLab. Nếu đã có lịch sử local, tạo remote trống (không khởi tạo README) để tránh hai lịch sử độc lập.

Đẩy project local lên GitHub

git remote add origin git@github.com:USERNAME/git-demo.git
git branch -M main
git push -u origin main

Đẩy project local lên GitLab

git remote add origin git@gitlab.com:USERNAME/git-demo.git
git branch -M main
git push -u origin main

Clone và quản lý remote

git clone git@github.com:USERNAME/git-demo.git
git clone git@gitlab.com:GROUP_NAME/git-demo.git

git remote -v
git remote show origin
git remote set-url origin git@github.com:USERNAME/new-project.git
git remote rename origin github
git remote remove github

Fetch, pull và push

LệnhTác dụng
git fetch originLấy commit và remote-tracking refs, không tự tích hợp vào branch hiện tại.
git pull --no-rebase origin mainFetch rồi merge.
git pull --rebase origin mainFetch rồi rebase commit local.
git push origin mainĐẩy nhánh local lên remote.
git fetch origin
git log HEAD..origin/main --oneline
git pull --ff-only origin main
git push origin main

--ff-only chỉ pull khi có thể fast-forward, tránh tự tạo merge commit nếu hai nhánh phân kỳ.

6. Branch, merge, rebase và cherry-pick

Quản lý branch

git branch                         # Branch local
git branch -a                      # Local và remote
git switch -c feature/login        # Tạo và chuyển branch
git switch main                    # Chuyển branch
git switch -                       # Quay về branch trước
git branch -d feature/login        # Xóa branch đã merge
git branch -D feature/login        # Ép xóa branch local
git push origin --delete feature/login

Quy ước tên phổ biến: main, develop, feature/login, bugfix/login-error, hotfix/payment-failure, release/1.2.0.

Merge

git switch main
git merge feature/login

# Luôn tạo merge commit khi có thể
git merge --no-ff feature/login

# Hủy merge chưa hoàn tất
git merge --abort

Merge có thể là fast-forward (di chuyển branch pointer) hoặc tạo merge commit khi cần hợp nhất hai dòng lịch sử.

Rebase

git switch feature/login
git fetch origin
git rebase origin/main
Trước:
main:           A---B---C---D
                    \
feature:             E---F

Sau rebase:
main:           A---B---C---D
                            \
feature:                    E'---F'

Rebase tạo commit mới E', F'. Tránh rebase lịch sử đã chia sẻ nếu team chưa thống nhất.

Cherry-pick

git switch main
git cherry-pick abc123

# Nếu có conflict, sửa file rồi:
git add .
git cherry-pick --continue

# Hoặc hủy
git cherry-pick --abort

Cherry-pick áp dụng thay đổi từ một commit cụ thể sang branch hiện tại, hữu ích cho hotfix hoặc backport.

7. Quy trình làm việc nhóm với PR/MR

  1. Cập nhật main:
    git switch main
git pull --ff-only origin main
  2. Tạo branch:
    git switch -c feature/login
  3. Code, kiểm tra, commit:
    git status
git diff
git add src/login.js
git commit -m "feat: implement login API"
  4. Push branch:
    git push -u origin feature/login
  5. Tạo Pull Request trên GitHub hoặc Merge Request trên GitLab: chọn source feature/login và target main, mô tả thay đổi, thêm reviewer.
  6. Sửa theo review:
    git add .
git commit -m "fix: handle invalid credentials"
git push
  7. Merge trên website sau khi review và CI thành công; cập nhật local:
    git switch main
git pull --ff-only origin main

PR/MR nên có gì?

  • Mục đích và phạm vi thay đổi.
  • Danh sách tính năng hoặc lỗi được sửa.
  • Cách kiểm thử, kết quả test.
  • Ảnh minh họa nếu thay đổi giao diện.
  • Những điểm cần reviewer chú ý.
Với nhánh production, nên bật branch protection, yêu cầu PR/MR, approval và CI checks trước khi merge. Team nhỏ thường chỉ cần main cùng các feature/fix branch.

8. Xử lý merge conflict

Conflict xuất hiện khi Git không thể tự quyết định cách hợp nhất thay đổi. Ví dụ:

<<<<<<< HEAD
const API_URL = "https://api.dev.example.com";
=======
const API_URL = "https://api.prod.example.com";
>>>>>>> feature/config

Mở file, chọn hoặc kết hợp nội dung phù hợp, rồi xóa các conflict marker. Ví dụ sửa thành:

const API_URL = process.env.API_URL;

Nếu đang merge

git status
# Sửa file conflict
git add config.js
git merge --continue

# Hoặc hủy
git merge --abort

Nếu đang rebase

git status
# Sửa file conflict
git add config.js
git rebase --continue

# Hoặc hủy
git rebase --abort

VS Code Merge Editor hỗ trợ so sánh và chỉnh sửa hai phía, nhưng vẫn cần hiểu logic code trước khi chọn kết quả.

9. Hoàn tác, reset, revert và khôi phục

Restore

git restore app.js             # Bỏ thay đổi chưa stage
git restore --staged app.js    # Bỏ stage, giữ code

Reset

LệnhCommit/HEADStagingWorking tree
git reset --soft HEAD~1Lùi 1 commitGiữ thay đổi đã stageGiữ
git reset --mixed HEAD~1Lùi 1 commitReset stagingGiữ
git reset --hard HEAD~1Lùi 1 commitResetReset, có thể mất thay đổi
Cảnh báo: reset --hard có thể xóa thay đổi chưa commit. Không dùng push --force trên branch chia sẻ chỉ để vượt qua lỗi push.

Revert — an toàn hơn cho commit đã chia sẻ

git revert HEAD

Tạo commit mới đảo ngược thay đổi của commit cũ, không xóa lịch sử đã chia sẻ.

Sửa commit gần nhất

git commit --amend -m "fix: correct login validation"

# Thêm file vào commit gần nhất
git add src/login.js
git commit --amend --no-edit

Amend thay thế commit bằng một commit có hash mới.

Reflog — cứu commit sau reset nhầm

git reflog
# Ví dụ thấy commit c91f128 cần cứu
git branch recovery/payment c91f128
git switch recovery/payment

Reflog không phải bản sao lưu vĩnh viễn; dữ liệu không còn tham chiếu có thể bị dọn theo thời gian.

10. Stash, tag và lệnh nâng cao

Stash — cất tạm thay đổi

git stash
git stash push -m "WIP login"
git stash push -u -m "WIP login"   # Gồm file untracked
git stash list
git stash apply                   # Áp dụng, giữ stash
git stash pop                     # Áp dụng và xóa nếu thành công
git stash apply stash@{0}
git stash drop stash@{0}

Tag — đánh dấu release

git tag -a v1.0.0 -m "Release version 1.0.0"
git tag
git show v1.0.0
git push origin v1.0.0
git push origin --tags

LệnhÝ nghĩa

git blame app.jsTruy tìm commit cuối sửa từng dòng
git grep "login"Tìm chuỗi trong file Git quản lý

11. CI/CD với GitHub Actions và GitLab

CI/CD thường chạy chuỗi bước Push → Install → Lint/Test → Build → Deploy. Dưới đây là ví dụ cho dự án Node.js có package-lock.json và npm scripts tương ứng.

GitHub Actions

Tạo .github/workflows/ci.yml:

name: Node.js CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test-and-build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'npm'
      - name: Install dependencies
        run: npm ci
      - name: Lint
        run: npm run lint
      - name: Test
        run: npm test
      - name: Build
        run: npm run build

Workflow chạy khi push vào main hoặc tạo/cập nhật PR nhắm tới main. Kết quả hiển thị trong tab Actions.

GitLab CI/CD

Tạo .gitlab-ci.yml:

image: node:22

stages:
  - test
  - build

lint_job:
  stage: test
  script:
    - npm ci
    - npm run lint

unit_test_job:
  stage: test
  script:
    - npm ci
    - npm test

build_job:
  stage: build
  script:
    - npm ci
    - npm run build

GitLab cần runner phù hợp để thực thi job. Các job cùng stage có thể chạy song song; stage sau thông thường chờ stage trước thành công.

Bảo mật: Không hardcode token, password, private key trong YAML. Dùng GitHub Actions Secrets hoặc GitLab CI/CD Variables và cấp quyền tối thiểu.

12. Lỗi Git thường gặp

fatal: not a git repository

Bạn đang ở sai thư mục hoặc chưa khởi tạo Git. Kiểm tra pwd, ls -a và chuyển vào đúng repository.

Author identity unknown

git config --global user.name "Developer"
git config --global user.email "you@example.com"

Permission denied (publickey)

ssh -T git@github.com
git remote -v

Kiểm tra SSH key, tài khoản và quyền truy cập repository.

failed to push some refs / non-fast-forward

git fetch origin
git status -sb
git log --oneline --graph --all
# Sau khi xác định tình trạng phân kỳ:
git pull --rebase
git push

Chỉ dùng git pull --rebase khi đã có upstream phù hợp và cách tích hợp này đúng với quy trình team.

Your local changes would be overwritten by checkout

git stash push -u -m "save current changes"
git switch main
# Khi quay lại branch làm việc:
git stash pop

refusing to merge unrelated histories

Hai lịch sử không có commit gốc chung. Chỉ khi thật sự muốn hợp nhất hai lịch sử độc lập mới dùng:

git pull origin main --allow-unrelated-histories

14. Bài thực hành từ đầu đến cuối

Bài 1 — Khởi tạo và commit đầu tiên

mkdir git-practice
cd git-practice
git init -b main
echo "# Git Practice" > README.md
git add README.md
git commit -m "docs: initial README"
git status
git log --oneline

Bài 2 — Tạo feature branch

git switch -c feature/hello
echo "Hello Git" > hello.txt
git add hello.txt
git commit -m "feat: add hello file"
git log --oneline --graph --all

Bài 3 — Merge branch

git switch main
git merge feature/hello
git branch -d feature/hello
git log --oneline --graph

Bài 4 — Push lên GitHub hoặc GitLab

Tạo remote repository trống tên git-practice, rồi chọn một trong hai lệnh sau:

# GitHub
git remote add origin git@github.com:USERNAME/git-practice.git

# HOẶC GitLab (không chạy cả hai)
# git remote add origin git@gitlab.com:USERNAME/git-practice.git

git push -u origin main

Bài 5 — Mô phỏng Pull Request / Merge Request

git switch -c feature/greeting
echo "Welcome to Git" > greeting.txt
git add greeting.txt
git commit -m "feat: add greeting"
git push -u origin feature/greeting

Trên website tạo PR/MR từ feature/greeting vào main, review và merge. Sau đó:

git switch main
git pull --ff-only origin main
git log --oneline --graph
