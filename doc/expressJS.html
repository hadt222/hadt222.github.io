Chương 01 · Tổng quan~ 6 phút

Express.js là gì? Vì sao nên học?

Express.js là web framework tối giản chạy trên Node.js. Nó giúp bạn tạo HTTP server, khai báo endpoint (route), xử lý dữ liệu đầu vào và trả response mà không cần tự xây mọi thứ từ module http của Node.

Express xử lý tốt việc gì?

REST API, backend cho ứng dụng React/Vue, website render phía server, webhook, hệ thống nội bộ, microservice.

Express không tự cung cấp gì?

Database, ORM, xác thực người dùng, validation schema, hàng đợi tác vụ. Bạn chọn thư viện phù hợp và kết hợp.

Vòng đời một HTTP request

ClientTrình duyệt / app
→
ExpressHTTP server
→
MiddlewareParse · auth · log
→
RouteBusiness logic → JSON

Khi có request, Express lần lượt xét các middleware và route theo thứ tự đăng ký. Một handler có thể phản hồi ngay bằng res.json(), chuyển tiếp bằng next(), hoặc phát sinh lỗi.

Kiến thức nên có trước khi học

JavaScript cơ bản (const, function, object, array, async/await), command line, JSON và một chút kiến thức HTTP. Chưa biết frontend vẫn học được.

Path parameter và query parameter

Chương 05 · Dữ liệu~ 8 phút

Làm việc với req và res

Để đọc JSON client gửi trong body, bạn phải đăng ký parser express.json() trước các route sử dụng req.body.

request-response.js · javascript
import express from 'express';
const app = express();

// Đặt trước các route cần đọc JSON
app.use(express.json({ limit: '32kb' }));
app.use(express.urlencoded({ extended: false }));

app.post('/profile', (req, res) => {
  const { name } = req.body ?? {};
  if (typeof name !== 'string' || !name.trim()) {
    return res.status(400).json({ error: 'Thiếu name hợp lệ' });
  }

  res.status(201).json({
    message: `Xin chào ${name.trim()}`,
    userAgent: req.get('user-agent') ?? 'unknown'
  });
});

app.listen(3000);
APIĐọc / ghi gì?
req.params.idBiến đường dẫn từ /:id.
req.queryQuery string của URL, không mặc định được kiểm chứng.
req.bodyDữ liệu body đã được middleware parse.
req.get('authorization')Giá trị HTTP header.
res.status(201)Đặt status code (có thể chain với .json()).

Không tin dữ liệu đầu vào

Giá trị ở req.body, req.query, req.params đều do client kiểm soát. Kiểm tra kiểu dữ liệu, giới hạn độ dài, lọc trường được phép và kiểm soát quyền trước khi sử dụng.

Chương 06 · Trái tim Express~ 9 phút

Middleware: tư duy nền tảng

Middleware thường có chữ ký (req, res, next). Nó có thể gắn thông tin vào request, ghi log, kiểm tra quyền, trả response hoặc chuyển tiếp xử lý.

middleware.js · javascript
import express from 'express';
const app = express();

// 1. Middleware toàn cục
app.use((req, res, next) => {
  console.log(`${req.method} ${req.originalUrl}`);
  next(); // Bắt buộc nếu chưa kết thúc response
});

// 2. Middleware chỉ áp dụng cho nhóm /admin
function requireAdmin(req, res, next) {
  const role = req.get('x-demo-role'); // Chỉ để minh họa!
  if (role !== 'admin') {
    return res.status(403).json({ error: 'Forbidden' });
  }
  next();
}

app.get('/admin', requireAdmin, (req, res) => {
  res.json({ secret: 'Ví dụ cho middleware' });
});

app.listen(3000);
Ví dụ trên KHÔNG phải cơ chế xác thực thật

Header x-demo-role có thể bị người gửi giả mạo. Ứng dụng thật phải xác minh session/token ở phía server, sau đó kiểm tra quyền trên danh tính đã được xác thực.

Quy tắc thứ tự

  1. Parser (express.json()), logging, cấu hình bảo mật và middleware chung.
  2. Router chính của ứng dụng như /api/tasks.
  3. Handler 404 sau các router.
  4. Error handler 4 tham số (err, req, res, next) đặt cuối cùng.

Không gọi next() sau khi đã gửi response, trừ khi có chủ đích đặc biệt; cũng không bỏ quên cả res lẫn next() vì request sẽ bị treo.

Bước 2 — Tạo router đầy đủ CRUD

src/routes/tasks.routes.js
import { Router } from 'express';
import { HttpError } from '../lib/http-error.js';

const router = Router();

// Demo: lưu trong RAM, KHÔNG dùng làm data store production
const tasks = [{ id: 1, title: 'Học Express.js', done: false }];
let nextId = 2;

function parseId(value) {
  const id = Number(value);
  if (!Number.isSafeInteger(id) || id < 1) {
    throw new HttpError(400, 'ID phải là số nguyên dương');
  }
  return id;
}

function findTask(id) {
  const task = tasks.find(item => item.id === id);
  if (!task) throw new HttpError(404, 'Không tìm thấy task');
  return task;
}

// GET /api/tasks?search=express
router.get('/', (req, res) => {
  const search = typeof req.query.search === 'string'
    ? req.query.search.toLowerCase().trim()
    : '';

  const data = search
    ? tasks.filter(task => task.title.toLowerCase().includes(search))
    : tasks;
  res.json({ data, total: data.length });
});

// GET /api/tasks/:id
router.get('/:id', (req, res) => {
  const task = findTask(parseId(req.params.id));
  res.json({ data: task });
});

// POST /api/tasks
router.post('/', (req, res) => {
  const { title } = req.body ?? {};
  if (typeof title !== 'string' ||
      !title.trim() || title.trim().length > 120) {
    throw new HttpError(400, 'title phải có 1–120 ký tự');
  }

  const task = { id: nextId++, title: title.trim(), done: false };
  tasks.push(task);
  res.status(201).location(`/api/tasks/${task.id}`).json({ data: task });
});

// PATCH /api/tasks/:id
router.patch('/:id', (req, res) => {
  const task = findTask(parseId(req.params.id));
  const body = req.body;
  if (!body || typeof body !== 'object' || Array.isArray(body)) {
    throw new HttpError(400, 'Body phải là JSON object');
  }

  const { title, done } = body;
  if (title === undefined && done === undefined) {
    throw new HttpError(400, 'Cần title hoặc done');
  }
  if (title !== undefined) {
    if (typeof title !== 'string' ||
        !title.trim() || title.trim().length > 120) {
      throw new HttpError(400, 'title phải có 1–120 ký tự');
    }
    task.title = title.trim();
  }
  if (done !== undefined) {
    if (typeof done !== 'boolean') {
      throw new HttpError(400, 'done phải là boolean');
    }
    task.done = done;
  }
  res.json({ data: task });
});

// DELETE /api/tasks/:id
router.delete('/:id', (req, res) => {
  const id = parseId(req.params.id);
  const index = tasks.findIndex(task => task.id === id);
  if (index === -1) throw new HttpError(404, 'Không tìm thấy task');
  tasks.splice(index, 1);
  res.sendStatus(204);
});

export default router;

Bước 3 — Khởi tạo app và xử lý lỗi

src/app.js
import express from 'express';
import taskRouter from './routes/tasks.routes.js';
import { HttpError } from './lib/http-error.js';

const app = express();
app.disable('x-powered-by');
app.use(express.json({ limit: '32kb' }));

app.get('/health', (req, res) => {
  res.json({ status: 'ok' });
});

app.use('/api/tasks', taskRouter);

// Route không tồn tại: đăng ký SAU các router
app.use((req, res, next) => {
  next(new HttpError(404, 'Endpoint không tồn tại'));
});

// Middleware xử lý lỗi: BỐN tham số, đặt cuối
app.use((err, req, res, next) => {
  if (res.headersSent) return next(err);
  const rawStatus = err.status ?? err.statusCode ?? 500;
  const status = Number.isInteger(rawStatus) &&
    rawStatus >= 400 && rawStatus <= 599 ? rawStatus : 500;

  console.error(err);
  res.status(status).json({
    error: status >= 500 ? 'Lỗi máy chủ' : err.message
  });
});

export default app;

Validation, async/await và xử lý lỗi

Ở mini project, ta kiểm tra dữ liệu thủ công. Khi API lớn hơn, nên dùng thư viện validation schema như Zod hoặc Joi để mô tả rõ kiểu dữ liệu, giá trị cho phép và thông báo lỗi.

// Đặt trong POST route:
const result = createTaskSchema.safeParse(req.body);
if (!result.success) {
  return res.status(400).json({

      path: issue.path.join('.'),

Express 5 tự chuyển lỗi từ async handler

async-route-example.js
// Hàm db là ví dụ minh họa; bạn cần cung cấp DB thật.
app.get('/api/users/:id', async (req, res) => {
  const user = await db.getUser(req.params.id);
  if (!user) throw new HttpError(404, 'User không tồn tại');
  res.json({ data: user });
  // Nếu Promise bị reject, Express 5 tự chuyển vào error handler.
});

Với Express 5, các route/middleware trả Promise sẽ tự chuyển lỗi rejected/throw vào error handler. Không cần bọc mọi route trong try/catch(next) như nhiều tutorial Express 4 trước đây.

Một số ngoại lệ cần hiểu

Lỗi từ callback ngoài Promise chain, timer, hoặc event emitter không tự động đi vào Express error handler. Hãy quản lý lỗi tại nơi callback/event phát sinh. Nếu response đã bắt đầu gửi, chuyển tiếp bằng next(err).

4. Truy vấn có tham số chống SQL injection

Ví dụ route thay thế GET /api/tasks/:id
import { pool } from '../db.js';

router.get('/:id', async (req, res) => {
  const id = parseId(req.params.id);
  const result = await pool.query(
    'SELECT id, title, done FROM tasks WHERE id = $1',
    [id]
  );
  if (result.rowCount === 0) {
    throw new HttpError(404, 'Không tìm thấy task');
  }
  res.json({ data: result.rows[0] });
});
Điểm quan trọng

Dùng $1 cùng mảng tham số [id], không nối trực tiếp input vào SQL. Đây chỉ là đoạn thay thế một route; cần chuyển toàn bộ CRUD và migration sang PostgreSQL trước khi bỏ dữ liệu RAM. Với BIGSERIAL, pg thường trả id dưới dạng chuỗi để giữ độ chính xác.

Chương 12 · An toàn~ 11 phút

Bảo mật, CORS và xác thực

Express để bạn chủ động chọn lớp bảo mật. Dưới đây là baseline hữu ích cho API công khai; nó không thay thế kiểm tra quyền, xác thực và đánh giá rủi ro theo ứng dụng.

Helmet + CORS + Rate limiting

terminal
npm install helmet cors express-rate-limit
src/app.js · thêm trước các routes
import helmet from 'helmet';
import cors from 'cors';
import { rateLimit } from 'express-rate-limit';

app.use(helmet());
app.use(cors({
  origin: 'https://app.example.com',
  credentials: true
}));
app.use('/api', rateLimit({
  windowMs: 15 * 60 * 1000,
  limit: 100,
  standardHeaders: 'draft-8',
  legacyHeaders: false
}));

Hãy đổi https://app.example.com thành frontend origin thực tế. CORS là chính sách trình duyệt, không phải cơ chế xác thực hay lớp ngăn truy cập API từ server/curl. Nếu dùng cookies cross-origin, phải kết hợp cấu hình CORS phù hợp với SameSite, Secure, HTTPS và chống CSRF.

Authentication (Bạn là ai?)

Xác minh người dùng qua session hoặc access token. Mật khẩu phải được hash bằng thư viện phù hợp (Argon2id/bcrypt), không lưu plain text.

Authorization (Bạn được làm gì?)

Kiểm tra user có quyền đọc/sửa đúng dữ liệu này không. Ví dụ user A không được sửa task thuộc user B.

Checklist bảo mật tối thiểu

  • Sử dụng HTTPS/TLS trên môi trường thực.
  • Không lộ thông tin lỗi nội bộ, stack trace, credentials hoặc secret ra client.
  • Validate mọi đầu vào; giới hạn kích thước body và số request.
  • Dùng query có tham số, kiểm soát XSS và CSRF theo cơ chế xác thực.
  • Lưu secret trong biến môi trường/secret manager; không commit .env.
  • Duy trì các dependency được hỗ trợ, thường xuyên audit & cập nhật.
  • Nếu chạy sau reverse proxy, chỉ thiết lập trust proxy phù hợp với hạ tầng thực tế; cấu hình sai có thể làm spoof IP và sai rate limit.
Rate limit khi scale nhiều instance

Bộ nhớ mặc định của express-rate-limit chỉ theo từng tiến trình. Khi chạy nhiều container/instance, sử dụng store chia sẻ (ví dụ Redis) hoặc giới hạn ở API gateway. Không sao chép đoạn cấu hình demo như một chính sách production hoàn chỉnh.

Viết test API với node:test & Supertest

Test giúp đảm bảo endpoint hoạt động đúng sau khi bạn chỉnh sửa code. Ta dùng node:test có sẵn trong Node và supertest để gửi HTTP request vào Express app.

terminal
npm install --save-dev supertest
npm test

Trước khi chạy npm test, tạo file test dưới đây và đảm bảo đã chạy lệnh npm pkg set scripts.test="node --test" ở Chương 7.

test/tasks.test.js
import test from 'node:test';
import assert from 'node:assert/strict';
import request from 'supertest';
import app from '../src/app.js';

test('GET /health trả trạng thái ok', async () => {
  const res = await request(app).get('/health');
  assert.equal(res.status, 200);
  assert.deepEqual(res.body, { status: 'ok' });
});

test('GET /api/tasks trả danh sách', async () => {
  const res = await request(app).get('/api/tasks');
  assert.equal(res.status, 200);
  assert.ok(Array.isArray(res.body.data));
});

test('POST /api/tasks tạo task mới', async () => {
  const res = await request(app)
    .post('/api/tasks')
    .send({ title: 'Viết integration test' });

  assert.equal(res.status, 201);
  assert.equal(res.body.data.title, 'Viết integration test');
  assert.equal(res.body.data.done, false);
});

test('POST thiếu title trả lỗi 400', async () => {
  const res = await request(app).post('/api/tasks').send({});
  assert.equal(res.status, 400);
});

test('GET đường dẫn lạ trả 404', async () => {
  const res = await request(app).get('/does-not-exist');
  assert.equal(res.status, 404);
});
Khi project lớn dần

Tách trạng thái test và production; dùng database test riêng, seed dữ liệu trước mỗi test, dọn dữ liệu sau test và bổ sung test 401/403/409, edge case, quyền truy cập, invalid JSON.

Đưa ứng dụng lên production

Để triển khai, bạn có thể dùng VPS, một nền tảng chạy Node hoặc container. Nguyên tắc chung: dependency được khóa, config đến từ môi trường, server lắng nghe đúng PORT và có health endpoint.

Thiết lập biến môi trường

terminal
# Bash/Linux/macOS
NODE_ENV=production PORT=3000 npm start

# Khi dùng hosting: khai báo NODE_ENV, PORT, DATABASE_URL

Ví dụ Dockerfile tối giản

Dockerfile · minh họa
FROM node:22-alpine
WORKDIR /app

COPY package*.json ./
RUN npm ci --omit=dev

COPY src ./src
ENV NODE_ENV=production
EXPOSE 3000
USER node
CMD ["node", "src/server.js"]

Dockerfile giả định bạn đã có package-lock.json do npm install tạo. Khi deploy hãy chọn bản Node LTS còn được hỗ trợ, cập nhật base image định kỳ và truyền biến môi trường lúc chạy container (không bake secret vào image). Nếu chạy file trong public, migrations hay view templates, cần COPY thêm các thư mục đó.

Checklist trước khi công bố

Production không chỉ là “npm start”

Chú ý quản lý process/restart, graceful shutdown, database pooling, timeouts, logging, monitoring, backup, reverse proxy, TLS và giới hạn tài nguyên. Node không nên xử lý tác vụ CPU nặng ngay trên event loop chính.

Express 5: những thay đổi & lỗi hay gặp

Nhiều bài hướng dẫn cũ viết cho Express 4. Khi học với Express 5, hãy chú ý các khác biệt sau.

Chủ đềExpress 5 nên dùng
Wildcard route/*splat hoặc /{*splat}; không dùng '*' vô danh.
Async errorPromise rejected/throw trong async handler tự được chuyển vào error handler.
File responseres.sendFile(), không phải res.sendfile().
Response statusres.status(201).send(data) hoặc res.sendStatus(204), không dùng mẫu cũ res.send(201) để đặt mã trạng thái.
Route string patternsCú pháp route string với các ký tự đặc biệt đã thay đổi; đọc migration guide trước khi copy pattern cũ.
Node.jsCần Node ≥ 18 cho Express 5.

Gỡ lỗi bằng triệu chứng

Triệu chứngNguyên nhân thường gặp / giải pháp
Cannot GET /...Route không tồn tại, sai method/path, hoặc đăng ký nhầm thứ tự.
req.body là undefinedThiếu express.json(), sai Content-Type, hoặc body không được parse.
EADDRINUSECổng đã có tiến trình khác sử dụng; đóng tiến trình hoặc đổi PORT.
ERR_MODULE_NOT_FOUNDSai path import, thiếu đuôi .js ở local ESM import, hoặc chưa cài package.
CORS errorFrontend khác origin; kiểm tra allowlist, preflight, credential và headers.
Request treoHandler không gửi response và cũng không gọi next().
500 nhưng thiếu logThêm error logging phía server, kiểm tra Promise, dữ liệu DB, không lộ stack cho client.
