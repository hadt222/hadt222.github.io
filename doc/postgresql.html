Nhập môn/Bài 01

PostgreSQL là gì?

Hiểu công cụ trước khi viết dòng SQL đầu tiên.

◷ 7 phút

PostgreSQL (thường gọi là Postgres) là hệ quản trị cơ sở dữ liệu quan hệ mã nguồn mở. Nó lưu dữ liệu bền vững, cho phép truy vấn bằng SQL và hỗ trợ transaction, ràng buộc dữ liệu, chỉ mục, JSONB, truy vấn phức tạp và khả năng mở rộng.

▦
DatabaseKhông gian lưu trữ các schema, bảng, view, hàm…
▤
TableDữ liệu gồm hàng (row) và cột (column).
⌁
SQLNgôn ngữ để khai báo, đọc và cập nhật dữ liệu.
⛨
TransactionNhóm thao tác đảm bảo nhất quán dữ liệu.

Cài đặt & kết nối

Có bốn lựa chọn. Docker là cách dễ tái lập và tránh xung đột môi trường.

◷ 12 phút

Cần cài Docker Desktop hoặc Docker Engine. Container postgres:18 tự tạo DB shop_lab ở lần khởi chạy đầu tiên. Volume lưu dữ liệu khi container bị xóa; tham số 127.0.0.1 chỉ công bố cổng trên máy cục bộ.

Terminal · Docker
docker run --name pg-tutorial \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=change_me_local \
  -e POSTGRES_DB=shop_lab \
  -p 127.0.0.1:5432:5432 \
  -v pg_shop_data:/var/lib/postgresql \
  -d postgres:18

# Kiểm tra container đang chạy
docker ps

# Mở psql ngay bên trong container
docker exec -it pg-tutorial psql -U postgres -d shop_lab

Trên Windows, tải bộ cài từ trang PostgreSQL for Windows. Chọn PostgreSQL Server và có thể chọn pgAdmin. Ghi nhớ mật khẩu của user postgres và cổng (thường là 5432).

psql · kết nối / tạo database
# Sau khi cài, mở SQL Shell (psql) hoặc Terminal:
psql -h localhost -p 5432 -U postgres -d postgres

-- Trong psql, tạo database học tập:
CREATE DATABASE shop_lab;
\c shop_lab

Trên macOS, có thể dùng trình cài chính thức, Postgres.app hoặc Homebrew. Cách dưới đây dành cho Homebrew và có thể thay đổi tên formula theo bản có sẵn.

Terminal · macOS
brew install postgresql@18
brew services start postgresql@18

# Nếu psql chưa nằm trong PATH, thêm đường dẫn Homebrew
# theo hướng dẫn "brew info postgresql@18".
psql -d postgres

# Tạo DB nếu chưa có:
createdb shop_lab
psql -d shop_lab

Trên Ubuntu/Debian, kho mặc định có thể cung cấp phiên bản khác 18; nếu cần đúng 18, dùng kho chính thức PGDG. Ví dụ cài từ kho hệ điều hành:

Terminal · Ubuntu / Debian
sudo apt update
sudo apt install postgresql postgresql-client
sudo systemctl enable --now postgresql
sudo -u postgres psql

-- Trong psql (với phiên làm việc phù hợp):
CREATE DATABASE shop_lab;
\c shop_lab
!
Lưu ý quan trọng

Mật khẩu change_me_local chỉ để học trên máy cá nhân. Không sao chép cấu hình này vào production; hãy dùng secret và chính sách phân quyền riêng. Với image PostgreSQL 18, volume chính nằm ở /var/lib/postgresql (khác bản 17 trở xuống).

Xác nhận cài đặt thành công

SQL · chạy trong psql / Query Tool
SELECT version();
SELECT current_database(), current_user, now();

Nếu truy vấn trả về phiên bản PostgreSQL và database shop_lab, môi trường đã sẵn sàng. Bạn có thể dùng pgAdmin, DBeaver hoặc psql để chạy các câu SQL còn lại.

Làm quen với psql

Lệnh bắt đầu bằng dấu \ là meta-command của psql, không phải SQL.

◷ 8 phút
Terminal · mở phiên SQL
psql -h 127.0.0.1 -p 5432 -U postgres -d shop_lab

# Hoặc nếu chạy qua Docker:
docker exec -it pg-tutorial psql -U postgres -d shop_lab
psql · meta-command
\l                 -- Liệt kê database
\c shop_lab        -- Chuyển database
\dn                -- Liệt kê schema
\dt                -- Danh sách bảng trong search_path
\d customers      -- Mô tả cấu trúc bảng
\du                -- Danh sách role
\conninfo          -- Thông tin kết nối
\timing on         -- Đo thời gian truy vấn
\x auto            -- Hiển thị ngang/dọc tùy kết quả
\q                 -- Thoát psql
ⓘ
Ghi nhớ

Mỗi câu SQL thường kết thúc bằng dấu ;. Meta-command \dt, \q chỉ chạy trong psql, không chạy trực tiếp trong Query Tool của pgAdmin.

Khái niệm schema và search_path

SQL · chạy trong psql / Query Tool
SELECT current_schema();
SHOW search_path;
SELECT current_database();

-- Viết đầy đủ schema khi cần:
SELECT * FROM public.customers; -- chạy sau khi tạo bảng

Kiểu dữ liệu thiết yếu

Chọn đúng kiểu dữ liệu giúp tránh lỗi làm tròn, mất tính nhất quán và truy vấn chậm.

NULL không phải 0 hay chuỗi rỗng

SQL · chạy trong psql / Query Tool
SELECT
  NULL IS NULL AS la_null,          -- true
  COALESCE(NULL, 'chưa có') AS ten,
  NULL = NULL AS phep_so_sanh;     -- NULL (unknown)

-- Dùng IS NULL / IS NOT NULL, không dùng = NULL
ⓘ
Ghi nhớ

PostgreSQL có ba giá trị logic: TRUE, FALSE, UNKNOWN (thường biểu diễn bằng NULL). WHERE chỉ giữ những hàng có điều kiện TRUE.

Thiết kế database thực hành

Xây dựng một shop đơn giản dùng xuyên suốt tutorial: khách hàng, sản phẩm, đơn hàng và dòng hàng.

◷ 15 phút

Sơ đồ quan hệ

customers 1
PK customer_id
full_name · email
joined_at
1 → N
orders N
PK order_id
FK customer_id
status · created_at
1 → N
order_items N
PK order_id + product_id
FK order_id · product_id
quantity · unit_price
N → 1
products 1
PK product_id
sku · name · price
stock · metadata

1. Tạo 4 bảng với khóa, ràng buộc

SQL · Schema mẫu — chạy một lần
-- Chạy trong database shop_lab (nên là DB mới).
CREATE TABLE customers (
  customer_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  full_name   TEXT NOT NULL,
  email       TEXT NOT NULL UNIQUE,
  joined_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE products (
  product_id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  sku        TEXT NOT NULL UNIQUE,
  name       TEXT NOT NULL,
  price      NUMERIC(12,2) NOT NULL CHECK (price >= 0),
  stock      INTEGER NOT NULL DEFAULT 0 CHECK (stock >= 0),
  metadata   JSONB NOT NULL DEFAULT '{}'::jsonb
);

CREATE TABLE orders (
  order_id    BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer_id BIGINT NOT NULL REFERENCES customers(customer_id),
  status      TEXT NOT NULL DEFAULT 'pending'
              CHECK (status IN ('pending','paid','cancelled')),
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE order_items (
  order_id   BIGINT NOT NULL REFERENCES orders(order_id)
             ON DELETE CASCADE,
  product_id BIGINT NOT NULL REFERENCES products(product_id),
  quantity   INTEGER NOT NULL CHECK (quantity > 0),
  unit_price NUMERIC(12,2) NOT NULL CHECK (unit_price >= 0),
  PRIMARY KEY (order_id, product_id)
);

2. Thêm dữ liệu mẫu

SQL · Seed data — chạy một lần
-- Giả định 4 bảng vừa được tạo và đang rỗng.
INSERT INTO customers (full_name, email) VALUES
('An Nguyễn',   'an@example.com'),
('Bình Trần',   'binh@example.com'),
('Chi Lê',      'chi@example.com');

INSERT INTO products (sku, name, price, stock, metadata) VALUES
('KB-01', 'Bàn phím cơ', 890000, 12,
 '{"brand":"KeyLab","tags":["office","keyboard"]}'),
('MS-02', 'Chuột không dây', 350000, 25,
 '{"brand":"PointX","tags":["office","mouse"]}'),
('MN-03', 'Màn hình 24 inch', 3200000, 7,
 '{"brand":"ViewMax","tags":["display"]}');

-- ID trong DB mới: customer 1..3, product 1..3, order 1..3.
INSERT INTO orders (customer_id, status, created_at) VALUES
(1, 'paid',    NOW() - INTERVAL '5 days'),
(2, 'pending', NOW() - INTERVAL '2 days'),
(1, 'paid',    NOW() - INTERVAL '1 day');

INSERT INTO order_items (order_id, product_id, quantity, unit_price) VALUES
(1, 1, 1, 890000),
(1, 2, 2, 350000),
(2, 3, 1, 3200000),
(3, 2, 1, 350000);

SELECT 'customers' AS bang, COUNT(*) FROM customers
UNION ALL SELECT 'products', COUNT(*) FROM products
UNION ALL SELECT 'orders', COUNT(*) FROM orders
UNION ALL SELECT 'order_items', COUNT(*) FROM order_items;
!
Thứ tự thực hành

Các ví dụ tiếp theo giả định đã chạy schema + seed đúng một lần trong database trống. Nếu chạy lại các câu CREATE TABLE / INSERT, bạn có thể gặp lỗi trùng bảng hoặc trùng email, SKU.

Vì sao có 4 bảng?

  • Quan hệ 1–N: một khách hàng có nhiều đơn hàng.
  • Quan hệ N–N: đơn hàng có nhiều sản phẩm và sản phẩm có thể nằm trong nhiều đơn; bảng order_items nối hai bên.
  • Lưu unit_price trong order_items để giữ đúng giá tại thời điểm mua, dù giá sản phẩm sau này đổi.
  • PRIMARY KEY duy nhất; FOREIGN KEY giữ tính toàn vẹn tham chiếu; CHECK chặn dữ liệu không hợp lệ.

ALTER TABLE thay đổi cấu trúc

SQL · chạy trong psql / Query Tool
ALTER TABLE customers ADD COLUMN phone TEXT;
-- Xóa cột vừa thêm nếu chỉ thử nghiệm:
ALTER TABLE customers DROP COLUMN phone;

CRUD — Thêm, đọc, sửa, xóa

Bốn thao tác xương sống: INSERT, SELECT, UPDATE và DELETE.

◷ 12 phút

INSERT và RETURNING

SQL · chạy trong psql / Query Tool
INSERT INTO customers (full_name, email)
VALUES ('Dũng Phạm', 'dung@example.com')
RETURNING customer_id, full_name, joined_at;

-- INSERT này tạo khách hàng thứ 4 nếu dữ liệu mẫu còn nguyên.

SELECT và WHERE

SQL · chạy trong psql / Query Tool
SELECT product_id, name, price
FROM products
WHERE price >= 500000
ORDER BY price DESC;

UPDATE an toàn

SQL · chạy trong psql / Query Tool
UPDATE products
SET price = price * 0.90
WHERE sku = 'KB-01'
RETURNING sku, name, price;

DELETE có điều kiện

SQL · chạy trong psql / Query Tool
-- Chỉ xóa khách hàng vừa tạo, nếu chưa có orders tham chiếu.
DELETE FROM customers
WHERE email = 'dung@example.com'
RETURNING customer_id, email;
!
Lưu ý quan trọng

Luôn kiểm tra WHERE trước UPDATE/DELETE. Thiếu WHERE có thể sửa/xóa toàn bảng. Khi chưa chắc chắn, chạy trong transaction và ROLLBACK để hoàn tác.

UPSERT — xử lý khóa trùng

SQL · chạy trong psql / Query Tool
INSERT INTO products (sku, name, price, stock)
VALUES ('MS-02', 'Chuột không dây', 350000, 5)
ON CONFLICT (sku) DO UPDATE
SET stock = products.stock + EXCLUDED.stock
RETURNING sku, stock;

Ở đây EXCLUDED.stock là giá trị dự kiến chèn. Khi sku đã tồn tại, câu lệnh tăng tồn kho thêm 5 thay vì tạo bản ghi trùng.

SELECT từ dễ đến khó

Biết lọc, sắp xếp, phân trang và xử lý giá trị NULL trước khi kết hợp bảng.

◷ 13 phút
SQL · chạy trong psql / Query Tool
-- Chọn cột + đặt bí danh
SELECT name AS ten_san_pham, price AS gia
FROM products;

-- Nhiều điều kiện
SELECT sku, name, price
FROM products
WHERE price BETWEEN 300000 AND 1000000
  AND name ILIKE '%chuột%';

-- IN, IS NULL, biểu thức
SELECT customer_id, full_name
FROM customers
WHERE email IN ('an@example.com', 'chi@example.com');

-- Sắp xếp + giới hạn
SELECT name, price
FROM products
ORDER BY price DESC, name ASC
LIMIT 2 OFFSET 0;

Phân trang theo OFFSET hay keyset?

LIMIT/OFFSET đơn giản nhưng OFFSET lớn buộc hệ thống đi qua nhiều hàng trước khi trả kết quả. Với dữ liệu lớn và thứ tự ổn định, ưu tiên keyset pagination.

SQL · chạy trong psql / Query Tool
-- Ví dụ trang tiếp theo sau order_id = 10
SELECT order_id, created_at, status
FROM orders
WHERE order_id > 10
ORDER BY order_id
LIMIT 20;

CASE, COALESCE và DISTINCT

SQL · chạy trong psql / Query Tool
SELECT name, price,
  CASE
    WHEN price >= 1000000 THEN 'Cao cấp'
    WHEN price >= 500000  THEN 'Trung cấp'
    ELSE 'Phổ thông'
  END AS phan_khuc
FROM products;

SELECT DISTINCT status FROM orders;
SELECT COALESCE(NULL::TEXT, 'Không có') AS ket_qua;
ⓘ
Ghi nhớ

Không nên lạm dụng SELECT * trong API production: khó kiểm soát dữ liệu trả về và dễ phát sinh truyền tải thừa.

JOIN — kết hợp nhiều bảng

JOIN giúp biến các bảng chuẩn hóa thành thông tin có ý nghĩa nghiệp vụ.

◷ 15 phút

INNER JOIN — chỉ lấy hàng khớp

SQL · chạy trong psql / Query Tool
SELECT o.order_id, c.full_name, o.status, o.created_at
FROM orders AS o
JOIN customers AS c ON c.customer_id = o.customer_id
ORDER BY o.order_id;

LEFT JOIN — giữ cả hàng không khớp

SQL · chạy trong psql / Query Tool
-- Khách hàng chưa từng đặt hàng vẫn xuất hiện.
SELECT c.full_name, COUNT(o.order_id) AS so_don
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.full_name
ORDER BY c.customer_id;

JOIN 4 bảng để xem chi tiết đơn hàng

SQL · chạy trong psql / Query Tool
SELECT o.order_id,
       c.full_name,
       p.name AS san_pham,
       oi.quantity,
       oi.unit_price,
       oi.quantity * oi.unit_price AS thanh_tien
FROM orders o
JOIN customers c ON c.customer_id = o.customer_id
JOIN order_items oi ON oi.order_id = o.order_id
JOIN products p ON p.product_id = oi.product_id
ORDER BY o.order_id, p.name;
Loại JOINÝ nghĩa
INNER JOINChỉ hàng khớp ở cả hai phía.
LEFT JOINTất cả hàng bên trái; bên phải NULL nếu không khớp.
RIGHT JOINTất cả hàng bên phải; ít dùng hơn LEFT JOIN.
FULL OUTER JOINGiữ hàng từ cả hai phía kể cả không khớp.
CROSS JOINTích Descartes; số hàng có thể tăng rất mạnh.
ⓘ
Ghi nhớ

Điều kiện lọc bảng bên phải trong WHERE có thể vô tình biến kết quả LEFT JOIN thành giống INNER JOIN. Hãy cân nhắc đặt điều kiện trong ON.

GROUP BY, HAVING và thống kê

Tổng hợp từ dữ liệu giao dịch để làm báo cáo và dashboard.

◷ 12 phút

Doanh thu từng đơn

SQL · chạy trong psql / Query Tool
SELECT o.order_id,
       o.status,
       SUM(oi.quantity * oi.unit_price) AS tong_tien
FROM orders o
JOIN order_items oi ON oi.order_id = o.order_id
GROUP BY o.order_id, o.status
ORDER BY tong_tien DESC;

Tổng doanh thu đã thanh toán theo khách hàng

SQL · chạy trong psql / Query Tool
SELECT c.customer_id, c.full_name,
       COUNT(DISTINCT o.order_id) AS so_don_da_tra,
       COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS doanh_thu

ACID viết tắt cho điều gì?

Thuộc tínhÝ nghĩa thực tế
AtomicityMột transaction hoàn tất toàn bộ hoặc không có thay đổi nào được commit.
ConsistencyDữ liệu phải tuân thủ các ràng buộc và quy tắc hợp lệ.
IsolationCác transaction đồng thời được cô lập theo mức được chọn.

BEGIN, COMMIT, ROLLBACK

SQL · chạy trong psql / Query Tool
BEGIN;
UPDATE products SET stock = stock - 1
WHERE product_id = 1 AND stock >= 1
RETURNING product_id, stock;

-- Đây chỉ là bản thử nghiệm; không lưu thay đổi.
ROLLBACK;

-- Khi xử lý nghiệp vụ thực tế, ứng dụng phải kiểm tra
-- số hàng UPDATE được trước khi tiếp tục/COMMIT.

SAVEPOINT — hoàn tác một phần

SQL · chạy trong psql / Query Tool
BEGIN;
SAVEPOINT before_change;
UPDATE products SET price = price + 1000 WHERE product_id = 1;
ROLLBACK TO SAVEPOINT before_change;
COMMIT;

Khóa hàng để tránh cập nhật cạnh tranh

SQL · chạy trong psql / Query Tool
BEGIN;
SELECT product_id, stock
FROM products
WHERE product_id = 1
FOR UPDATE;

-- Sau khi khóa, kiểm tra tồn kho trong ứng dụng.
-- Cập nhật và ghi order_items trong cùng transaction.
COMMIT;

Các mức cô lập (isolation levels)

MứcĐặc điểm
READ COMMITTEDMặc định; mỗi câu lệnh thấy dữ liệu đã commit trước khi câu lệnh bắt đầu.
REPEATABLE READẢnh chụp dữ liệu ổn định trong transaction; có thể cần retry khi xung đột.
SERIALIZABLEMạnh nhất; đảm bảo kết quả tương đương một thứ tự thực thi tuần tự, ứng dụng phải retry lỗi serialization.
SQL · chạy trong psql / Query Tool

COMMIT;

Role, quyền truy cập và bảo mật

Phân quyền tối thiểu và giữ kết nối an toàn quan trọng không kém viết SQL.

◷ 14 phút

Tạo user chỉ đọc cho báo cáo

SQL · chạy trong psql / Query Tool
-- Chạy bằng role có quyền quản trị phù hợp.
CREATE ROLE report_reader LOGIN PASSWORD 'replace_with_strong_secret';
GRANT CONNECT ON DATABASE shop_lab TO report_reader;
GRANT USAGE ON SCHEMA public TO report_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO report_reader;

-- Với các bảng sẽ tạo trong tương lai bởi role hiện tại:
ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT ON TABLES TO report_reader;

Mô hình cấp quyền nên dùng

  • Mỗi ứng dụng hoặc dịch vụ có role riêng; tránh dùng postgres superuser cho ứng dụng.
  • Chỉ cấp SELECT, INSERT, UPDATE, DELETE thật sự cần thiết.
  • Dùng biến môi trường / secret manager, bật TLS cho kết nối từ xa và hạn chế IP mạng.
  • Khi có nhiều tenant, cân nhắc Row-Level Security (RLS) và kiểm tra chính sách theo từng role.

LEFT JOIN order_items oi ON oi.product_id = p.product_id
LEFT JOIN orders o ON o.order_id = oi.order_id
GROUP BY p.product_id, p.sku, p.name
ORDER BY quantity_sold DESC, p.name;

Bài 3 — Doanh thu theo ngày

SQL · chạy trong psql / Query Tool
SELECT DATE(o.created_at AT TIME ZONE 'UTC') AS ngay_utc,
       SUM(oi.quantity * oi.unit_price) AS revenue
FROM orders o
JOIN order_items oi ON oi.order_id = o.order_id
WHERE o.status = 'paid'
GROUP BY DATE(o.created_at AT TIME ZONE 'UTC')
ORDER BY ngay_utc;

Bài 4 — Tạo báo cáo tồn kho thấp

SQL · chạy trong psql / Query Tool
CREATE OR REPLACE VIEW v_low_stock AS
SELECT sku, name, stock, price
FROM products
WHERE stock < 10;

SELECT * FROM v_low_stock ORDER BY stock, name;
ⓘ
Ghi nhớ

Các ví dụ thống kê ngày dùng UTC để có kết quả nhất quán giữa các múi giờ. Dashboard thật nên chọn một múi giờ kinh doanh rõ ràng; chỉ tính doanh thu từ đơn paid.

Bài tập tự luyện có lời giải

Tự viết truy vấn trước rồi mở đáp án. Có thể chạy trực tiếp trên bộ dữ liệu shop_lab.

◷ 15 phút
01 · Liệt kê sản phẩm có giá trên 500.000, từ đắt đến rẻ.
SQL · chạy trong psql / Query Tool
SELECT name, price
FROM products
WHERE price > 500000
ORDER BY price DESC;
02 · Đếm số đơn hàng của mỗi khách hàng, kể cả chưa có đơn.
SQL · chạy trong psql / Query Tool
SELECT c.full_name, COUNT(o.order_id) AS so_don
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.full_name;
03 · Tìm đơn hàng có tổng tiền lớn nhất.
SQL · chạy trong psql / Query Tool
SELECT order_id, SUM(quantity * unit_price) AS total
FROM order_items
GROUP BY order_id
ORDER BY total DESC
LIMIT 1;
04 · Tìm các sản phẩm chưa từng xuất hiện trong đơn.
SQL · chạy trong psql / Query Tool
SELECT p.product_id, p.name
FROM products p
WHERE NOT EXISTS (
  SELECT 1 FROM order_items oi WHERE oi.product_id = p.product_id
);
05 · Viết cập nhật tồn kho chỉ khi còn đủ số lượng.
SQL · chạy trong psql / Query Tool
UPDATE products
SET stock = stock - 2
WHERE product_id = 1 AND stock >= 2
RETURNING product_id, stock;
