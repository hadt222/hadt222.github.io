01HƯỚNG DẪN

Django là gì và hoạt động thế nào?

Django là web framework viết bằng Python, không chỉ là một thư viện nhỏ. Nó cung cấp sẵn routing, ORM, template engine, xác thực, admin, forms và các cơ chế bảo mật quan trọng.

⚡

Phát triển nhanh

Có sẵn nhiều thành phần thường dùng, ít phải viết lại từ đầu.

🗃️

ORM mạnh mẽ

Thao tác dữ liệu bằng Python thay vì viết SQL cho mọi truy vấn.

🛡️

Security by default

Hỗ trợ CSRF, escaping template, quản lý session và mật khẩu.

View trả về HttpResponse trực tiếp, trang HTML qua template, hoặc JSON cho API. Django thường được mô tả bằng kiến trúc MVT (Model – View – Template).

02HƯỚNG DẪN

Cài đặt Python, Django và virtual environment

Dùng Python 3.12 trở lên (trong dải phiên bản Django 6.1.3 hỗ trợ) và tạo môi trường ảo riêng cho dự án.

Bước 1 — Kiểm tra Python

TerminalBASH
python --version
# Windows nếu lệnh python không hoạt động: py --version

Bước 2 — Tạo thư mục và môi trường ảo

Chọn hướng dẫn đúng với hệ điều hành. Toàn bộ các lệnh Python về sau được chạy khi môi trường ảo đã kích hoạt.

Terminal · macOS / LinuxBASH
mkdir django-blog
cd django-blog
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install "Django==6.1.3"
PowerShell · WindowsPOWERSHELL
mkdir django-blog
cd django-blog
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install "Django==6.1.3"
⚠️ Nếu PowerShell chặn Activate.ps1
Có thể dùng .venv\Scripts\python.exe để chạy lệnh Python trong môi trường ảo mà không cần kích hoạt; hoặc kiểm tra chính sách PowerShell của máy. Không nên tắt các cơ chế bảo vệ toàn hệ thống chỉ để chạy tutorial.

Bước 3 — Khởi tạo project + app

TerminalBASH
python -m django --version
# Kỳ vọng: 6.1.3
django-admin startproject config .
python manage.py startapp blog
python manage.py migrate
python manage.py runserver

Truy cập http://127.0.0.1:8000/. Trang chào mừng Django xuất hiện khi cấu hình ban đầu đúng. Dừng server bằng Ctrl + C.

📌 Phân biệt hai lệnh
startproject tạo cấu hình toàn hệ thống; startapp tạo một module chức năng (ví dụ blog, shop, users). Một project có thể chứa nhiều app.

03HƯỚNG DẪN

Hiểu cấu trúc thư mục của Django

Sau khi tạo project và app, bạn sẽ làm việc thường xuyên với những file sau.

django-blog/ ├── manage.py # CLI của Django ├── config/ # Cấu hình project │ ├── __init__.py │ ├── settings.py # Apps, database, middleware... │ ├── urls.py # URL cấp project │ ├── wsgi.py # WSGI entrypoint │ └── asgi.py # ASGI entrypoint ├── blog/ # App của chúng ta │ ├── admin.py │ ├── apps.py │ ├── models.py │ ├── views.py │ ├── tests.py │ ├── migrations/ │ ├── urls.py # Sẽ tự tạo │ ├── forms.py # Sẽ tự tạo │ ├── templates/ # Sẽ tự tạo │ │ ├── blog/ │ │ └── registration/ │ └── static/blog/ # Sẽ tự tạo └── db.sqlite3 # SQLite sau migrate

Lưu ý: Các thư mục màu xanh lá là những file/thư mục bạn tự tạo ở các chương tiếp theo. manage.py nên được chạy từ thư mục gốc chứa file đó.

Project ≠ App

Project quyết định các cài đặt chung. App là một chức năng đóng gói, có thể tái sử dụng.

Migrations ≠ Database

Migration là lịch sử thay đổi schema; db.sqlite3 là file cơ sở dữ liệu chạy thực tế.

05HƯỚNG DẪN

Model, quan hệ dữ liệu và migrations

Model là class Python ánh xạ sang bảng trong database. Ta tạo Post có tác giả liên kết tới tài khoản Django.

blog/models.pyPYTHON
from django.conf import settings
from django.db import models


class Post(models.Model):
    title = models.CharField(max_length=200)
    slug = models.SlugField(max_length=220, unique=True)
    body = models.TextField()
    author = models.ForeignKey(
        settings.AUTH_USER_MODEL,
        on_delete=models.CASCADE,
        related_name="posts",
    )
    is_published = models.BooleanField(default=False)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    class Meta:
        ordering = ["-created_at"]

    def __str__(self):
        return self.title
FieldCông dụng
CharFieldChuỗi ngắn, giới hạn ký tự
SlugFieldChuỗi dùng trong URL; ở đây yêu cầu không trùng
TextFieldNội dung dài
ForeignKeyNhiều bài viết thuộc về một user
auto_now_addĐặt thời điểm tạo
auto_nowCập nhật thời điểm sửa

Chuyển thay đổi model thành bảng dữ liệu

TerminalBASH
python manage.py makemigrations blog
python manage.py migrate
python manage.py showmigrations blog
models.py thay đổi→makemigrations→migration file→migrate→database
⚠️ Điều cần nhớ
makemigrations tạo file mô tả thay đổi, còn migrate mới áp dụng thay đổi vào DB. Hãy commit migration cùng mã nguồn. on_delete=models.CASCADE nghĩa là xóa user sẽ xóa luôn bài viết liên quan; hãy chọn chính sách phù hợp nghiệp vụ.

Django Admin: trang quản trị tự động

Admin có sẵn chức năng thêm, sửa, xóa bản ghi. Đây là công cụ quản trị nội bộ, không thay thế giao diện cho người dùng cuối.

blog/admin.pyPYTHON
from django.contrib import admin
from .models import Post


@admin.register(Post)
class PostAdmin(admin.ModelAdmin):
    list_display = ("title", "author", "is_published", "created_at")
    list_filter = ("is_published", "created_at")
    search_fields = ("title", "body")
    prepopulated_fields = {"slug": ("title",)}

Tạo tài khoản quản trị

TerminalBASH
python manage.py createsuperuser
python manage.py runserver

Đăng nhập tại http://127.0.0.1:8000/admin/. Tạo một vài Post, chọn tác giả, đặt is_published=True, rồi lưu.

💡 Lưu ý slug có dấu
Với tiêu đề tiếng Việt có dấu, hãy kiểm tra giá trị slug được tạo tự động; điều chỉnh thành chuỗi không dấu dạng hoc-django-co-ban để URL dễ chia sẻ.

07HƯỚNG DẪN

Viết Views: danh sách và chi tiết bài viết

View nhận request, truy vấn database và render template. Trang danh sách có phân trang; trang chi tiết chỉ cho xem bài đã xuất bản.

Thay hoàn toàn file view thử nghiệm ở chương 04 bằng phiên bản bên dưới. Các view CRUD sẽ được bổ sung sau.

blog/views.py · giai đoạn đọc dữ liệuPYTHON
from django.core.paginator import Paginator
from django.shortcuts import get_object_or_404, render
from .models import Post


def post_list(request):
    posts = Post.objects.filter(is_published=True).select_related("author")
    paginator = Paginator(posts, 5)  # Mỗi trang 5 bài
    page_obj = paginator.get_page(request.GET.get("page"))
    return render(request, "blog/list.html", {"page_obj": page_obj})


def post_detail(request, slug):
    post = get_object_or_404(Post, slug=slug, is_published=True)
    return render(request, "blog/detail.html", {"post": post})
blog/urls.py · giai đoạn đọc dữ liệuPYTHON
from django.urls import path
from . import views

app_name = "blog"

urlpatterns = [
    path("", views.post_list, name="list"),
    path("bai-viet/<slug:slug>/", views.post_detail, name="detail"),
]

Giải thích nhanh

filter(is_published=True)Chỉ hiển thị bài viết đã xuất bản.
select_related("author")Lấy thông tin tác giả trong cùng truy vấn để tránh N+1 query.
get_object_or_404()Trả HTTP 404 nếu không tìm thấy bài viết phù hợp.
render()Kết hợp template với context để tạo HTTP response.
🔎 HTTP request có gì?
Bạn có thể đọc query string bằng request.GET, dữ liệu form bằng request.POST, người dùng bằng request.user và phương thức bằng request.method.

08HƯỚNG DẪN

Template inheritance, vòng lặp và hiển thị dữ liệu

Template Language (DTL) cho phép tạo trang HTML động bằng các thẻ như {% for %}, {% if %}, {% url %} và biến {{ post.title }}.

Tạo thư mục blog/templates/blog/, sau đó tạo 3 file. Django tìm template trong app nhờ APP_DIRS=True ở cấu hình mặc định.

blog/templates/blog/base.htmlHTML
<!doctype html>
<html lang="vi">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{% block title %}Mini Blog{% endblock %}</title>
  {% load static %}
  <link rel="stylesheet" href="{% static 'blog/style.css' %}">
</head>
<body>
  <header>
    <a href="{% url 'blog:list' %}">Mini Blog</a>
    {% if user.is_authenticated %}
      <a href="{% url 'blog:mine' %}">Bài của tôi</a>
      <a href="{% url 'blog:create' %}">Viết bài</a>
      <form method="post" action="{% url 'logout' %}" class="inline">
        {% csrf_token %}
        <button type="submit">Đăng xuất</button>
      </form>
    {% else %}
      <a href="{% url 'login' %}">Đăng nhập</a>
    {% endif %}
  </header>
  <main>{% block content %}{% endblock %}</main>
</body>
</html>

Các URL blog:mine và blog:create được tạo ở chương 11; login/logout được cấu hình ở chương 12. Hãy hoàn tất những chương đó trước khi chạy toàn bộ giao diện.

blog/templates/blog/list.htmlHTML
{% extends "blog/base.html" %}
{% block title %}Bài viết | Mini Blog{% endblock %}
{% block content %}
<h1>Bài viết mới</h1>
{% for post in page_obj %}
  <article>
    <h2><a href="{% url 'blog:detail' post.slug %}">{{ post.title }}</a></h2>
    <small>{{ post.author.username }} · {{ post.created_at|date:"d/m/Y" }}</small>
    <p>{{ post.body|truncatewords:35 }}</p>
  </article>
{% empty %}
  <p>Chưa có bài viết nào được xuất bản.</p>
{% endfor %}

<nav class="pagination" aria-label="Phân trang">
  {% if page_obj.has_previous %}
    <a href="?page={{ page_obj.previous_page_number }}">← Trước</a>
  {% endif %}
  <span>Trang {{ page_obj.number }}/{{ page_obj.paginator.num_pages }}</span>
  {% if page_obj.has_next %}
    <a href="?page={{ page_obj.next_page_number }}">Sau →</a>
  {% endif %}
</nav>
{% endblock %}
blog/templates/blog/detail.htmlHTML
{% extends "blog/base.html" %}
{% block title %}{{ post.title }} | Mini Blog{% endblock %}
{% block content %}
<article>
  <h1>{{ post.title }}</h1>
  <p>Tác giả: {{ post.author.username }}</p>
  <div>{{ post.body|linebreaks }}</div>
  {% if user.is_authenticated and post.author_id == user.id %}
    <a href="{% url 'blog:edit' post.pk %}">Chỉnh sửa</a>
    <form method="post" action="{% url 'blog:delete' post.pk %}" class="inline">
      {% csrf_token %}
      <button type="submit">Xóa bài</button>
    </form>
  {% endif %}
</article>
<a href="{% url 'blog:list' %}">← Về danh sách</a>
{% endblock %}

Những cú pháp DTL phổ biến

DTLÝ nghĩa
{{ variable }}In giá trị (HTML được escape mặc định)
{% if ... %}Rẽ nhánh điều kiện
{% for ... in ... %}Vòng lặp
{% extends ... %}Kế thừa template
{% block ... %}Định nghĩa vùng thay thế
{% url ... %}Sinh URL theo tên route
{% csrf_token %}Token cho form POST
⚠️ Đừng nhầm hai loại template
{{ ... }} là giá trị; {% ... %} là cú pháp điều khiển. Đừng dùng bộ lọc |safe với nội dung người dùng nhập khi chưa được làm sạch vì có rủi ro XSS.

10HƯỚNG DẪN

Django ORM: tạo, đọc, lọc và tối ưu query

ORM cho phép biểu diễn truy vấn SQL bằng các phương thức Python. Bạn có thể thử trực tiếp trong Django shell.

TerminalBASH
python manage.py shell
Django shellPYTHON
from django.contrib.auth import get_user_model
from blog.models import Post

User = get_user_model()
user = User.objects.first()  # Cần có ít nhất 1 user

# CREATE
post = Post.objects.create(
    title="Học Django từng bước",
    slug="hoc-django-tung-buoc",
    body="Bài đầu tiên của tôi",
    author=user,
    is_published=True,
)

# READ
Post.objects.all()
Post.objects.filter(is_published=True)
Post.objects.get(pk=post.pk)
Post.objects.filter(title__icontains="django")

# UPDATE
post.title = "Django cơ bản"
post.save()

# DELETE — chỉ chạy nếu bạn thật sự muốn xóa
# post.delete()

# Tối ưu nếu template truy cập post.author
Post.objects.select_related("author").all()

# Đếm bài đã xuất bản
Post.objects.filter(is_published=True).count()

QuerySet là gì?

Post.objects.filter(...) trả về QuerySet có tính lazy: thường chỉ truy cập DB khi được đánh giá (lặp, list(), v.v.). get() trả về một object hoặc gây exception nếu không đúng một kết quả.

select_related()

Dùng cho quan hệ ForeignKey / OneToOne, truy vấn theo phép JOIN.

prefetch_related()

Dùng cho quan hệ ManyToMany / reverse ForeignKey, lấy thêm tập dữ liệu bằng truy vấn riêng.

⚠️ SQL injection
Ưu tiên ORM và tham số hóa truy vấn. Tránh ghép chuỗi dữ liệu người dùng vào câu SQL thô. Khi dùng raw() hoặc cursor, hãy truyền tham số đúng cách.

Bước 2 — Bổ sung view CRUD

Giữ nguyên hai view đọc ở chương 07, sau đó thêm các import và hàm sau vào blog/views.py.

blog/views.py · thêm import + các viewPYTHON
from django.contrib.auth.decorators import login_required
from django.shortcuts import redirect
from django.views.decorators.http import require_POST
from .forms import PostForm


@login_required
def my_posts(request):
    posts = Post.objects.filter(author=request.user)
    return render(request, "blog/mine.html", {"posts": posts})


@login_required
def post_create(request):
    form = PostForm(request.POST or None)
    if request.method == "POST" and form.is_valid():
        post = form.save(commit=False)
        post.author = request.user  # Không tin author từ browser
        post.save()
        return redirect("blog:mine")
    return render(request, "blog/form.html", {"form": form, "heading": "Viết bài"})


@login_required
def post_edit(request, pk):
    post = get_object_or_404(Post, pk=pk, author=request.user)
    form = PostForm(request.POST or None, instance=post)
    if request.method == "POST" and form.is_valid():
        form.save()
        return redirect("blog:mine")
    return render(request, "blog/form.html", {"form": form, "heading": "Sửa bài"})


@login_required
@require_POST
def post_delete(request, pk):
    post = get_object_or_404(Post, pk=pk, author=request.user)
    post.delete()
    return redirect("blog:mine")

Tạo JSON API đơn giản với JsonResponse

Django có thể trả JSON mà không cần thêm thư viện. API sau minh họa endpoint GET công khai cho danh sách bài đã xuất bản.

Thêm import và view vào cuối blog/views.py:

blog/views.py · bổ sungPYTHON
from django.http import JsonResponse
from django.views.decorators.http import require_GET


@require_GET
def posts_api(request):
    posts = list(
        Post.objects.filter(is_published=True)
        .values("id", "title", "slug", "created_at")[:20]
    )
    return JsonResponse({"count": len(posts), "results": posts})

Thêm route dưới đây vào trong urlpatterns của blog/urls.py:

blog/urls.py · thêm 1 dòngPYTHON
path("api/posts/", views.posts_api, name="posts_api"),

Truy cập http://127.0.0.1:8000/api/posts/ để xem dữ liệu JSON. Đây là API chỉ đọc, chưa có token auth, pagination chuẩn API hay rate limiting.

🚀 Khi nào nên dùng Django REST Framework?
Với API cần serializers, validation theo schema, authentication, permissions, pagination và CRUD chuẩn REST, bạn có thể học Django REST Framework (DRF). DRF là gói bên thứ ba, không phải thành phần mặc định của Django.

Viết automated tests với Django TestCase

Kiểm thử giúp đảm bảo logic hoạt động sau khi bạn sửa code. Django cung cấp test client giả lập request và test database độc lập.

Thay nội dung blog/tests.py bằng ví dụ dưới. Test chạy được sau khi bạn đã thêm đầy đủ các route và view công khai.

blog/tests.pyPYTHON
from django.contrib.auth import get_user_model
from django.test import TestCase
from django.urls import reverse
from .models import Post


class PostPagesTests(TestCase):
    @classmethod
    def setUpTestData(cls):
        User = get_user_model()
        cls.user = User.objects.create_user(
            username="tester", password="strong-test-password-123"
        )
        cls.published = Post.objects.create(
            title="Public post",
            slug="public-post",
            body="Hello!",
            author=cls.user,
            is_published=True,
        )
        cls.draft = Post.objects.create(
            title="Draft", slug="draft", body="Hidden",
            author=cls.user, is_published=False,
        )

    def test_home_shows_published_post_only(self):
        response = self.client.get(reverse("blog:list"))
        self.assertEqual(response.status_code, 200)
        self.assertContains(response, "Public post")
        self.assertNotContains(response, "Draft")

    def test_published_detail_works(self):
        url = reverse("blog:detail", args=["public-post"])
        self.assertEqual(self.client.get(url).status_code, 200)

    def test_draft_detail_is_hidden(self):
        url = reverse("blog:detail", args=["draft"])
        self.assertEqual(self.client.get(url).status_code, 404)

    def test_create_requires_login(self):
        response = self.client.get(reverse("blog:create"))
        self.assertEqual(response.status_code, 302)
        self.assertIn("/accounts/login/", response["Location"])

Các nguyên tắc bảo mật quan trọng

Django có nhiều lớp bảo vệ sẵn, nhưng cấu hình, phân quyền và xử lý input của ứng dụng vẫn là trách nhiệm của lập trình viên.

01

CSRF

Giữ middleware CSRF, đặt {% csrf_token %} trong form POST.

02

XSS

Template escape HTML mặc định; thận trọng với |safe và HTML người dùng cung cấp.

03

Quyền truy cập

Kiểm tra ownership / permission trong view, không chỉ ở frontend.

04

Secrets

Không commit secret key, password DB hoặc token vào Git.

05

HTTPS

Thiết lập HTTPS, secure cookie và chính sách redirect phù hợp ở production.

06

Dependencies

Cập nhật bản vá bảo mật của Django và các package đã cài.

Ví dụ cấu hình đọc biến môi trường

import os

SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]
DEBUG = os.environ.get("DJANGO_DEBUG", "0") == "1"

    host.strip()
    for host in os.environ.get("DJANGO_ALLOWED_HOSTS", "").split(",")

SESSION_COOKIE_SECURE = True

18HƯỚNG DẪN

Lỗi thường gặp khi mới học Django

Bảng dưới là những lỗi dễ gặp nhất và cách kiểm tra nhanh. Hãy đọc đầy đủ traceback thay vì chỉ xem dòng cuối.

ModuleNotFoundError: No module named 'django'+

Kiểm tra đã kích hoạt đúng .venv chưa; chạy python -m pip show Django và python -m django --version. Có thể terminal đang sử dụng Python khác.

ModuleNotFoundError: No module named 'blog.urls'+

App mới tạo chưa có file blog/urls.py. Hãy tự tạo file đúng tên, kiểm tra đường dẫn và lỗi typo.

TemplateDoesNotExist+

Kiểm tra blog/templates/blog/list.html, APP_DIRS=True, tên template trong render() và app đã được khai báo ở INSTALLED_APPS.

no such table: blog_post+

Đã tạo model nhưng chưa chạy python manage.py makemigrations blog và python manage.py migrate, hoặc đang kết nối nhầm database.

Reverse for 'mine' not found+

Bạn đang dùng base.html của chương 08 nhưng chưa khai báo route blog:mine ở chương 11. Hoàn thiện các chương liên quan trước khi chạy.

403 CSRF verification failed+

Kiểm tra form method="post" có {% csrf_token %} chưa, middleware CSRF còn hoạt động không và cấu hình origin/trusted origins của môi trường triển khai.

DisallowedHost / Bad Request (400)+

Đặt hostname thực tế vào ALLOWED_HOSTS. Tránh dùng wildcard không kiểm soát trong production.

Trang 404 cho bài vừa tạo+

Trang post_detail chỉ trả bài có is_published=True. Bài nháp xem và sửa qua trang Bài của tôi.
