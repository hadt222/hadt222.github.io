01 / START HERE

Tailwind CSS trong 5 phút

Hiểu cách Tailwind làm việc, khi nào nên dùng và hành trình từ class đầu tiên đến giao diện hoàn chỉnh.

Tailwind CSS là gì?

Tailwind là một utility-first CSS framework: thay vì viết nhiều selector CSS cho từng component, bạn ghép các class nhỏ có mục đích rõ ràng ngay trong HTML/JSX, như p-6, rounded-xl hoặc text-slate-800.

Tailwind không phải thư viện component dựng sẵn. Nó cung cấp các “viên gạch” để bạn tự thiết kế giao diện theo ý muốn.

03 / CORE IDEA

Tư duy utility-first

Chuyển từ “đặt tên class CSS” sang “ghép các utility có ý nghĩa”, vẫn giữ code dễ đọc.

Đọc class như một câu lệnh CSS

Mỗi class thường điều khiển một (nhóm) thuộc tính cụ thể. Các class được ghép với nhau để tạo thành component mà không cần đặt tên selector mới.

HTML
<button class="bg-indigo-600 px-5 py-3 text-white font-semibold
               rounded-xl shadow-lg hover:bg-indigo-700
               focus-visible:outline-2 focus-visible:outline-offset-2
               focus-visible:outline-indigo-600 transition-colors">
  Đăng ký ngay
</button>
Preview: nút có hover và focus
bg-* nềnpx-* ngangpy-* dọctext-* chữrounded-* bo góchover:* khi rê chuột
✓
Cú pháp ghép biến thể

Quy tắc: [variant:]*utility. Ví dụ md:hover:bg-blue-700 nghĩa là áp dụng nền xanh khi hover ở màn hình từ md trở lên.

Tailwind “nhìn” code như thế nào?

Build tool quét các file nguồn tìm tên class đầy đủ, rồi sinh CSS tương ứng. Không phải ứng dụng phải tải một file CSS khổng lồ chứa mọi utility. Trong phần Build & tối ưu bạn sẽ học các lỗi liên quan đến việc phát hiện class.

04 / FOUNDATIONS

Spacing & kích thước

Nắm box model, trục X/Y, giới hạn độ rộng và quy tắc thang spacing.

Spacing: margin, padding và gap

p-4 là padding bốn phía; px-6 chỉ trái/phải; mt-4 là margin-top; gap-4 là khoảng giữa các item trong flex/grid.

HTML
<div class="mx-auto max-w-2xl p-6">
  <h2 class="mb-4 text-2xl">Khóa học</h2>
  <div class="flex gap-3">
    <span class="rounded-lg bg-blue-100 px-3 py-2">HTML</span>
    <span class="rounded-lg bg-blue-100 px-3 py-2">CSS</span>
  </div>
</div>
Nội dung
Padding
Margin
margin → bên ngoài phần tử
padding → bên trong phần tử
gap → giữa các phần tử

Đọc thang kích thước

Với cấu hình mặc định, nhiều utility spacing dựa trên biến --spacing: 0.25rem (thường tương đương 4px khi root font-size là 16px). Vì vậy p-4 ≈ 16px, p-6 ≈ 24px và p-8 ≈ 32px.

10 / INTERACTIONS

Hover, focus & variants

Biến đổi giao diện theo trạng thái mà không cần viết selector thủ công.

States là các điều kiện hiển thị

Những class như hover:, focus-visible:, active: hay disabled: chỉ có hiệu lực trong trạng thái tương ứng. Có thể kết hợp nhiều variant.

HTML
<button class="rounded-xl bg-indigo-600 px-5 py-3 text-white
  transition hover:bg-indigo-700 hover:-translate-y-0.5
  active:translate-y-0 disabled:cursor-not-allowed
  disabled:opacity-50 focus-visible:outline-2
  focus-visible:outline-offset-2 focus-visible:outline-indigo-600">
  Gửi thông tin
</button>

group & peer: trạng thái từ phần tử khác

HTML
<!-- Khi hover cả card, tiêu đề đổi màu -->
<a class="group block rounded-xl border p-5 hover:border-indigo-500" href="#">
  <h3 class="font-bold group-hover:text-indigo-600">Khóa HTML</h3>
  <p class="text-slate-500">Khóa học nền tảng.</p>
</a>

<!-- Peer giúp hiện thông báo khi input không hợp lệ -->

       type="email" placeholder="Email" required />

11 / THEMING

Dark Mode

Từ chế độ tự động theo hệ điều hành đến công tắc theme do người dùng điều khiển.

Dark mode: hai cách hoạt động

Theo mặc định, dark: dùng prefers-color-scheme của hệ điều hành. Nếu muốn người dùng tự bật/tắt, bạn cần tự định nghĩa variant dựa trên class hoặc data attribute.

CSS
/* src/style.css — bật dark mode theo class .dark */
@import "tailwindcss";
@custom-variant dark (&:where(.dark, .dark *));
HTML
<html class="dark">
  <div class="bg-white text-slate-900 dark:bg-slate-900 dark:text-white">
    Nội dung theo theme
  </div>
</html>

JavaScript bật/tắt class dark tại <html>:

JavaScript
const root = document.documentElement;
const isDark = root.classList.toggle('dark');
localStorage.setItem('theme', isDark ? 'dark' : 'light');

Trong Tailwind v4, bạn có thể định nghĩa biến chủ đề trong CSS bằng @theme. Biến thuộc đúng namespace sẽ sinh utility tương ứng, ví dụ --color-brand-500 → bg-brand-500, text-brand-500.

CSS
/* src/style.css */
@import "tailwindcss";

@theme {
  --color-brand-500: #7357ff;
  --color-brand-700: #4d32d6;
  --font-display: "Inter", ui-sans-serif, sans-serif;
  --radius-card: 1.25rem;
  --breakpoint-3xl: 120rem;
}
HTML
<section class="rounded-card bg-brand-500 p-6 text-white
               3xl:p-12">
  <h2 class="font-display text-3xl font-bold">Thương hiệu của bạn</h2>
  <button class="mt-4 rounded-lg bg-brand-700 px-4 py-2">
    Bắt đầu
  </button>
</section>

Thay token một lần, dùng lại khắp ứng dụng.

CSS variables và tùy biến

@theme khác với biến CSS thông thường: các biến namespace như --color-*, --font-*, --radius-* được Tailwind sử dụng để tạo utility. Khi chỉ cần biến nội bộ mà không sinh utility, dùng :root thông thường.

✓

V4 ưu tiên cấu hình trong CSS. Những project nâng cấp từ v3 có thể dùng @config để nạp cấu hình JavaScript cũ (với giới hạn tương thích), nhưng tutorial mới nên bắt đầu bằng @theme.

Arbitrary values & variants

Tùy chỉnh pixel, màu, shadow và selector khi utility mặc định không bao quát hết.

Khi giá trị mặc định chưa đủ

Square brackets [...] cho phép nhập giá trị CSS trực tiếp. Hữu ích cho trường hợp đặc biệt, nhưng dùng quá nhiều dễ làm mất tính nhất quán.

HTML

            bg-[#f0f4ff] p-[18px] shadow-[0_12px_40px_#1e1b4b20]">

Với CSS variable, bạn có thể dùng cú pháp thích hợp như bg-(--my-color) hoặc trực tiếp bg-[var(--my-color)].

HTML
<div style="--card-color: #0f766e"
     class="rounded-xl bg-(--card-color) px-5 py-3 text-white">
  Nền theo biến CSS
</div>

16 / ADVANCED

Kết hợp Tailwind và CSS thuần

@utility, @apply, @reference và cách tránh “lạm dụng utility” trong dự án thật.

Khi nào nên viết CSS thuần?

Tailwind không cấm CSS. Với animation đặc biệt, selector phức tạp hoặc mã bên thứ ba, CSS truyền thống vẫn hữu ích. Hãy dùng công cụ phù hợp thay vì cố nhét mọi thứ vào class HTML.

CSS
@import "tailwindcss";

/* Tạo custom utility có hỗ trợ variants */
@utility content-auto {
  content-visibility: auto;
}

/* CSS bình thường cho thư viện bên thứ ba */
.third-party-widget {
  isolation: isolate;
}

@apply có nên dùng?

@apply chèn utility đã có vào CSS rule. Rất tiện cho selector không sửa markup được, nhưng không nên mặc định dùng để biến toàn bộ Tailwind thành CSS truyền thống.

CSS
@import "tailwindcss";

.article-content a {
  @apply font-medium text-indigo-600 underline;
}

Nếu bạn viết @apply trong CSS được xử lý tách biệt (ví dụ <style> của Vue/Svelte), có thể cần @reference đến stylesheet chính hoặc Tailwind để công cụ biết tokens và utilities.

CSS
/* Ví dụ trong CSS module / style block tách biệt */
@reference "./app.css";

.title {
  @apply text-2xl font-bold;
}
i
Lưu ý Preflight

Tailwind áp dụng base reset (Preflight), vì vậy h1 không tự có cỡ chữ lớn và ul không tự hiển thị dấu bullet. Hãy thêm utility một cách chủ động.

17 / PRODUCTION

Build & tối ưu production

Tìm class đúng cách, tránh lỗi class động, cấu hình nguồn và đóng gói dự án.

Tailwind v4 tạo CSS như thế nào?

Trình biên dịch tìm class trong các file nguồn và chỉ sinh CSS cần thiết. Đây là lý do bạn nên dùng class name đầy đủ và kiểm tra đường dẫn nguồn.

JavaScript
// ❌ Sai: nối chuỗi tùy ý có thể không được phát hiện
const color = 'red';
const badge = `bg-${color}-500`;

// ✅ Đúng: liệt kê nguyên class trong source
const badgeStyles = {
  error: 'bg-red-500 text-white',
  success: 'bg-green-500 text-white',
};
const status = 'success';
const badge = badgeStyles[status];

Cho Tailwind biết các source đặc biệt

CSS
@import "tailwindcss";

/* Thêm thư mục nằm ngoài vùng tự động quét */
@source "../shared-components";

/* Bắt buộc sinh utility không xuất hiện trực tiếp trong source */
@source inline("bg-red-500 hover:bg-red-600 text-white");

Build production

Nếu dùng Vite, chạy npm run build để tạo thư mục đầu ra (thường là dist/). Nếu dùng CLI, chạy một lần không có --watch và phục vụ HTML cùng CSS đã biên dịch.

Terminal
# Vite
npm run build

# CLI (dùng file nguồn và đích đúng với cấu trúc của bạn)
npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --minify
!
Không dùng Play CDN cho production

CDN dành cho học và thử nghiệm. Vite/CLI tạo file CSS tĩnh có thể cache, triển khai và tối ưu tốt hơn.

18 / DEBUG

6 lỗi thường gặp

Những lỗi phổ biến nhất khi chuyển từ Tailwind v3 sang v4 hoặc khi đóng gói dự án.

01 Class không có tác dụng sau khi build
Kiểm tra utility có đúng chính tả, file nguồn có nằm trong vùng quét và tên class có được viết đầy đủ hay không. Tránh nối string kiểu `bg-${'color'}-500`. Nếu source đặc biệt, dùng @source.
02 npx tailwindcss init -p không chạy
Đây là bước quen thuộc của Tailwind v3. Với v4, hãy dùng @tailwindcss/vite hoặc @tailwindcss/cli, import "tailwindcss" trong CSS, cấu hình theme qua @theme.
03 dark: không đổi khi click
Mặc định dark mode theo hệ điều hành. Nếu bật thủ công bằng class, cần khai báo @custom-variant dark (&:where(.dark, .dark *)); trong CSS rồi thêm dark trên phần tử cha như <html>.
04 @apply báo unknown utility
Kiểm tra file có được Tailwind xử lý không. Với CSS module hoặc style block riêng, cân nhắc @reference đến stylesheet chứa theme. Hạn chế @apply nếu viết utility ngay trong markup đơn giản hơn.
05 H1, ul, button khác mặc định trình duyệt
Đó có thể là Preflight reset. Hãy đặt cỡ chữ, font-weight, list-style và background chủ động. Điều này giúp tạo hệ thống thiết kế đồng nhất.
06 CSS tải được nhưng trang vẫn không có style
Kiểm tra file CSS có @import "tailwindcss", đã được import vào entry Vite hoặc link từ HTML, đường dẫn có đúng và dev server / build process có đang chạy không.
