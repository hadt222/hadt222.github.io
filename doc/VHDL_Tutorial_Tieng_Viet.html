VHDL là gì?

Phân biệt mô tả phần cứng với lập trình phần mềm.

VHDL (VHSIC Hardware Description Language) là ngôn ngữ mô tả và kiểm chứng mạch số, thường dùng trong thiết kế FPGA, ASIC, điều khiển số, vi xử lý và các khối giao tiếp.

Phần mềm (Python / C)

Câu lệnh thường được thực thi theo luồng điều khiển của CPU.

x = a + b

Được biên dịch hoặc thông dịch để chạy trên bộ xử lý.

VHDL (thiết kế RTL)

Mô tả các khối mạch tồn tại và hoạt động song song.

sum <= a + b;

Được mô phỏng hoặc tổng hợp thành các phần tử logic/flip-flop.

Quy trình thiết kế

RTL (Register Transfer Level) mô tả cách dữ liệu đi qua logic tổ hợp giữa các thanh ghi theo từng chu kỳ clock. Simulation kiểm chứng hành vi; synthesis chuyển mô tả phù hợp thành cấu trúc phần cứng thực.

!
Không phải mọi mã VHDL đều tổng hợp được

Các câu lệnh wait for 10 ns, thao tác file và một số cấu trúc mô phỏng hợp lệ trong testbench nhưng thường không tổng hợp thành phần cứng.

Entity & Architecture

Hai khối quan trọng nhất của một module VHDL.

Entity khai báo tên và giao diện cổng; architecture mô tả phần logic bên trong. library và use đưa các kiểu và package vào phạm vi sử dụng.

and_gate.vhd
library ieee;
use ieee.std_logic_1164.all;

entity and_gate is
    port (
        a, b : in  std_logic;
        y    : out std_logic
    );
end entity and_gate;

architecture rtl of and_gate is
begin
    y <= a and b;
end architecture rtl;

Giải thích từng phần

Thành phầnÝ nghĩa
entity and_gateKhai báo giao diện khối mạch
portKhai báo các đường tín hiệu vào/ra
in, outHướng của cổng tín hiệu
architecture rtlPhần triển khai của entity
begin ... endChứa các statement đồng thời
<=Gán tín hiệu (signal assignment)

Một entity có thể có nhiều architecture (hành vi, RTL, structural), nhưng mỗi lần elaborate sẽ chọn một triển khai.

Ví dụ khác: cổng XOR 2 đầu vào
library ieee;
use ieee.std_logic_1164.all;

entity xor_gate is
    port (a, b : in std_logic; y : out std_logic);
end entity;

architecture rtl of xor_gate is
begin
    y <= a xor b;
end architecture;

Kiểu dữ liệu & Numeric

std_logic, vector, signed/unsigned, integer, boolean.

VHDL là ngôn ngữ kiểm tra kiểu chặt. Không nên trộn lẫn std_logic_vector và số học mà không chuyển kiểu rõ ràng.

KiểuVí dụKhi nào dùng
std_logicsignal en : std_logic;Tín hiệu 1 bit
std_logic_vector(7 downto 0)Bus bit chưa có ý nghĩa số học
unsignedunsigned(7 downto 0)Số nguyên không dấu
signedsigned(7 downto 0)Số nguyên có dấu bù 2
integer range0 to 255Giá trị hoặc chỉ số giới hạn
booleantrue / falseĐiều kiện logic trong mô tả

std_logic có 9 giá trị mô phỏng: U, X, 0, 1, Z, W, L, H, -. Hai trạng thái U/X thường báo thiếu khởi tạo hoặc xung đột/không xác định; không thể coi chúng là số nhị phân bình thường.

numeric_std — phép cộng đúng kiểu
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity add8 is
    port (
        a, b : in  std_logic_vector(7 downto 0);
        y    : out std_logic_vector(8 downto 0)
    );
end entity;

architecture rtl of add8 is
begin
    y <= std_logic_vector(
        resize(unsigned(a), 9) + resize(unsigned(b), 9)
    );
end architecture;

Các chuyển đổi hữu ích: unsigned(v), signed(v), std_logic_vector(x), to_unsigned(n, width), to_signed(n, width), to_integer(x), resize(x, width).

✓
Thói quen quan trọng

Sử dụng ieee.numeric_std.all cho số học. Tránh các package không chuẩn hoặc legacy như std_logic_unsigned và std_logic_arith khi viết dự án mới.

library ieee;
use ieee.std_logic_1164.all;

entity bit_ops is
    port (
        high : in  std_logic_vector(3 downto 0);
        low  : in  std_logic_vector(3 downto 0);
        sel  : in  std_logic;
        y    : out std_logic_vector(7 downto 0)
    );
end entity;

architecture rtl of bit_ops is
begin
    y <= high & low when sel = '1' else low & high;
end architecture;

Song song & Process

Tại sao thứ tự các câu lệnh VHDL có thể gây nhầm lẫn.

Các câu lệnh ở mức architecture là concurrent: nhiều mạng logic hoạt động cùng lúc. Bên trong process, statement được đánh giá theo thứ tự tuần tự (sequential), nhưng gán signal thường chỉ cập nhật sau khi process tạm dừng (delta cycle).

Hai mô tả tương đương về logic tổ hợpĐối chiếu: tín hiệu y phụ thuộc x, có thể cần thêm delta cycle trong mô phỏng
-- Dạng concurrent
x <= a and b;
y <= x or c;

-- Dạng process (mô tả logic tổ hợp)
process(all)
begin
    x <= a and b;
    y <= x or c;
end process;

Với process(all) (VHDL-2008), công cụ tự tạo danh sách sensitivity đầy đủ. Signal assignment <= được lên lịch; variable assignment := có hiệu lực ngay trong process.

Variable vs signal
process(all)
    variable temp : std_logic;
begin
    temp := a and b;  -- cập nhật variable ngay
    y <= temp or c;  -- dùng giá trị temp vừa tính
end process;
✦
Chọn kiểu mô tả

Dùng process(all) cho logic tổ hợp, process(clk) hoặc process(clk, rst_n) cho logic tuần tự. Không dùng variable để “giả lập” độ trễ phần cứng.

Logic tổ hợp

MUX, decoder, adder và tránh tạo latch ngoài ý muốn.

Multiplexer 2:1

mux2.vhd
library ieee;
use ieee.std_logic_1164.all;

entity mux2 is
    port (a, b, sel : in std_logic; y : out std_logic);
end entity;

architecture rtl of mux2 is
begin
    y <= a when sel = '0' else b;
end architecture;

Full adder 1-bit

full_adder.vhd
library ieee;
use ieee.std_logic_1164.all;

entity full_adder is
    port (
        a, b, cin : in  std_logic;
        s, cout  : out std_logic
    );
end entity;

architecture rtl of full_adder is
begin
    s    <= a xor b xor cin;
    cout <= (a and b) or (cin and (a xor b));
end architecture;

Process tổ hợp đầy đủ nhánh

ALU 4-bit đơn giản (tùy lựa chọn)
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity alu4 is
    port (
        a, b : in  unsigned(3 downto 0);
        op   : in  std_logic_vector(1 downto 0);
        y    : out unsigned(3 downto 0)
    );
end entity;

architecture rtl of alu4 is
begin
    process(all)
    begin
        case op is
            when "00"   => y <= a + b;
            when "01"   => y <= a - b;
            when "10"   => y <= a and b;
            when others => y <= a or b;
        end case;
    end process;
end architecture;
!
Lỗi inferred latch

Nếu y không được gán trong mọi nhánh của process tổ hợp, synthesis có thể suy ra latch để giữ giá trị cũ. Hãy có default hoặc nhánh others, trừ khi thực sự thiết kế latch.

Flip-flop & Reset

Mạch tuần tự: cập nhật dữ liệu tại cạnh clock.

Flip-flop (DFF) lưu 1 bit hoặc 1 từ dữ liệu. Mẫu rising_edge(clk) giúp công cụ nhận diện phần tử tuần tự.

dff_en.vhd — synchronous reset + clock enable
library ieee;
use ieee.std_logic_1164.all;

entity dff_en is
    port (
        clk, rst, en : in  std_logic;
        d            : in  std_logic;
        q            : out std_logic
    );
end entity;

architecture rtl of dff_en is
    signal q_reg : std_logic := '0';
begin
    process(clk)
    begin
        if rising_edge(clk) then
            if rst = '1' then
                q_reg <= '0';
            elsif en = '1' then
                q_reg <= d;
            end if;
        end if;
    end process;

    q <= q_reg;
end architecture;

Reset đồng bộ và bất đồng bộ

Tiêu chíSynchronous resetAsynchronous reset
Thời điểm có hiệu lựcCạnh clock hoạt độngNgay khi reset được kích hoạt
Sensitivity listprocess(clk)process(clk, rst_n)
Mẫu lệnhif rising_edge(clk) then if rst ...if rst_n = '0' then ... elsif rising_edge(clk)
Lưu ýCần clock để xóa trạng tháiCần chú ý thời điểm deassert reset
Ví dụ reset bất đồng bộ active-low
process(clk, rst_n)
begin
    if rst_n = '0' then
        q_reg <= '0';
    elsif rising_edge(clk) then
        q_reg <= d;
    end if;
end process;
✓
Tính khả thi trên FPGA

Không có một kiểu reset tốt nhất cho mọi thiết bị. Chọn chiến lược reset theo tài liệu FPGA/ASIC, xử lý deassert reset đúng cách và tránh tạo “clock giả” bằng logic tùy tiện.

Counter & Generic

Xây dựng bộ đếm N-bit có thể tái sử dụng.

generic là tham số cấu hình ở thời điểm elaborate. Kiểu unsigned giúp bộ đếm tăng/giảm mà không cần ép kiểu phức tạp.

counter.vhd — thiết kế chính (DUT)
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity counter is
    generic (WIDTH : positive := 4);
    port (
        clk : in  std_logic;
        rst : in  std_logic; -- active-high, synchronous
        en  : in  std_logic;
        q   : out std_logic_vector(WIDTH-1 downto 0)
    );
end entity;

architecture rtl of counter is
    signal count : unsigned(WIDTH-1 downto 0) := (others => '0');
begin
    process(clk)
    begin
        if rising_edge(clk) then
            if rst = '1' then
                count <= (others => '0');
            elsif en = '1' then
                count <= count + 1;
            end if;
        end if;
    end process;

    q <= std_logic_vector(count);
end architecture;

Khi WIDTH=4, bộ đếm có 16 trạng thái: từ 0 đến 15 rồi quay về 0 (overflow modulo 16).

FSM — Máy trạng thái

Thiết kế điều khiển bằng các trạng thái xác định.

FSM (Finite State Machine) có thể mô tả theo phong cách Moore (đầu ra dựa vào trạng thái) hoặc Mealy (đầu ra dựa vào trạng thái và đầu vào). Dưới đây là bộ điều khiển có ba trạng thái IDLE, RUN, DONE.

fsm_controller.vhd — FSM Moore hai process
library ieee;
use ieee.std_logic_1164.all;

entity fsm_controller is
    port (
        clk, rst : in  std_logic;
        start    : in  std_logic;
        finish_i : in  std_logic;
        busy     : out std_logic;
        done     : out std_logic
    );
end entity;

architecture rtl of fsm_controller is
    type state_t is (IDLE, RUN, DONE_STATE);
    signal state, next_state : state_t := IDLE;
begin
    -- State register
    process(clk)
    begin
        if rising_edge(clk) then
            if rst = '1' then
                state <= IDLE;
            else
                state <= next_state;
            end if;
        end if;
    end process;

    -- Next-state + Moore outputs
    process(all)
    begin
        next_state <= state;
        busy <= '0';
        done <= '0';
        case state is
            when IDLE =>
                if start = '1' then
                    next_state <= RUN;
                end if;
            when RUN =>
                busy <= '1';
                if finish_i = '1' then
                    next_state <= DONE_STATE;
                end if;
            when DONE_STATE =>
                done <= '1';
                next_state <= IDLE;
        end case;
    end process;
end architecture;
IDLEchờ start
→
RUNbusy = 1
→
DONEdone = 1
↺

Nếu start được nhận ở IDLE, trạng thái chuyển sang RUN ở cạnh clock tiếp theo. Khi finish_i = '1' trong RUN, chuyển sang DONE_STATE tại cạnh kế tiếp; done được giữ ở mức 1 trong thời gian FSM ở trạng thái DONE_STATE.

✓
Mẫu FSM tốt

Dùng kiểu enum cho state, có giá trị mặc định ở process tổ hợp, định nghĩa rõ reset và tránh tạo latch. Cần chú ý timing và cách mã hóa state do công cụ synthesis lựa chọn.

Hierarchy & Port Map

Ghép các module thành hệ thống lớn.

Tư duy phân cấp chia hệ thống thành các thành phần độc lập có giao diện rõ ràng. Dùng entity work.module_name để instantiate module đã compile trong thư viện work.

top.vhd — instantiate counter với generic
library ieee;
use ieee.std_logic_1164.all;

entity top is
    port (
        clk, rst : in  std_logic;
        led      : out std_logic_vector(7 downto 0)
    );
end entity;

architecture structural of top is
begin
    u_counter : entity work.counter
        generic map (WIDTH => 8)
        port map (
            clk => clk,
            rst => rst,
            en  => '1',
            q   => led
        );
end architecture;

Package, Function & Procedure

Gom định nghĩa chung và logic tái sử dụng.

package lưu constant, type, subtype, function, procedure dùng chung. Phân biệt package declaration với package body khi hàm có phần triển khai.

math_pkg.vhd — package ví dụ
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

package math_pkg is
    constant WORD_W : positive := 8;
    function saturating_inc(x : unsigned) return unsigned;
end package;

package body math_pkg is
    function saturating_inc(x : unsigned) return unsigned is
        variable r : unsigned(x'range);
    begin
        r := x;
        if x /= (x'range => '1') then
            r := x + 1;
        end if;
        return r;
    end function;
end package body;

Hàm saturating_inc tăng 1 và giữ nguyên khi đã đạt mức tối đa (khác với counter modulo). Có thể dùng trong một architecture khác với use work.math_pkg.all; sau khi phân tích package.

Sử dụng package trong module
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;
use work.math_pkg.all;

-- Trong architecture:
-- signal value : unsigned(WORD_W-1 downto 0);
-- value <= saturating_inc(value);

Array, Record & RAM

Kiểu phức hợp và bộ nhớ đồng bộ.

Array mô tả một dãy phần tử, record nhóm nhiều trường, còn RAM thường dùng mảng từ dữ liệu với truy cập địa chỉ. Việc ánh xạ sang block RAM phụ thuộc cú pháp, cấu hình và công cụ FPGA.

Định nghĩa kiểu array và record
-- Trong declarative region hoặc package:
type byte_array_t is array (natural range <>) of
    std_logic_vector(7 downto 0);

type packet_t is record
    valid : std_logic;
    addr  : unsigned(7 downto 0);
    data  : std_logic_vector(15 downto 0);
end record;

RAM 16 × 8 bit

ram16x8.vhd — synchronous read và write
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity ram16x8 is
    port (
        clk  : in  std_logic;
        we   : in  std_logic;
        addr : in  unsigned(3 downto 0);
        din  : in  std_logic_vector(7 downto 0);
        dout : out std_logic_vector(7 downto 0)
    );
end entity;

architecture rtl of ram16x8 is
    type ram_t is array (0 to 15) of std_logic_vector(7 downto 0);
    signal mem : ram_t;
    signal dout_reg : std_logic_vector(7 downto 0);
begin
    process(clk)
    begin
        if rising_edge(clk) then
            if we = '1' then
                mem(to_integer(addr)) <= din;
            end if;
            dout_reg <= mem(to_integer(addr));
        end if;
    end process;
    dout <= dout_reg;
end architecture;
!
Read-during-write

Khi đọc và ghi cùng địa chỉ tại một cạnh clock, giá trị dout_reg trong mô phỏng mã trên là dữ liệu bộ nhớ trước cạnh đó (read-first). Chế độ RAM thực tế và tương thích synthesis phải được kiểm tra theo IP/tool và thiết bị đích.

Timing & Pipelining

Tăng tần số hoạt động nhờ chia đường truyền logic.

Trong thiết kế synchronous, dữ liệu phải đi từ FF nguồn qua combinational path và ổn định trước cạnh clock của FF đích. Critical path quyết định chu kỳ tối thiểu có thể đạt được (còn phụ thuộc clock uncertainty, skew, setup time và routing).

Tclock ≳ Tclk→Q + Tlogic + Troute + Tsetup + các hiệu chỉnh timing

Pipelining thêm các thanh ghi trung gian, giảm độ dài logic mỗi giai đoạn để tăng throughput hoặc khả năng chạy clock nhanh hơn; đổi lại tăng độ trễ tính bằng số chu kỳ và tiêu thụ tài nguyên.

pipeline_add.vhd — cộng 2 tầng thanh ghi
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;

entity pipeline_add is
    port (
        clk : in  std_logic;
        a,b : in  unsigned(7 downto 0);
        y   : out unsigned(8 downto 0)
    );
end entity;

architecture rtl of pipeline_add is
    signal sum_stage : unsigned(8 downto 0);
    signal out_stage : unsigned(8 downto 0);
begin
    process(clk)
    begin
        if rising_edge(clk) then
            sum_stage <= resize(a,9) + resize(b,9);
            out_stage <= sum_stage;
        end if;
    end process;
    y <= out_stage;
end architecture;

Ví dụ này minh họa hai mức đăng ký, còn phép cộng vẫn nằm trọn trong tầng đầu (không chia nội bộ carry chain). Dữ liệu tại cạnh clock được thể hiện ở đầu ra sau hai lần đăng ký; cần thiết kế valid pipeline nếu các chu kỳ đầu không có dữ liệu hợp lệ.

Setup / HoldCác ràng buộc ổn định dữ liệu quanh cạnh clock

Clock Domain Crossing

CDC, metastability và nguyên tắc đồng bộ tín hiệu.

Một tín hiệu đi từ clock domain A sang clock domain B có thể thay đổi quá gần cạnh lấy mẫu và gây metastability. Với tín hiệu điều khiển 1-bit chậm, cấu trúc đồng bộ 2 flip-flop trong clock domain nhận thường là lựa chọn cơ bản.

sync_2ff.vhd — đồng bộ một bit
library ieee;
use ieee.std_logic_1164.all;

entity sync_2ff is
    port (
        clk_dst : in  std_logic;
        async_in : in std_logic;
        sync_out : out std_logic
    );
end entity;

architecture rtl of sync_2ff is
    signal meta, stable : std_logic := '0';
begin
    process(clk_dst)
    begin
        if rising_edge(clk_dst) then
            meta   <= async_in;
            stable <= meta;
        end if;
    end process;
    sync_out <= stable;
end architecture;

Quy tắc thiết kế CDC

  • Tín hiệu nhiều bit cần handshake, Gray coding hoặc asynchronous FIFO thích hợp; không tự đồng bộ từng bit độc lập.
  • Xung ngắn từ domain nhanh sang domain chậm có thể bị bỏ lỡ; cần pulse stretching hoặc handshake.
  • Cần xử lý reset release/deassert phù hợp clock domain và yêu cầu hệ thống.
  • Giữ các stage đồng bộ gần nhau theo hướng dẫn vendor, khai báo thuộc tính synchronizer/CDC constraints khi cần.
!
Không thể “xóa bỏ” metastability

Synchronizer giảm xác suất lỗi xuống mức chấp nhận được, không bảo đảm tuyệt đối. Phải đánh giá MTBF, tần số clock/data, và đường reset cho ứng dụng thực tế.

Testbench cơ bản

Tạo clock, kích thích đầu vào và kiểm tra kết quả tự động.

Testbench là entity không có port ngoài; bên trong instantiate DUT, cấp clock/reset và tạo các tình huống kiểm tra. Mã testbench có thể dùng cấu trúc không synthesizable như wait for hoặc report.

tb_counter.vhd — kiểm chứng bộ đếm 4-bit
library ieee;
use ieee.std_logic_1164.all;
use ieee.numeric_std.all;
use std.env.all; -- VHDL-2008

entity tb_counter is
end entity;

architecture sim of tb_counter is
    signal clk : std_logic := '0';
    signal rst : std_logic := '1';
    signal en  : std_logic := '0';
    signal q   : std_logic_vector(3 downto 0);
begin
    -- Đồng hồ 100 MHz (chu kỳ 10 ns)
    clk <= not clk after 5 ns;

    dut : entity work.counter
        generic map (WIDTH => 4)
        port map (clk => clk, rst => rst, en => en, q => q);

    stim : process
    begin
        -- Reset bằng một cạnh clock
        wait until rising_edge(clk);
        wait for 1 ns;
        assert q = "0000" report "Reset failed" severity failure;
        rst <= '0';
        en <= '1';

        -- Sau 3 cạnh clock: q = 3
        for i in 1 to 3 loop
            wait until rising_edge(clk);
            wait for 1 ns;
            assert unsigned(q) = to_unsigned(i, 4)
                report "Counter mismatch" severity failure;
        end loop;

        -- Disable: phải giữ nguyên q
        en <= '0';
        wait until rising_edge(clk);
        wait for 1 ns;
        assert q = "0011" report "Enable failed" severity failure;

        report "PASS: all counter tests completed" severity note;
        finish;
    end process;
end architecture;

Tại sao lại có wait for 1 ns trong testbench?

Vì process của DUT cập nhật signal sau cạnh clock và một hoặc nhiều delta cycle. Chờ một khoảng nhỏ sau cạnh clock giúp assertion đọc đầu ra đã cập nhật. Trong testbench lớn có thể dùng cơ chế wait on, clocking protocol hoặc kiểm thử theo phase rõ ràng.

✓
Testbench phải tự thất bại khi có lỗi

Dùng assert ... severity failure và kết thúc mô phỏng rõ ràng. Một waveform “trông có vẻ đúng” chưa đủ để chứng minh DUT đúng.

Assertions & Verification

Kiểm thử biên, coverage, self-checking và tiến trình debug.

Testbench tốt không chỉ kiểm tra “happy path” mà còn kiểm tra điều kiện biên, chu kỳ reset, overflow và tính đúng đắn sau nhiều chu kỳ ngẫu nhiên.

Assertion: giá trị và điều kiện thời gian
-- Dùng trong testbench, ví dụ ngay sau cạnh clock:
assert q = expected
    report "Unexpected q value" severity error;

-- Nếu reset đồng bộ đã được lấy mẫu ở cạnh clock:
assert q = (q'range => '0')
    report "Counter did not reset" severity failure;
