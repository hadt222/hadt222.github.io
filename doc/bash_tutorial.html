01Nền tảng

Bash là gì? Bắt đầu từ đâu

Hiểu Bash, Terminal và cách chạy lệnh trước khi bắt đầu.

Bash (Bourne Again SHell) là một shell: chương trình nhận lệnh bạn gõ, diễn giải chúng và khởi chạy chương trình tương ứng. Terminal là giao diện hiển thị để bạn tương tác với shell; script Bash là tập hợp lệnh lưu trong tệp để chạy tự động.

Thuật ngữ Hiểu ngắn gọn
Terminal Cửa sổ nhập và xem kết quả lệnh
Shell Trình thông dịch lệnh, ví dụ Bash hoặc Zsh
Bash Một shell phổ biến và ngôn ngữ scripting
Prompt Dấu nhắc như $, user@host:~$
Working directory Thư mục hiện tại của tiến trình shell

Mở Bash: Linux thường có sẵn Bash; macOS có thể mở Terminal rồi chạy bash (shell mặc định trên nhiều máy Mac là Zsh). Windows có thể dùng WSL (Windows Subsystem for Linux) và mở bản phân phối Linux. Bài này dùng cú pháp Bash; một số tùy chọn tiện ích có thể khác giữa GNU/Linux và macOS.

BASH
bash --version             # Kiểm tra phiên bản Bash
printf '%s\n' "$SHELL"    # Shell đăng nhập mặc định (không chắc là shell hiện hành)
printf '%s\n' "$BASH_VERSION"  # Phiên bản nếu đang ở Bash
pwd                        # In thư mục hiện tại
whoami                     # Tài khoản đang thực thi

Quy ước: $ trong ví dụ mô tả prompt, không gõ ký tự $ nếu nó đứng ở đầu dòng minh họa lệnh. Các khối mã trên trang chỉ chứa phần lệnh để sao chép thẳng. Dấu # mở đầu chú thích (trừ một số ngữ cảnh đặc biệt).

Mẹo học nhanh: tạo một thư mục thử nghiệm, chỉ thao tác bên trong nó và kiểm tra kết quả sau từng lệnh. Lệnh trong Terminal thường tác động ngay lên tệp thật, không có nút hoàn tác chung.

02Cơ bản

Cấu trúc lệnh & cách tra cứu

Nắm được tên lệnh, cờ tùy chọn, đối số, mã thoát và trợ giúp.

Một lệnh thường có dạng lenh [tuy_chon] [doi_so]. Ví dụ: ls -lah /tmp gồm ls (tên lệnh), -l -a -h (tùy chọn gộp) và /tmp (đường dẫn).

BASH
ls -lah .                  # Liệt kê chi tiết thư mục hiện tại
command -v git            # Tìm vị trí lệnh git trong PATH
type cd                   # cd là builtin, alias hay tệp thực thi?
help cd                   # Trợ giúp về builtin của Bash
man ls                    # Hướng dẫn đầy đủ (nhấn q để thoát)
ls --help                  # Phổ biến ở GNU/Linux; không phải lệnh nào cũng có

Bash kết thúc mỗi lệnh bằng mã trạng thái: 0 thường có nghĩa thành công, khác 0 là lỗi hoặc một điều kiện không thỏa. $? chứa trạng thái của lệnh ngay trước đó.

BASH
ls /duong-dan-khong-ton-tai
printf 'Ma thoat: %s\n' "$?"  # Thường khác 0
true
printf '%s\n' "$?"            # 0
  • ; chạy nhiều lệnh nối tiếp bất kể thành công hay thất bại.
  • && chỉ chạy vế sau nếu vế trước thành công.
  • || chỉ chạy vế sau nếu vế trước thất bại.
  • \ ở cuối dòng cho phép tiếp tục lệnh sang dòng kế tiếp.
BASH
mkdir -p demo && cd demo
command -v python3 >/dev/null 2>&1 || echo 'Chua cai Python 3'
printf '%s\n' 'mot'; printf '%s\n' 'hai'

Các ký hiệu như [...], ... trong phần mô tả cú pháp là ký hiệu tài liệu, không phải phần phải gõ nguyên xi.

03Thao tác tệp

Điều hướng hệ thống tệp

Di chuyển giữa các thư mục và hiểu đường dẫn tuyệt đối, tương đối.

Trên Unix, đường dẫn tuyệt đối bắt đầu bằng /. Đường dẫn tương đối bắt đầu từ thư mục hiện tại. . là thư mục hiện tại, .. là thư mục cha, ~ được Bash mở rộng thành thư mục nhà của người dùng.

BASH
pwd                         # Đang ở đâu?
ls                          # Danh sách tệp/thư mục
ls -la                      # Bao gồm tệp ẩn, chi tiết
ls -lh /var/log             # Kích thước dễ đọc (nếu có quyền truy cập)
cd /tmp                     # Đi tới đường dẫn tuyệt đối
cd ..                       # Lên một cấp
cd ~                        # Về thư mục home
cd -                        # Quay lại thư mục trước
Ký hiệu Ý nghĩa Ví dụ
/ Gốc hệ thống tệp /etc/hosts
. Thư mục hiện tại ./script.sh
.. Thư mục cha ../data
~ Home của người dùng ~/Downloads
- (với cd) Thư mục trước đó cd -

Lưu ý: đường dẫn chứa dấu cách cần được đặt trong dấu nháy: cd "$HOME/Du lieu". Không thể dùng cd để di chuyển tiến trình shell cha từ một script con.

04Thao tác tệp

Tạo, sao chép, di chuyển & xóa

Nhóm lệnh hằng ngày để quản lý cấu trúc tệp và thư mục.

Trước tiên hãy tạo không gian thực hành:

BASH
mkdir -p "$HOME/bash-lab/tai-lieu"
cd "$HOME/bash-lab"
touch ghi-chu.txt
printf 'Xin chao Bash\n' > ghi-chu.txt
cp ghi-chu.txt tai-lieu/ban-sao.txt
mv ghi-chu.txt ghi-chu-cu.txt
ls -R .
Lệnh Chức năng Ví dụ phổ biến
touch Tạo tệp rỗng/cập nhật mốc thời gian touch todo.txt
mkdir -p Tạo thư mục, kể cả thư mục cha mkdir -p a/b/c
cp Sao chép tệp cp a.txt b.txt
cp -R Sao chép thư mục đệ quy cp -R thu-muc ban-sao
mv Đổi tên hoặc di chuyển mv old.txt new.txt
rm Xóa tệp rm tep-tam.txt
rm -r Xóa thư mục và nội dung rm -r thu-muc-tam
rmdir Xóa thư mục rỗng rmdir rong
file Nhận diện loại tệp file hinh.png
stat Siêu dữ liệu của tệp stat ghi-chu-cu.txt

Cảnh báo: rm thường xóa trực tiếp, không đưa vào thùng rác. Trước lệnh xóa đệ quy, hãy kiểm tra đường dẫn bằng pwd và ls, sử dụng biến có dấu nháy, tránh rm -rf trên đường dẫn không chắc chắn. rm -i yêu cầu xác nhận từng tệp.

BASH
cp -i nguon.txt dich.txt    # Hỏi trước khi ghi đè (nếu tệp nguồn tồn tại)
mv -i old.txt new.txt      # Hỏi trước khi ghi đè
rm -i tep-khong-can.txt    # Hỏi trước khi xóa

Ghi đè: > sẽ thay nội dung file; >> nối thêm. Để thử nghiệm hãy dùng các tệp trong ~/bash-lab thay vì thư mục hệ thống.

05Thao tác tệp

Đọc tệp & kiểm tra dữ liệu

Xem nhanh nội dung, dòng đầu/cuối, kích thước và dung lượng.

BASH
cat /etc/hosts            # In toàn bộ nội dung tệp ngắn
less /etc/hosts           # Xem tệp dài; q để thoát, / để tìm
head -n 5 /etc/hosts      # 5 dòng đầu
tail -n 5 /etc/hosts      # 5 dòng cuối
wc -l /etc/hosts          # Đếm dòng
wc -w /etc/hosts          # Đếm từ
wc -c /etc/hosts          # Đếm byte
du -sh "$HOME/bash-lab"   # Dung lượng thư mục
df -h                     # Dung lượng hệ thống tệp đã gắn

Theo dõi một tệp nhật ký đang được ghi thêm (nhấn Ctrl+C để dừng):

BASH
tail -f /duong-dan/ung-dung.log

cat phù hợp tệp ngắn; less phù hợp tệp dài. head/tail hữu ích trong pipeline vì chúng giới hạn lượng dữ liệu hiển thị. du đo phần dung lượng mà thư mục chiếm trên đĩa; df báo mức sử dụng của hệ thống tệp.

06Cốt lõi

Đầu vào, đầu ra & pipeline

Tận dụng các chương trình nhỏ bằng cách ghép chúng với nhau.

Mỗi chương trình thường có ba luồng chuẩn: stdin (0) để nhận đầu vào, stdout (1) để in kết quả và stderr (2) để in lỗi.

Cú pháp Tác dụng
> Ghi stdout vào tệp, ghi đè
>> Nối stdout vào cuối tệp
< Đọc stdin từ tệp
2> Ghi stderr vào tệp
2>&1 Chuyển stderr tới đích hiện tại của stdout
| Dẫn stdout lệnh trái thành stdin lệnh phải
tee Ghi vừa ra màn hình vừa vào tệp
BASH
printf 'an\nbo\nan\n' > trai-cay.txt
cat trai-cay.txt | sort | uniq -c
sort trai-cay.txt | uniq -c > thong-ke.txt
printf 'them mot dong\n' >> trai-cay.txt
ls /khong-co 2> loi.txt
printf 'noi dung\n' | tee ban-ghi.txt

Pipeline (|) đưa stdout của lệnh bên trái sang stdin của lệnh bên phải. Theo mặc định, trạng thái của pipeline thường là trạng thái lệnh cuối; bật set -o pipefail để phát hiện thất bại của các lệnh trước trong pipeline.

BASH
# Gộp stdout và stderr vào cùng một tệp
lenh_bat_ky > ket-qua.log 2>&1

# Here-document: nhập nhiều dòng; nháy 'EOF' ngăn mở rộng biến
cat <<'EOF' > chao.txt
Xin chào!
$HOME sẽ được giữ nguyên dưới dạng văn bản.
EOF

Thứ tự quan trọng: lenh > all.log 2>&1 khác lenh 2>&1 > all.log vì phép chuyển hướng được thực hiện từ trái sang phải.

07Cốt lõi

Tìm tệp & lọc dòng

Kết hợp find, grep, sort, uniq, cut để tìm đúng thông tin.

BASH
find . -type f -name '*.txt'           # Tìm tệp .txt bên dưới thư mục hiện tại
find . -type d -name 'src'             # Tìm thư mục tên src
find . -type f -mtime -7              # Tệp sửa trong chưa tới 7 ngày
find . -type f -size +10M             # Tệp lớn hơn 10 MiB (tùy triển khai)
grep -n 'ERROR' app.log               # Số dòng kèm dòng chứa ERROR
grep -i 'warning' app.log             # Không phân biệt hoa/thường
grep -Rni 'TODO' ./src                 # Tìm đệ quy, kèm số dòng

Các công cụ xử lý text thường gặp:

Lệnh Tác dụng Ví dụ
grep Lọc dòng khớp mẫu grep -E '404|500' access.log
sort Sắp xếp dòng sort ten.txt
uniq -c Đếm chuỗi dòng liền kề trùng nhau sort ten.txt | uniq -c
cut -d: -f1 Lấy cột 1 phân tách bằng : cut -d: -f1 /etc/passwd
tr Thay/loại ký tự tr '[:lower:]' '[:upper:]'
wc -l Đếm số dòng wc -l ket-qua.txt
sort -n Sắp xếp theo số sort -n diem.txt
sort -u Sắp xếp và khử dòng trùng sort -u ds.txt

Ví dụ đếm số lần xuất hiện của từng tên:

BASH
printf 'Lan\nMinh\nLan\nHoa\nMinh\nLan\n' |
  sort | uniq -c | sort -nr

Lưu ý: grep trả mã 1 khi không tìm thấy khớp (không nhất thiết là lỗi hệ thống). Với tên tệp có ký tự lạ, sử dụng dạng xử lý dấu NUL (-print0/-0) thay cho tách chuỗi theo dấu cách.

08Cốt lõi

Wildcard & mở rộng biểu thức

Hiểu glob, brace expansion và command substitution.

Globbing để Bash mở rộng mẫu thành tên tệp; regular expression (regex) được các công cụ như grep sử dụng để so khớp nội dung. Hai khái niệm này khác nhau.

Cú pháp Ý nghĩa Ví dụ
* Bất kỳ chuỗi ký tự nào trong một thành phần đường dẫn *.log
? Một ký tự bất kỳ anh?.png
[abc] Một trong các ký tự chỉ định file[123].txt
{a,b} Tạo nhiều chuỗi bằng brace expansion mkdir -p {src,tests,docs}
{1..5} Sinh dãy echo {1..5}
$(...) Lấy stdout từ một lệnh today=$(date +%F)
$((...)) Tính toán số nguyên echo $((2 + 3))
BASH
mkdir -p lab/{input,output,logs}
printf '%s\n' *.txt         # Tên file .txt hiện có
hom_nay=$(date +%F)
printf 'Hom nay: %s\n' "$hom_nay"
printf '%s\n' {A,B}{1,2}  # A1 A2 B1 B2

Vấn đề thường gặp: *.txt mặc định không khớp tệp ẩn bắt đầu bằng .; nếu không có tệp phù hợp thì mẫu có thể được giữ nguyên. Không đặt nháy quanh mẫu glob khi muốn Bash mở rộng (ls *.txt), nhưng hãy đặt nháy cho mẫu truyền vào find -name '*.txt' để chính find xử lý.

09Viết script

Biến, dấu nháy & môi trường

Quy tắc quan trọng nhất để viết Bash ít lỗi và an toàn.

Gán biến trong Bash không có khoảng trắng quanh =. Dùng "$bien" khi truyền giá trị như một đối số để tránh tách từ và mở rộng wildcard ngoài ý muốn.

BASH
ten='Nguyen Van A'          # Gán biến
printf 'Xin chao %s\n' "$ten"
thu_muc="$HOME/Ho so"      # Có dấu cách vẫn giữ nguyên một chuỗi
mkdir -p "$thu_muc"
export APP_MODE=dev         # Cho tiến trình con thấy APP_MODE
printenv HOME               # Xem biến môi trường
unset APP_MODE              # Bỏ biến
Cách viết Bash xử lý thế nào?
'text $HOME' Giữ nguyên tất cả ký tự gần như nguyên văn
"text $HOME" Mở rộng biến nhưng không tách từ thông thường
text\ file Dấu \ bảo vệ dấu cách ngay sau
${ten} Phân tách rõ tên biến với văn bản bên cạnh
${ten:-mac_dinh} Lấy giá trị mặc định khi biến rỗng/chưa đặt
${ten:?thong_bao} Báo lỗi nếu biến rỗng/chưa đặt
BASH
file='bao cao 2026.txt'
printf '%s\n' "$file"
printf 'Duong dan: %s\n' "${HOME}/${file}"
: "${TOKEN:?Can dat bien TOKEN truoc khi chay}"

Lệnh cuối dùng : (lệnh không làm gì) để kiểm tra TOKEN; nếu thiếu, Bash dừng với thông báo. Chỉ chạy lệnh này khi bạn thực sự đang thử cơ chế kiểm tra biến.

Quy tắc vàng: gần như luôn dùng "$var", "${array[@]}", "$(command)" khi truyền dữ liệu tệp/đường dẫn. "$@" giữ nguyên ranh giới từng đối số. Không đặt dấu nháy kiểu ngẫu nhiên chỉ để xử lý lỗi; hiểu nơi cần Bash mở rộng glob hoặc pattern.

10Viết script

Nhập liệu, tham số & mã thoát

Biến một đoạn lệnh thành chương trình nhận dữ liệu từ người dùng.

Khi chạy ./hello.sh An 25, Bash cung cấp các tham số vị trí. $0 là tên/cách gọi script, $1 và $2 là hai đối số đầu, $# là số đối số, "$@" là toàn bộ đối số (giữ ranh giới giữa chúng).

BASH
#!/usr/bin/env bash
set -u
printf 'Script: %s\n' "$0"
printf 'So doi so: %s\n' "$#"
for arg in "$@"; do
  printf '  - %s\n' "$arg"
done

Đọc dữ liệu từ bàn phím:

BASH
read -r -p 'Nhap ten cua ban: ' ten
printf 'Chao, %s!\n' "$ten"

read -r không coi dấu \ là ký tự escape. Dùng exit 0 để báo thành công và exit 1 hoặc một mã khác 0 cho trường hợp thất bại. In thông báo lỗi ra stderr bằng >&2.

BASH
if (( $# < 1 )); then
  printf 'Cach dung: %s TEN\n' "$0" >&2
  exit 2
fi

Ví dụ: lưu mã ở trên trong một script thật để $1 và $# có ý nghĩa. Trong Terminal tương tác, tham số vị trí hoạt động khác tùy ngữ cảnh.

11Viết script

If, case & điều kiện

Ra quyết định dựa trên tệp, chuỗi, số và kết quả lệnh.

Bash hỗ trợ if ...; then ...; fi, elif, else. [[ ... ]] là cú pháp điều kiện của Bash; nên dùng cho string/path test trong script Bash. (( ... )) dùng để tính và so sánh số nguyên.

BASH
file='du-lieu.txt'
if [[ -f "$file" ]]; then
  printf 'Ton tai tep: %s\n' "$file"
elif [[ -d "$file" ]]; then
  printf 'Day la thu muc\n'
else
  printf 'Chua tim thay\n'
fi

age=20
if (( age >= 18 )); then
  echo 'Du tuoi'
fi
Test Ý nghĩa
-f path Là tệp thông thường
-d path Là thư mục
-e path Tồn tại
-r, -w, -x Có quyền đọc/ghi/thực thi
-z "$s" / -n "$s" Chuỗi rỗng / không rỗng
"$a" == "$b" Hai chuỗi bằng nhau
"$a" != "$b" Hai chuỗi khác nhau
(( a > b )) So sánh số nguyên
&& / || AND / OR trong [[ ... ]]

case hợp lý khi có nhiều nhánh cùng kiểm tra một giá trị:

BASH
read -r -p 'Chon start|stop|status: ' action
case "$action" in
  start)  echo 'Bat dau' ;;
  stop)   echo 'Dung' ;;
  status) echo 'Dang kiem tra' ;;
  *)      echo 'Lua chon khong hop le' >&2; exit 2 ;;
esac

Lưu ý: [[ "$x" == *.txt ]] so khớp pattern ở vế phải (không đặt *.txt trong nháy nếu bạn muốn dùng pattern). [ là một lệnh/test riêng và có quy tắc khác; mọi dấu cách trong [ "$x" = y ] đều quan trọng.

12Viết script

Vòng lặp & hàm

Lặp qua tệp, chuỗi dữ liệu và tái sử dụng đoạn mã.

BASH
for color in red blue yellow; do
  printf 'Mau: %s\n' "$color"
done

for f in ./*.txt; do
  [[ -e "$f" ]] || continue   # Bỏ qua nếu glob không khớp
  printf 'Tep: %s\n' "$f"
done

i=1
while (( i <= 3 )); do
  printf 'Lan %d\n' "$i"
  ((i += 1))
done

Với file có khoảng trắng, không viết for f in $(find ...): command substitution chia đầu ra thành các từ. Dùng vòng lặp nhận đường dẫn kết thúc bằng byte NUL:

BASH
while IFS= read -r -d '' f; do
  printf 'File: %s\n' "$f"
done < <(find . -type f -name '*.txt' -print0)

Tạo hàm với biến cục bộ và trả kết quả qua stdout:

BASH
chao() {
  local ten="${1:-ban}"
  printf 'Xin chao, %s!\n' "$ten"
}

chao 'Minh'
ket_qua=$(chao 'Lan')
printf '%s\n' "$ket_qua"

return trong hàm dùng cho mã trạng thái (0–255), không phải để trả chuỗi. Nếu cần giá trị dạng chuỗi, hãy dùng stdout và $(...) hoặc biến kết quả có chủ đích.

13Viết script

Mảng, số học & xử lý chuỗi

Làm việc với nhiều giá trị mà không làm mất dấu cách.

Bash có mảng chỉ số (indexed array) và các phép mở rộng tham số rất tiện. Bash 3.2 vẫn có mảng chỉ số; mảng kết hợp (declare -A) cần Bash 4+.

BASH
files=('bao cao.txt' 'anh.png' 'tai lieu.pdf')
printf 'Phan tu dau: %s\n' "${files[0]}"
printf 'So phan tu: %s\n' "${#files[@]}"
for f in "${files[@]}"; do
  printf '%s\n' "-> $f"
done

count=3
((count += 2))
printf 'Tong: %d\n' "$((count * 4))"

Một số phép xử lý chuỗi không cần sed/cut:

BASH
path='/home/user/report.csv'
name="${path##*/}"          # report.csv (bỏ prefix dài nhất tới /)
ext="${name##*.}"          # csv
stem="${name%.*}"          # report
printf '%s | %s | %s\n' "$name" "$ext" "$stem"

msg='Hello Bash'
printf '%s\n' "${#msg}"       # Độ dài chuỗi (theo ký tự/locale)
printf '%s\n' "${msg:0:5}"  # Hello

Bash chỉ tính số nguyên với $(( ... )). Muốn số thực, hãy dùng công cụ phù hợp như awk, python3 hoặc bc nếu cài đặt. Đừng dùng ((i++)) như một lệnh đơn lẻ dưới set -e khi i có thể bằng 0, vì biểu thức cho trạng thái thất bại khi giá trị tính ra là 0.

14Hệ thống

Tiến trình, job & tài nguyên

Xem chương trình đang chạy và quản lý tác vụ nền.

BASH
ps aux                    # Danh sách tiến trình dạng phổ biến
top                       # Quan sát CPU/RAM theo thời gian
pgrep -fl bash            # Tìm PID tiến trình phù hợp (tùy hệ điều hành)
sleep 30 &                # Chạy trong nền
jobs                      # Xem job của shell hiện tại
fg %1                     # Đưa job 1 lên foreground
bg %1                     # Tiếp tục job 1 trong nền (nếu đang dừng)
wait                      # Đợi các job nền của shell

Khi lệnh đang chiếm Terminal: Ctrl+C thường gửi SIGINT để ngắt; Ctrl+Z gửi SIGTSTP để tạm dừng. fg tiếp tục ở foreground; bg tiếp tục ở background. & chạy job nền ngay từ đầu.

BASH
kill -TERM 12345          # Yêu cầu PID 12345 kết thúc mềm
kill -KILL 12345          # Cưỡng bức, chỉ khi thật cần thiết

kill gửi tín hiệu; không nhất thiết “xóa” tiến trình lập tức. Tránh gửi tín hiệu tới PID không xác minh. top có thể khác ở macOS/Linux; ở máy chủ có htop thì công cụ này thường dễ đọc hơn nhưng không luôn được cài sẵn.

15Hệ thống

Quyền tệp, người dùng & PATH

Đọc `rwx`, điều chỉnh quyền tối thiểu và hiểu môi trường chạy.

BASH
ls -l hello.sh              # Ví dụ -rwxr-xr-x
chmod u+x hello.sh          # Thêm quyền thực thi cho chủ sở hữu
chmod 644 du-lieu.txt       # Owner rw-, group r--, others r--
chmod 755 script.sh         # Owner rwx, group r-x, others r-x
id                          # UID, GID, nhóm hiện tại
whoami                      # Tên người dùng
printf '%s\n' "$PATH"       # Nơi shell tìm chương trình
command -v bash             # Đường dẫn Bash được tìm thấy

Bộ quyền r = đọc (4), w = ghi (2), x = thực thi (1). 755 tương đương rwxr-xr-x, 644 tương đương rw-r--r--. Với thư mục, x cho phép đi xuyên qua thư mục (khi đã biết tên mục), không chỉ mang nghĩa thực thi chương trình.

sudo thực thi một lệnh với quyền khác (thường là quản trị). Chỉ dùng khi hiểu chính xác ảnh hưởng; không dùng sudo chỉ để “thử cho chạy được”. chown thay chủ sở hữu, thường đòi quyền phù hợp.

BASH
# Ví dụ minh họa cú pháp; không chạy nếu không có nhu cầu thực tế
sudo chown user:group /duong-dan/toi-tep

Để chạy script: bash script.sh không yêu cầu cờ thực thi; ./script.sh yêu cầu quyền thực thi và dòng shebang thích hợp. Nếu lệnh chưa được tìm thấy, kiểm tra PATH và thử command -v ten_lenh.

16Hệ thống

Mạng, tải dữ liệu & nén tệp

Dùng curl, ssh, tar và gzip trong tình huống thực tế.

BASH
curl -I https://example.com           # Xem HTTP response headers
curl -L --fail -o trang.html https://example.com
ssh user@server.example.com           # Kết nối máy chủ được phép truy cập
scp file.txt user@server.example.com:~/

tar -czf tai-lieu.tar.gz tai-lieu/    # Nén thư mục dạng tar.gz
tar -tzf tai-lieu.tar.gz              # Liệt kê trước khi giải nén
tar -xzf tai-lieu.tar.gz              # Giải nén ở thư mục hiện tại
gzip du-lieu.txt                      # Nén thành du-lieu.txt.gz
gunzip du-lieu.txt.gz                 # Giải nén
Lệnh Công dụng
curl Gửi yêu cầu HTTP và tải nội dung
ssh Đăng nhập từ xa qua kênh mã hóa
scp Sao chép tệp qua SSH
tar Đóng gói nhiều tệp/thư mục, có thể nén

An toàn: không chạy mã tải từ Internet bằng curl URL | bash khi chưa đọc, kiểm tra nguồn và hiểu nội dung. Không giải nén các kho lưu trữ không đáng tin vào thư mục chứa dữ liệu quan trọng trước khi kiểm tra danh sách tệp và đường dẫn bên trong.

curl không được cài ở mọi môi trường tối giản; ssh/scp yêu cầu quyền truy cập máy đích. Trên macOS, BSD tar và GNU tar có thể có khác biệt tùy chọn nâng cao.

17Nâng cao

sed, awk, xargs & công thức text

Tăng tốc khi cần đổi chuỗi, tách cột và thao tác trên nhiều tệp.

BASH
printf 'red\nblue\n' | sed 's/red/do/'
printf 'An,8\nBinh,9\n' | awk -F, '{ print $1, $2 }'
printf 'An,8\nBinh,9\n' | awk -F, '{ sum += $2 } END { print sum }'
printf ' a b c \n' | tr ' ' '_'

sed là stream editor; s/cu/moi/ thay lần khớp đầu tiên mỗi dòng, thêm g để thay tất cả. awk -F, dùng , làm dấu phân tách cột; $1, $2 là cột, $0 là toàn bộ dòng, NR là số dòng đã đọc.

BASH
# Bỏ dòng trống rồi lấy các giá trị duy nhất
sed '/^[[:space:]]*$/d' input.txt | sort -u

# Gọi một lệnh cho từng tệp chứa tên bất kỳ (kể cả dấu cách)
find . -type f -name '*.log' -print0 | xargs -0 -r grep -n 'ERROR'

Tính tương thích: tùy chọn xargs -r thông dụng trên GNU/Linux nhưng không có trên mọi phiên bản BSD/macOS. Bản tương thích hơn: dùng find ... -exec grep -n 'ERROR' {} + hoặc while IFS= read -r -d '' .... sed -i cũng khác nhau giữa GNU sed và BSD sed; khi sửa file quan trọng, nên tạo bản sao và kiểm tra kỹ lệnh.

BASH
# Thay thế an toàn hơn cho ví dụ ở trên, hoạt động phổ biến
find . -type f -name '*.log' -exec grep -n 'ERROR' {} +

Với dữ liệu CSV có dấu phẩy trong trường được đặt nháy, cut -d, và awk -F, không phải bộ phân tích CSV đầy đủ. Dùng Python hoặc công cụ CSV chuyên dụng.

18Thực hành

Viết script Bash hoàn chỉnh

Tạo một script sao lưu thư mục có kiểm tra lỗi và đối số.

Mục tiêu: nhận thư mục nguồn và (tùy chọn) thư mục đích, tạo tệp tar.gz gắn thời gian, rồi thông báo vị trí tệp. Chỉ chạy với dữ liệu thử nghiệm của bạn.

Tạo backup.sh bằng trình soạn thảo yêu thích và dán đoạn sau:

BASH
#!/usr/bin/env bash
set -euo pipefail

usage() {
  printf 'Cach dung: %s THU_MUC_NGUON [THU_MUC_DICH]\n' "$0" >&2
  exit 2
}

(( $# >= 1 && $# <= 2 )) || usage
source_dir=$1
backup_dir=${2:-./backups}

[[ -d "$source_dir" ]] || usage
mkdir -p -- "$backup_dir"

source_abs=$(cd -- "$source_dir" && pwd -P)
source_name=${source_abs##*/}
source_parent=${source_abs%/*}
[[ -n "$source_parent" ]] || source_parent=/

archive="$backup_dir/backup-$(date +%Y%m%d-%H%M%S).tar.gz"
tar -czf "$archive" -C "$source_parent" -- "$source_name"
printf 'Da sao luu: %s\n' "$archive"

Giải thích phần chính:

  1. #!/usr/bin/env bash yêu cầu dùng Bash trong môi trường hiện tại.
  2. set -euo pipefail: dừng ở nhiều lỗi lệnh, báo biến chưa khai báo và kiểm tra lỗi trong pipeline (không thay thế việc tự xử lý lỗi).
  3. [[ -d "$source_dir" ]]: xác nhận thư mục nguồn tồn tại.
  4. mkdir -p: tạo thư mục chứa bản sao lưu nếu thiếu.
  5. tar -czf: tạo kho tar.gz từ thư mục nguồn mà không phải cd rời khỏi vị trí hiện tại.
BASH
mkdir -p "$HOME/bash-lab/du-lieu"
printf 'Chao Bash\n' > "$HOME/bash-lab/du-lieu/chao.txt"
chmod u+x backup.sh
./backup.sh "$HOME/bash-lab/du-lieu" "$HOME/bash-lab/backups"
ls -lh "$HOME/bash-lab/backups"

Thực tế vận hành: chọn thư mục đích nằm ngoài thư mục nguồn để tránh đóng gói bản sao lưu vào chính nó; đảm bảo đủ dung lượng; kiểm tra nội dung với tar -tzf. Trên tệp có dữ liệu nhạy cảm, cần thêm chính sách kiểm soát quyền và mã hóa phù hợp. Ví dụ giả định đường dẫn nguồn không phải / và tên thư mục nguồn không rỗng.

19Thực hành

Gỡ lỗi & nguyên tắc an toàn

Kiểm tra script trước khi chạy và tránh các lỗi Bash kinh điển.

BASH
bash -n script.sh           # Kiểm tra cú pháp, không chạy script
bash -x script.sh           # Trace các lệnh được thực thi
set -x                     # Bật trace bên trong script
set +x                     # Tắt trace
printf 'Gia tri=%q\n' "$var" # In chuỗi dạng dễ kiểm tra escape (Bash)

Bảng lỗi thường gặp

Triệu chứng Nguyên nhân hay gặp Cách sửa
command not found Sai tên hoặc PATH không chứa lệnh command -v, kiểm tra cài đặt
Permission denied Thiếu quyền hoặc mount hạn chế ls -l, dùng bash script.sh khi phù hợp
No such file or directory Đường dẫn sai/thư mục hiện tại khác pwd, ls, nháy đường dẫn
unexpected EOF Thiếu fi, done, ) hoặc dấu nháy bash -n, kiểm tra cặp cú pháp
Tên tệp có dấu cách bị tách Dùng $var không có dấu nháy Dùng "$var"
Vòng lặp đọc file bị lỗi Tách dòng/đường dẫn theo dấu cách read -r, -print0 + NUL
Script chạy bằng sh bị lỗi Script dùng cú pháp chỉ có ở Bash bash script.sh hoặc shebang đúng

Những nguyên tắc nên áp dụng:

  • Kiểm tra đường dẫn và dữ liệu đầu vào trước khi ghi đè/xóa; thử với tập dữ liệu nhỏ.
  • Không dùng eval trên chuỗi có nguồn không đáng tin; ưu tiên mảng để xây lệnh.
  • Tránh log mật khẩu, token hoặc khóa riêng; set -x có thể làm lộ dữ liệu nhạy cảm.
  • Dùng trap để dọn tài nguyên tạm khi script thoát, khi phù hợp.
  • set -e có nhiều ngoại lệ (đặc biệt trong if, &&, ||, command substitution); đọc/kiểm tra mã trạng thái rõ ràng tại các bước quan trọng.
BASH
#!/usr/bin/env bash
set -euo pipefail
workdir=$(mktemp -d)
trap 'rm -rf -- "$workdir"' EXIT  # Chỉ dọn thư mục tạm do chính script tạo
printf 'Thu muc tam: %s\n' "$workdir"

Không chạy snippet trap sau khi chỉnh biến workdir thành đường dẫn tùy ý; cách này chỉ an toàn khi biến luôn do mktemp -d tạo thành công. Với dự án thật, có thể kiểm tra bằng ShellCheck nếu công cụ đã được cài.
