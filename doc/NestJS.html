NestJS là gì?

Làm quen NestJS và lý do nên dùng framework này cho ứng dụng backend có cấu trúc.

NestJS là framework backend cho Node.js, ưu tiên TypeScript, tổ chức ứng dụng theo module và dùng dependency injection (DI). Nest thường chạy trên Express, và có thể chuyển sang Fastify thông qua adapter.

◇Kiến trúc rõ ràngController nhận HTTP; Service xử lý nghiệp vụ; Module nhóm thành phần.
⚡Hỗ trợ sẵnValidation, guard, middleware, test, WebSocket, microservices.
⌘Dễ mở rộngDI giúp thay provider, mock khi test và tách chức năng.

Trước khi học, bạn nên biết

JavaScript cơ bản (async/await, object, array), TypeScript cơ bản (class, interface, kiểu dữ liệu), HTTP/REST (GET, POST, status code) và thao tác terminal.

Điểm mới cần nhớ ở NestJS 12

  • ESM là lựa chọn mặc định cho dự án mới; Vitest là test runner mặc định với ESM. Bạn vẫn có thể chọn CommonJS/Jest.
  • Để dùng lệnh tạo dự án/tạo code của Nest CLI 12, nên dùng Node.js v24.15+ (hoặc v22.22.3+, v26+); nên chọn bản LTS đang được hỗ trợ.
  • Ví dụ TypeScript ESM trong tài liệu này dùng hậu tố .js cho đường dẫn import tương đối, dù file nguồn là .ts.
✓
Mục tiêu cuối tutorial
Bạn sẽ tự xây một REST API quản lý công việc với 5 endpoint, kiểm tra dữ liệu đầu vào, mã lỗi chuẩn, unit test và hướng mở rộng dùng PostgreSQL.

Kiến thức nền

Module · Controller · Provider · DI

Đây là bốn khái niệm quan trọng nhất. Hiểu chúng sẽ giúp bạn đọc phần còn lại rất nhanh.

Client / Browser→Controller→Service→Data
HTTP request RouteBusiness logicDB / cache
MODULE đăng ký Controller + Provider và quản lý dependency injection

1. Controller

Nhận request, đọc params/query/body, gọi service rồi trả kết quả. Một controller thường gắn với một nhóm endpoint: /tasks, /users...

2. Provider / Service

Một class có @Injectable() và được khai báo trong providers. Service nên giữ nghiệp vụ, không nên dồn hết logic vào controller.

3. Module

Một class có @Module() gom imports, controllers, providers, exports. Mỗi tính năng nên có module riêng.

4. Dependency Injection (DI)

Thay vì tự tạo new TasksService(), controller khai báo dependency trong constructor. Nest tạo và cung cấp instance phù hợp, từ đó việc thay mock service khi test trở nên đơn giản.

Ví dụ cấu trúc module
typescript
@Module({
  imports: [],              // Các module cần dùng
  controllers: [TasksController],
  providers: [TasksService],
  exports: [TasksService],   // Chỉ export khi module khác cần
})
export class TasksModule {}
✓
Nguyên tắc thiết kế
Một route nên mỏng: Controller → Service → Repository. Controller biết HTTP; service hiểu nghiệp vụ; repository hiểu nơi lưu trữ.

Từ chối dữ liệu sai trước khi đi vào service: tiêu đề quá ngắn, sai kiểu hay trường lạ.

export class CreateTaskDto {

  @MinLength(3)
  @MaxLength(100)
  title!: string;

  @IsOptional()
  @IsString()
  @MaxLength(500)
  description?: string;

  IsBoolean, IsOptional, IsString, MaxLength, MinLength,
} from 'class-validator';

export class UpdateTaskDto {

  @MaxLength(100)

Logic nghiệp vụ

Viết TasksService hoàn chỉnh

Service lưu trong bộ nhớ và triển khai toàn bộ find, create, update, delete.

Sao chép toàn bộ code sau vào src/tasks/tasks.service.ts. Đây là code có thể chạy được của mini project.

src/tasks/tasks.service.ts
typescript
import { Injectable, NotFoundException } from '@nestjs/common';
import type { Task } from './task.model.js';
import { CreateTaskDto } from './dto/create-task.dto.js';
import { UpdateTaskDto } from './dto/update-task.dto.js';

@Injectable()
export class TasksService {
  private tasks: Task[] = [];
  private nextId = 1;

  findAll(): Task[] {
    return this.tasks;
  }

  findOne(id: number): Task {
    const task = this.tasks.find((item) => item.id === id);
    if (!task) {
      throw new NotFoundException(`Không tìm thấy task ${id}`);
    }
    return task;
  }

  create(input: CreateTaskDto): Task {
    const task: Task = {
      id: this.nextId++,
      title: input.title,
      description: input.description ?? '',
      completed: false,
      createdAt: new Date().toISOString(),
    };
    this.tasks.push(task);
    return task;
  }

  update(id: number, input: UpdateTaskDto): Task {
    const task = this.findOne(id);
    Object.assign(task, input);
    return task;
  }

  remove(id: number): void {
    this.findOne(id); // Ném 404 khi ID không tồn tại
    this.tasks = this.tasks.filter((task) => task.id !== id);
  }
}

Đọc logic theo thứ tự

  1. @Injectable() báo cho Nest rằng class có thể được quản lý và inject.
  2. findOne ném NotFoundException, Nest tự đổi thành HTTP 404.
  3. create sinh ID và ngày tạo; không tin client gửi id hay completed.
  4. update chỉ nhận dữ liệu đã qua validation; Object.assign sửa object hiện tại.
  5. remove kiểm tra tồn tại trước khi xóa.
✦
Khi kết nối DB
Các phương thức thường chuyển thành async và trả Promise. Controller của Nest xử lý được cả giá trị đồng bộ lẫn Promise.

Viết TasksController

Ánh xạ HTTP method và URL tới phương thức trong service.

src/tasks/tasks.controller.ts
typescript
import {
  Body, Controller, Delete, Get, HttpCode, HttpStatus,
  Param, ParseIntPipe, Patch, Post,
} from '@nestjs/common';
import { TasksService } from './tasks.service.js';
import { CreateTaskDto } from './dto/create-task.dto.js';
import { UpdateTaskDto } from './dto/update-task.dto.js';

@Controller('tasks')
export class TasksController {
  constructor(private readonly tasksService: TasksService) {}

  @Get()
  findAll() {
    return this.tasksService.findAll();
  }

  @Get(':id')
  findOne(@Param('id', ParseIntPipe) id: number) {
    return this.tasksService.findOne(id);
  }

  @Post()
  create(@Body() body: CreateTaskDto) {
    return this.tasksService.create(body);
  }

  @Patch(':id')
  update(
    @Param('id', ParseIntPipe) id: number,
    @Body() body: UpdateTaskDto,
  ) {
    return this.tasksService.update(id, body);
  }

  @Delete(':id')
  @HttpCode(HttpStatus.NO_CONTENT)
  remove(@Param('id', ParseIntPipe) id: number) {
    this.tasksService.remove(id);
  }
}

HTTP endpoint được tạo

GET/api/tasks/:idChi tiết task
POST/api/tasksTạo task • 201
PATCH/api/tasks/:idCập nhật task
DELETE/api/tasks/:idXóa task • 204

URL /api/tasks/15 cung cấp chuỗi "15". ParseIntPipe chuyển nó thành số; /api/tasks/abc trả 400 trước khi gọi service.

import { ValidationPipe } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module.js';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.setGlobalPrefix('api');
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,

Guard · Interceptor · Exception Filter

Tách các xử lý dùng chung khỏi service và controller để code dễ bảo trì.

Guard: bảo vệ endpoint

Guard triển khai interface CanActivate, trả về true/false hoặc Promise/Observable. Đoạn này minh họa cấu trúc; không nên coi nó là cơ chế authentication hoàn chỉnh.

Ví dụ guard • chỉ minh họa cơ chế
typescript
import { Injectable } from '@nestjs/common';
import type { CanActivate, ExecutionContext } from '@nestjs/common';

@Injectable()
export class DemoGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const request = context.switchToHttp().getRequest();
    return request.headers['x-demo-access'] === 'allowed';
  }
}

// Gắn @UseGuards(DemoGuard) trên controller/method
// Đừng dùng header cố định này để bảo vệ dữ liệu thật.

Interceptor: đo thời gian thực thi

src/common/interceptors/logging.interceptor.ts
typescript
import { Injectable } from '@nestjs/common';
import type { CallHandler, ExecutionContext, NestInterceptor } from '@nestjs/common';
import type { Observable } from 'rxjs';
import { tap } from 'rxjs/operators';

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  intercept(context: ExecutionContext, next: CallHandler): Observable<unknown> {
    const started = Date.now();
    const route = context.getHandler().name;
    return next.handle().pipe(
      tap(() => console.log(`${route}: ${Date.now() - started}ms`)),
    );
  }
}

// Sử dụng: @UseInterceptors(LoggingInterceptor)

Exception filter: thống nhất cách trả lỗi

src/common/filters/http-exception.filter.ts
typescript
import { Catch, HttpException } from '@nestjs/common';
import type { ArgumentsHost, ExceptionFilter } from '@nestjs/common';
import type { Response } from 'express';

@Catch(HttpException)
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: HttpException, host: ArgumentsHost) {
    const response = host.switchToHttp().getResponse<Response>();
    const status = exception.getStatus();
    response.status(status).json({
      statusCode: status,
      error: exception.getResponse(),
      timestamp: new Date().toISOString(),
    });
  }
}

// Đăng ký global: app.useGlobalFilters(new HttpExceptionFilter())

Filter chỉ bắt HttpException, không thay thế mọi cơ chế xử lý lỗi. Trong production, cần log lỗi máy chủ nhưng không trả stack trace, token hoặc thông tin nhạy cảm cho client.

6 · Thay TasksService bằng repository

src/tasks/tasks.service.ts • phiên bản DB
typescript
import { Injectable, NotFoundException } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import type { Repository } from 'typeorm';
import { TaskEntity } from './task.entity.js';
import { CreateTaskDto } from './dto/create-task.dto.js';
import { UpdateTaskDto } from './dto/update-task.dto.js';

@Injectable()
export class TasksService {
  constructor(
    @InjectRepository(TaskEntity)
    private readonly repo: Repository<TaskEntity>,
  ) {}

  findAll(): Promise<TaskEntity[]> {
    return this.repo.find({ order: { id: 'ASC' } });
  }

  async findOne(id: number): Promise<TaskEntity> {
    const task = await this.repo.findOneBy({ id });
    if (!task) throw new NotFoundException(`Không tìm thấy task ${id}`);
    return task;
  }

  async create(input: CreateTaskDto): Promise<TaskEntity> {
    const entity = this.repo.create({
      title: input.title,
      description: input.description ?? '',
      completed: false,
    });
    return this.repo.save(entity);
  }

  async update(id: number, input: UpdateTaskDto): Promise<TaskEntity> {
    const task = await this.findOne(id);
    Object.assign(task, input);
    return this.repo.save(task);
  }

  async remove(id: number): Promise<void> {
    const result = await this.repo.delete(id);
    if (!result.affected) {
      throw new NotFoundException(`Không tìm thấy task ${id}`);
    }
  }
}

Controller vẫn sử dụng lại được vì Nest xử lý Promise tự động. Method DELETE hiện tại gọi service mà không return Promise; khi chuyển sang DB, hãy cập nhật nó để chờ thao tác xóa hoàn tất:

Bảo mật ứng dụng

Authentication và Authorization

Phân biệt xác thực danh tính và kiểm soát quyền truy cập.

Authentication

Bạn là ai?

Đăng nhập, xác minh session hoặc token, gắn user đã xác thực vào ngữ cảnh.
Authorization

Bạn được làm gì?

Phân quyền theo role, ownership, policy hoặc resource.

Một luồng xác thực phổ biến

  1. Client gửi thông tin đăng nhập qua HTTPS.
  2. Server xác thực với dữ liệu đã lưu (password được hash bằng thuật toán chuyên dụng).
  3. Server cấp session an toàn hoặc access token có thời hạn.
  4. Request tiếp theo mang session/token, hệ thống xác thực kiểm tra và guard quyết định được truy cập endpoint hay không.
  5. Đăng xuất, thu hồi hoặc hết hạn session/token theo chính sách ứng dụng.

Trong NestJS 12, tài liệu chính thức có module @nestjs/authentication để xây xác thực dựa trên session và các cơ chế đăng nhập. Nếu dùng JWT, có thể tích hợp @nestjs/jwt và guard phù hợp, nhưng phải xử lý xác thực chữ ký, hạn dùng, audience/issuer, refresh/revoke, an toàn secret và chống tấn công.

Guard phân quyền theo vai trò (mẫu mở rộng)

Mẫu sau giả định đã có lớp authentication tin cậy gắn request.user; chỉ dùng sau khi tích hợp auth thật.

src/auth/roles.guard.ts • minh họa
typescript
import { Injectable, SetMetadata } from '@nestjs/common';
import type { CanActivate, ExecutionContext } from '@nestjs/common';
import { Reflector } from '@nestjs/core';

export const Roles = (...roles: string[]) => SetMetadata('roles', roles);

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const roles = this.reflector.getAllAndOverride<string[]>('roles', [
      context.getHandler(), context.getClass(),
    ]);
    if (!roles?.length) return true;

    // request.user phải được xác thực bằng cơ chế auth trước guard này
    const request = context.switchToHttp().getRequest();
    const user = request.user as { roles?: string[] } | undefined;
    return !!user && roles.some((role) => user.roles?.includes(role));
  }
}

// Ví dụ sử dụng khi đã đăng ký guard và có auth đúng cách:
// @Roles('admin')
// @UseGuards(RolesGuard)

Ôn tập

Lỗi thường gặp · Lộ trình · Tài liệu

Tổng hợp kiến thức và các bước tiếp theo để học NestJS hiệu quả.

6 lỗi phổ biến

01 Nest can't resolve dependencies

Provider chưa có trong providers, chưa được exports từ module nguồn, hoặc module cần thiết chưa được imports vào module đang dùng. Kiểm tra vòng lặp dependency.

02 Request gửi body sai nhưng không bị chặn

Chưa cài class-validator/class-transformer, chưa đăng ký ValidationPipe, dùng interface thay DTO class hoặc thiếu validation decorator.

03 Lỗi import module ESM

Với ESM, đường dẫn import tương đối trong TypeScript cần hậu tố .js như ./tasks.service.js; kiểm tra lại package.json, tsconfig.json và file được tạo bởi CLI.

04 404 khi gọi /tasks

Bài học đặt app.setGlobalPrefix('api'), nên URL đúng là /api/tasks. Đừng nhầm /docs của Swagger với prefix API.

05 Cập nhật/xóa bị lỗi sau khi chuyển sang DB

Service trả Promise; controller cần await hoặc return Promise. Kiểm tra database đã có bảng, DATABASE_URL đúng và entity được đăng ký.

06 Dữ liệu biến mất sau khi restart

Phiên bản đầu lưu danh sách trong RAM. Muốn lưu bền vững, làm phần PostgreSQL và chuyển sang service repository.

Bài kiểm tra nhanh

1. Thành phần nào nên chứa business logic?
Xem đáp án

Service/Provider. Controller chỉ nhận request và điều phối.

2. Vì sao chỉ dùng type TypeScript chưa đủ bảo vệ API?
Xem đáp án

TypeScript không kiểm tra dữ liệu HTTP ở runtime; cần DTO class và ValidationPipe hoặc Standard Schema validation.

3. 404 và 400 khác nhau thế nào?
Xem đáp án

400: request sai/không hợp lệ; 404: tài nguyên không tồn tại.

4. Guard và Interceptor khác nhau thế nào?
Xem đáp án

Guard quyết định có quyền đi tiếp; interceptor bao quanh xử lý route để log, đo thời gian hoặc chuyển đổi response.
