Next.js là gì?

Hiểu Next.js làm thêm những gì so với React thuần và vì sao nó phù hợp với ứng dụng web hiện đại.

React là thư viện để xây dựng giao diện; Next.js là framework dựa trên React, cung cấp thêm định tuyến, render ở máy chủ, xử lý dữ liệu, tối ưu ảnh/font, metadata và cơ chế triển khai. Bạn vẫn viết React component, nhưng có kiến trúc ứng dụng đầy đủ hơn.

Khái niệmÝ nghĩa dễ hiểu
CSR (Client-side Rendering)Trình duyệt chạy JavaScript để tạo/cập nhật phần giao diện tương tác.
Server RenderingMáy chủ có thể tạo HTML ban đầu; không đồng nghĩa toàn bộ UI đều phải có JavaScript ở client.
Prerender / staticNội dung có thể được tạo sẵn khi build hoặc được cache để phục vụ nhanh.
StreamingGửi dần nội dung theo từng phần, có thể hiển thị skeleton trước khi dữ liệu xong.
Full-stackCó trang React và xử lý server/API trong cùng codebase.

Next.js phối hợp giữa server và client; không bắt buộc mọi trang đều có API riêng.

Khi nào nên dùng?

  • Phù hợp: landing page có SEO, blog, dashboard, thương mại điện tử, SaaS, ứng dụng nhiều route.
  • Không bắt buộc: widget nhỏ nhúng vào trang tĩnh hoặc SPA cực đơn giản có thể chỉ cần React/Vite.
  • Đổi tư duy: trước tiên xem phần nào có thể chạy trên server; chỉ chuyển sang client khi cần tương tác hoặc API của trình duyệt.

Cài đặt & tạo dự án

Cài môi trường, tạo ứng dụng mới và chạy localhost lần đầu.

Bước 1 — Kiểm tra công cụ

Cài Node.js từ 20.9 trở lên (nên chọn bản LTS còn được hỗ trợ) và một trình soạn thảo như VS Code. Mở terminal và chạy:

TerminalBASH
node -v
npm -v

Bước 2 — Tạo ứng dụng

TerminalBASH

cd my-next-app
npm run dev

Khi trình tạo dự án hỏi lựa chọn, nên chọn TypeScript: Yes, App Router: Yes, ESLint: Yes. Tailwind CSS có thể chọn Yes nếu muốn học utility CSS, nhưng tài liệu này cũng có ví dụ CSS Modules. Tùy chọn src/ không làm thay đổi bản chất App Router.

Mở http://localhost:3000. Nếu thấy trang mặc định thì môi trường đã sẵn sàng. Nhấn Ctrl + C trong terminal để dừng server.

Page, Layout và JSX

Tạo trang, định nghĩa layout gốc và ghép component.

Trang chủ đầu tiên

app/page.tsxTSX
export default function HomePage() {
  return (
    <main>
      <h1>Xin chào Next.js!</h1>
      <p>Đây là trang chủ.</p>
    </main>
  )
}

Tên hàm tùy chọn, nhưng file page.tsx cần default export một React component. URL được suy ra từ vị trí file: app/page.tsx tương ứng với /.

Layout gốc

app/layout.tsxTSX
import type { Metadata } from 'next'
import './globals.css'

export const metadata: Metadata = {
  title: 'Học Next.js',
  description: 'Ứng dụng Next.js đầu tiên',
}

export default function RootLayout({
  children,
}: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="vi">
      <body>{children}</body>
    </html>
  )
}

{children} là nơi trang con được đặt vào. Root layout cần có <html> và <body>. Các layout lồng nhau giúp tạo sidebar dùng chung cho một nhóm trang.

app/dashboard/layout.tsxTSX
export default function DashboardLayout({
  children,
}: { children: React.ReactNode }) {
  return (
    <div className="dashboard">
      <aside>Menu dashboard</aside>
      <section>{children}</section>
    </div>
  )
}

Khi truy cập /dashboard hoặc route bên dưới nó, phần dashboard layout bao quanh nội dung và không cần lặp lại trong từng trang.

Routing & điều hướng

Trang tĩnh, dynamic route, Link, redirect và trường hợp 404.

Route tĩnh

app/about/page.tsxTSX
export default function AboutPage() {
  return <h1>Giới thiệu</h1>
}

Tạo file trên → truy cập /about. Dùng Link từ Next.js để chuyển giữa các trang, tận dụng prefetch và client-side navigation khi phù hợp.

components/site-nav.tsxTSX
import Link from 'next/link'

export function SiteNav() {
  return (
    <nav>
      <Link href="/">Trang chủ</Link>
      <Link href="/about">Giới thiệu</Link>
      <Link href="/blog/hello-nextjs">Bài viết</Link>
    </nav>
  )
}

Dynamic route: [slug]

Tạo thư mục app/blog/[slug]/. Trong App Router phiên bản mới, params là Promise, nên đọc bằng await.

app/blog/[slug]/page.tsxTSX
type Props = {
  params: Promise<{ slug: string }>
}

export default async function BlogPost({ params }: Props) {
  const { slug } = await params
  return <h1>Bài viết: {slug}</h1>
}

404 khi tài nguyên không tồn tại

app/blog/[slug]/page.tsx (biến thể)TSX
import { notFound } from 'next/navigation'

type Props = { params: Promise<{ slug: string }> }

export default async function BlogPost({ params }: Props) {
  const { slug } = await params
  const knownPosts = ['intro', 'routing']

  if (!knownPosts.includes(slug)) notFound()
  return <h1>{slug}</h1>
}

Nếu cần đọc query string như ?page=2 ở Server Page, dùng searchParams (cũng là Promise). Nếu cần đọc tại client, dùng hook useSearchParams từ next/navigation và chú ý Suspense ở trang prerender.

Route group (marketing) để nhóm file mà không đưa tên nhóm vào URL; catch-all [...slug] bắt nhiều segment; optional catch-all [[...slug]] cho phép rỗng.

Server vs Client Components

Phân biệt code chạy ở server và code cần chạy trong trình duyệt.

Trong App Router, page và layout mặc định là Server Components. Chúng phù hợp để đọc dữ liệu, giữ bí mật ở server và giảm JavaScript gửi về trình duyệt. Khi dùng state, sự kiện click, useEffect, localStorage… bạn cần Client Component.

Server Component (mặc định)Client Component ('use client')
Có thể async/await trực tiếp trong component.Có thể dùng useState, useEffect.
Có thể truy cập DB, secrets server nếu được đặt đúng nơi.Có thể dùng API của browser: window, localStorage.
Không xử lý trực tiếp onClick của UI.Xử lý sự kiện và cập nhật UI tương tác.
Không nên truyền secret cho client.Code và dữ liệu được gửi về client có thể bị người dùng xem.

Ví dụ: dữ liệu ở server, nút ở client

components/like-button.tsxTSX
'use client'

import { useState } from 'react'

export default function LikeButton() {
  const [likes, setLikes] = useState(0)
  return (
    <button onClick={() => setLikes((n) => n + 1)}>
      ❤️ {likes} lượt thích
    </button>
  )
}
app/page.tsxTSX
import LikeButton from '@/components/like-button'

export default function HomePage() {
  return (
    <main>
      <h1>Bài viết mới</h1>
      <p>Nội dung tĩnh có thể render trên server.</p>
      <LikeButton />
    </main>
  )
}

Hãy đặt 'use client' ở ranh giới component nhỏ nhất cần tương tác, không cần gắn vào mọi file. Các component được import vào ranh giới client sẽ thuộc client bundle; Server Components vẫn có thể được truyền như children theo đúng quy tắc composition.

!
Sai lầm phổ biến

Dùng useState trong Server Component sẽ báo lỗi. Truy cập window trong render ban đầu cũng dễ gây lỗi. Chỉ thêm 'use client' khi thật sự cần và xử lý API browser trong useEffect nếu phù hợp.

Lấy dữ liệu với fetch

Gọi API từ Server Component, xử lý lỗi và tải dữ liệu song song.

Bạn có thể khai báo page là async rồi await fetch(). Trong Next.js 16, đừng giả định dữ liệu từ fetch được cache mặc định; lựa chọn cache phải có chủ đích.

app/posts/page.tsxTSX
type Post = {
  id: number
  title: string
}

export default async function PostsPage() {
  const res = await fetch(
    'https://jsonplaceholder.typicode.com/posts?_limit=5'
  )

  if (!res.ok) throw new Error('Không tải được bài viết')
  const posts: Post[] = await res.json()

  return (
    <main>
      <h1>Bài viết</h1>
      <ul>
        {posts.map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </main>
  )
}

Ví dụ sử dụng API công khai để luyện tập. Trong ứng dụng thật, Server Component thường có thể truy cập hàm DB trực tiếp, không cần gọi vòng qua /api/* của chính ứng dụng.

Tải song song bằng Promise.all

lib/data.ts (minh họa)TSX
export async function getDashboardData() {
  const [usersRes, postsRes] = await Promise.all([
    fetch('https://jsonplaceholder.typicode.com/users'),
    fetch('https://jsonplaceholder.typicode.com/posts?_limit=5'),
  ])

  if (!usersRes.ok || !postsRes.ok) {
    throw new Error('Lỗi API')
  }

  return {
    users: await usersRes.json(),
    posts: await postsRes.json(),
  }
}
✓
Suy nghĩ về vị trí fetch

Fetch trên server là lựa chọn tốt nếu dữ liệu phục vụ HTML đầu tiên/SEO và cần bảo vệ token. Fetch ở client phù hợp dữ liệu phụ thuộc tương tác liên tục, polling, realtime; có thể dùng SWR hoặc TanStack Query.

Caching & rendering mới

Hiểu Cache Components, use cache, Suspense và cách cập nhật dữ liệu.

Next.js 16 giới thiệu mô hình Cache Components theo hướng cache tường minh. Bật cacheComponents: true để dùng cách dựng trang kết hợp nội dung cache và nội dung theo request. Khái niệm quan trọng: cache phần ít đổi, stream phần luôn mới.

next.config.tsTSX
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
}

export default nextConfig

Cache một hàm lấy dữ liệu

lib/articles.tsTSX
import { cacheLife } from 'next/cache'

export async function getArticles() {
  'use cache'
  cacheLife('hours')

  const res = await fetch('https://api.vercel.app/blog')
  if (!res.ok) throw new Error('Không tải được bài viết')
  return res.json() as Promise<
    Array<{ id: number; title: string }>
  >
}
app/articles/page.tsxTSX
import { getArticles } from '@/lib/articles'

export default async function ArticlesPage() {
  const articles = await getArticles()
  return (
    <ul>
      {articles.map((a) => <li key={a.id}>{a.title}</li>)}
    </ul>
  )
}

Với 'use cache', Next.js có thể lưu kết quả theo chính sách cache; cacheLife('hours') chọn profile thời gian. Với dữ liệu theo request không được cache khi bật Cache Components, dùng <Suspense> để streaming và tạo static shell.

app/live/page.tsxTSX
import { Suspense } from 'react'

async function LiveData() {
  const res = await fetch('https://api.vercel.app/blog')
  if (!res.ok) throw new Error('Lỗi dữ liệu')
  const data: Array<{ id: number; title: string }> = await res.json()
  return <p>Đã tải {data.length} bài viết</p>
}

export default function Page() {
  return (
    <Suspense fallback={<p>Đang tải dữ liệu...</p>}>
      <LiveData />
    </Suspense>
  )
}
Tình huốngCách nghĩ
Tin giới thiệu, danh mục ít thay đổiCache kết quả với 'use cache' + cacheLife.
Giỏ hàng cá nhân, dữ liệu theo người dùngKiểm soát riêng tư; không cache công khai dữ liệu cá nhân.
Trang cần dữ liệu mới tại requestĐọc ở server và dùng Suspense/streaming.
Sau thêm/sửa/xóaDùng revalidatePath, revalidateTag hoặc API làm mới phù hợp.
!
Quan trọng về các phiên bản

Các bài viết cho Next.js 13–15 thường nhấn mạnh fetch(..., { next: { revalidate } }) hoặc force-cache. Khi cacheComponents được bật, ưu tiên mô hình 'use cache' / cacheLife. Không trộn cấu hình cũ và mới một cách máy móc.

Loading, Suspense & Error

Form & Server Actions

Gửi biểu mẫu lên server, xác thực input và phản hồi trạng thái.

Server Action là cách gọi Server Function từ UI (thường là <form action={...}>). Code chạy trên máy chủ, nhưng bạn vẫn phải kiểm tra quyền và dữ liệu đầu vào như bất kỳ API công khai nào.

Server Function: validate dữ liệu

app/contact/actions.tsTSX
'use server'

export type FormState = {
  message: string
  success: boolean
}

export async function sendMessage(
  _prev: FormState,
  formData: FormData
): Promise<FormState> {
  const name = String(formData.get('name') ?? '').trim()

  if (name.length < 2) {
    return { message: 'Tên phải có ít nhất 2 ký tự', success: false }
  }

  // DEMO: thay bằng lưu DB hoặc gửi email ở production.
  console.log('Lời chào từ:', name)

  return { message: `Cảm ơn ${name}!`, success: true }
}

}

Route Handlers / API

Tạo endpoint GET, POST với route.ts và trả JSON.

Route Handler phù hợp khi ứng dụng cần HTTP endpoint cho mobile app, webhook, client fetch hoặc dịch vụ bên ngoài. Chúng dựa trên Web Request / Response, hỗ trợ các method như GET, POST, PUT, PATCH, DELETE.

app/api/hello/route.tsTSX
export async function GET() {
  return Response.json({ message: 'Xin chào từ API!' })
}

export async function POST(request: Request) {
  let body: unknown

  try {
    body = await request.json()
  } catch {
    return Response.json({ error: 'JSON không hợp lệ' }, { status: 400 })
  }

  if (
    typeof body !== 'object' || body === null ||
    !('name' in body) || typeof body.name !== 'string'
  ) {
    return Response.json({ error: 'Thiếu name' }, { status: 400 })
  }

  const name = body.name.trim()
  if (!name || name.length > 100) {
    return Response.json({ error: 'Tên không hợp lệ' }, { status: 400 })
  }

  return Response.json({ greeting: `Xin chào ${name}` }, { status: 200 })
}

Authentication & bảo mật

Các quy tắc không thể bỏ qua trước khi mở ứng dụng cho người dùng.

Next.js cung cấp công cụ để xây web full-stack, nhưng không tự động xây hệ thống đăng nhập, phân quyền hoàn chỉnh cho mọi ứng dụng. Có thể chọn thư viện như Auth.js hoặc dịch vụ quản lý danh tính tùy kiến trúc; phiên bản và hướng dẫn tích hợp nên đối chiếu tài liệu của giải pháp đang dùng.

  • Authentication: bạn là ai? Xác minh session trên server.
  • Authorization: bạn có quyền làm thao tác này trên tài nguyên này không? Phải kiểm tra bên trong action/handler và tầng data.
  • Validation: mọi input từ form/query/body đều có thể bị sửa. Sử dụng schema như Zod khi dự án lớn.
  • Secrets: giữ ở server, không in log và không đưa vào biến NEXT_PUBLIC_.
  • Rate limiting: cân nhắc cho login, upload, API có nguy cơ bị lạm dụng.
  • Dependency updates: theo dõi bản vá Next.js, React và thư viện liên quan; cập nhật các bản bảo mật.
  • Cookies/session: cân nhắc cờ HttpOnly, Secure, SameSite, timeout và chống CSRF trong thiết kế.
  • Không tin UI: ẩn link admin không ngăn được truy cập trực tiếp vào endpoint.

Bước 3 — Component có tương tác và localStorage

components/task-board.tsxTSX
'use client'

import { useEffect, useState, type FormEvent } from 'react'
import styles from './task-board.module.css'

type Task = {
  id: string
  title: string
  done: boolean
}

const STORAGE_KEY = 'nextjs-task-board-v1'

export default function TaskBoard() {
  const [tasks, setTasks] = useState<Task[]>([])
  const [title, setTitle] = useState('')
  const [loaded, setLoaded] = useState(false)

  useEffect(() => {
    try {
      const saved = localStorage.getItem(STORAGE_KEY)
      if (saved) {
        const parsed: unknown = JSON.parse(saved)
        if (Array.isArray(parsed)) {
          setTasks(parsed.filter((item): item is Task =>
            typeof item === 'object' && item !== null &&
            typeof item.id === 'string' &&
            typeof item.title === 'string' &&
            typeof item.done === 'boolean'
          ))
        }
      }
    } catch {
      // Dữ liệu trình duyệt hỏng thì bắt đầu với danh sách trống.
    } finally {
      setLoaded(true)
    }
  }, [])

  useEffect(() => {
    if (!loaded) return
    try {
      localStorage.setItem(STORAGE_KEY, JSON.stringify(tasks))
    } catch {
      // Trình duyệt có thể chặn lưu trữ hoặc hết dung lượng.
    }
  }, [tasks, loaded])

  function addTask(event: FormEvent<HTMLFormElement>) {
    event.preventDefault()
    const value = title.trim()
    if (!value || !loaded) return

    setTasks((old) => [
      { id: crypto.randomUUID(), title: value, done: false },
      ...old,
    ])
    setTitle('')
  }

  function toggleTask(id: string) {
    setTasks((old) => old.map((task) =>
      task.id === id ? { ...task, done: !task.done } : task
    ))
  }

  function deleteTask(id: string) {
    setTasks((old) => old.filter((task) => task.id !== id))
  }

  const completed = tasks.filter((task) => task.done).length

  return (
    <section className={styles.board}>
      <form className={styles.form} onSubmit={addTask}>
        <label htmlFor="task-title">Công việc mới</label>
        <div className={styles.row}>
          <input
            id="task-title"
            value={title}
            onChange={(e) => setTitle(e.target.value)}
            placeholder="Ví dụ: Học Next.js 30 phút"
            maxLength={120}
            disabled={!loaded}
            required
          />
          <button disabled={!loaded || !title.trim()} type="submit">
            Thêm
          </button>
        </div>
      </form>

      <p className={styles.summary} role="status">
        {!loaded ? 'Đang đọc dữ liệu…' :
          `${completed}/${tasks.length} công việc đã hoàn thành`}
      </p>

      {loaded && tasks.length === 0 && <p>Chưa có công việc nào.</p>}

      <ul className={styles.list}>
        {tasks.map((task) => (
          <li className={styles.task} key={task.id}>
            <label className={styles.taskTitle}>
              <input
                type="checkbox"
                checked={task.done}
                onChange={() => toggleTask(task.id)}
              />
              <span className={task.done ? styles.done : ''}>
                {task.title}
              </span>
            </label>
            <button type="button" onClick={() => deleteTask(task.id)}
              aria-label={`Xóa ${task.title}`}>
              Xóa
            </button>
          </li>
        ))}
      </ul>
    </section>
  )
}

FAQ & lỗi thường gặp

Những lỗi bạn có thể gặp trong quá trình học.

“You’re importing a component that needs useState”+

Component đang dùng hook hoặc API client nhưng không thuộc client boundary. Đặt 'use client' ở đầu file component tương tác, và giữ phần server khác độc lập.

“window is not defined”+

Bạn dùng API trình duyệt ở bối cảnh server. Chuyển logic sang Client Component và đọc trong useEffect hoặc event handler khi phù hợp.

“Hydration mismatch”+

HTML lần render đầu trên server khác nội dung lần render đầu ở client. Tránh đọc trực tiếp localStorage, random, thời gian biến đổi trong render; dùng giá trị khởi tạo ổn định rồi đồng bộ sau khi mount.

Route /blog/abc trả về 404+

Kiểm tra file có đúng app/blog/[slug]/page.tsx, có default export và không có logic notFound() chặn slug đó.

Biến .env không có giá trị+

Kiểm tra tên biến, vị trí file, server đã khởi động lại chưa. Biến server không đọc trực tiếp trong client; NEXT_PUBLIC_ chỉ dùng cho dữ liệu có thể công khai.

Build fail dù chạy dev được+

Production build kiểm tra thêm TypeScript, prerender, Suspense và nhiều đường thực thi. Đọc log bắt đầu từ lỗi đầu tiên, chạy npx tsc --noEmit rồi sửa lần lượt.

Tutorial cũ dùng middleware.ts / params.slug+

Next.js 16 dùng convention proxy.ts thay cho middleware và route params mới có dạng Promise; với Server Component, dùng await params.

Nên dùng Pages Router hay App Router?+

Dự án mới nên học App Router trước. Pages Router vẫn tồn tại và có thể xuất hiện trong dự án cũ; hai hệ có conventions và data-fetching APIs khác nhau.
