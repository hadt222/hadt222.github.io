01 · TypeScript là gì và khi nào nên dùng?

TypeScript (TS) là JavaScript được bổ sung hệ thống kiểu tĩnh (static type system). Trình kiểm tra kiểu phân tích chương trình trước khi chạy để cảnh báo các trường hợp không hợp lệ. Sau đó, mã TypeScript thường được chuyển thành JavaScript để trình duyệt hoặc Node.js thực thi.

TypeScript
// JavaScript hợp lệ nhưng lỗi có thể chỉ xuất hiện lúc chạy
function total(price, amount) {
  return price * amount;
}

total("199.000", 2); // Dữ liệu chuỗi: kết quả dễ gây nhầm lẫn

// TypeScript mô tả rõ ý định
function calculateTotal(price: number, amount: number): number {
  return price * amount;
}

calculateTotal(199000, 2); // 398000
// calculateTotal("199000", 2); // ❌ Lỗi kiểu trước khi chạy

3 điều cần nhớ#

  • TypeScript không phải một runtime mới. Đa số chú thích kiểu bị loại bỏ trong mã JavaScript tạo ra.
  • TypeScript không tự kiểm tra dữ liệu tại runtime. JSON, request mạng và input người dùng vẫn cần kiểm tra thực tế.
  • Không phải cứ thêm kiểu là hết bug. TypeScript hỗ trợ phát hiện sai kiểu, thiết kế API rõ ràng và refactor an toàn hơn, nhưng không thay thế kiểm thử.
JavaScript TypeScript
Kiểu thường được kiểm tra khi chạy Có thể kiểm tra kiểu trước khi chạy
Ít ràng buộc khi viết Hỗ trợ hợp đồng dữ liệu, gợi ý và tái cấu trúc
Chạy trực tiếp trong nhiều môi trường Thường cần chuyển thành JS hoặc dùng runtime/tool hỗ trợ TS

Lộ trình gợi ý: Hãy biết JavaScript cơ bản (const, let, function, object, array, promise, import/export) trước khi đi sâu vào TypeScript. Bạn có thể học theo thứ tự các chương trên trang này.

02 · Cài đặt môi trường và chạy chương trình đầu tiên

Bạn cần cài Node.js, một terminal và trình soạn thảo như VS Code. Cách ổn định cho dự án là cài TypeScript nội bộ bằng npm thay vì cài toàn cục. Tại thời điểm biên soạn (11/2026), tài liệu chính thức nêu TypeScript 7.0 là bản ổn định và 7.1 đang beta; ví dụ dưới đây dùng dòng 7.x ổn định.

Bước 1 — Tạo dự án#

Terminal
mkdir hoc-typescript
cd hoc-typescript
npm init -y
npm install -D typescript @types/node
npm pkg set type=module
npx tsc --version

-D có nghĩa là development dependency. @types/node cung cấp khai báo kiểu cho API Node.js. type=module giúp ví dụ sử dụng ESM.

Bước 2 — Tạo tsconfig.json#

Terminal
npx tsc --init

Thay nội dung tsconfig.json thành cấu hình Node.js ESM đơn giản sau:

JSON
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "rootDir": "./src",
    "outDir": "./dist",
    "strict": true,
    "types": ["node"],
    "skipLibCheck": true
  },
  "include": ["src/**/*.ts"]
}

strict: true là lựa chọn rất nên dùng để phát hiện lỗi sớm. rootDir và outDir phân tách mã nguồn và mã biên dịch.

Bước 3 — Viết, biên dịch, chạy#

Tạo thư mục src, sau đó tạo tệp src/index.ts:

TypeScript
const student: string = "Minh";
const completedLessons: number = 3;

console.log(`Xin chào ${student}! Đã học ${completedLessons} bài.`);
Terminal
npx tsc                  # Kiểm tra kiểu và biên dịch vào dist/
node dist/index.js       # Chạy JavaScript đã được tạo
npx tsc --noEmit         # Chỉ kiểm tra kiểu, không tạo tệp JS
npx tsc --watch          # Biên dịch lại khi tệp thay đổi

Kết quả dự kiến: Xin chào Minh! Đã học 3 bài.. Nếu báo không tìm thấy src/index.ts, kiểm tra lại tên thư mục/tệp. Bạn cũng có thể thử nhanh trên TypeScript Playground mà không cần cài gì.

03 · Kiểu dữ liệu cơ bản và suy luận kiểu

Một biến có thể được ghi rõ kiểu bằng dấu :. Tuy nhiên, type inference (suy luận kiểu) thường cho phép bỏ chú thích dư thừa mà vẫn an toàn.

TypeScript
let age: number = 24;
let fullName: string = "Lan";
let isActive: boolean = true;
let luckyNumber = 7;    // TypeScript suy luận là number

// luckyNumber = "bảy"; // ❌ string không gán được cho number

null, undefined, any, unknown, never, void#

TypeScript
let optionalText: string | null = null;
optionalText = "Sẵn sàng";

let anything: any = 10;
anything.doSomething(); // Có thể lỗi runtime; TS bỏ qua kiểm tra

let input: unknown = "Hello";
// input.toUpperCase(); // ❌ Cần kiểm tra trước
if (typeof input === "string") {
  console.log(input.toUpperCase());
}

function logMessage(message: string): void {
  console.log(message);
}

function fail(message: string): never {
  throw new Error(message); // Không kết thúc bình thường
}
  • any: tắt phần lớn bảo vệ kiểu tại vị trí đó; nên hạn chế.
  • unknown: chấp nhận giá trị bất kỳ nhưng phải kiểm tra trước khi sử dụng.
  • void: hàm không trả về kết quả hữu ích cho người gọi.
  • never: trạng thái không thể xảy ra hoặc hàm không trả về bình thường.

Literal type và as const#

TypeScript
let direction: "left" | "right" = "left";
// direction = "up"; // ❌ Không thuộc tập giá trị cho phép

const settings = {
  theme: "dark",
  pageSize: 20
} as const;

// settings.theme có kiểu "dark" và thuộc tính readonly

Mẹo: Ưu tiên để TypeScript tự suy luận với biến cục bộ; ghi rõ kiểu tại ranh giới API, tham số hàm và cấu trúc dữ liệu quan trọng.

04 · Array, tuple và readonly

Mảng chứa các phần tử cùng kiểu. Tuple dùng khi vị trí và số lượng phần tử có ý nghĩa rõ ràng.

TypeScript
const scores: number[] = [8, 9, 10];
const names: Array<string> = ["An", "Bình"];

const doubled = scores.map((score) => score * 2);
// doubled có kiểu number[]

const userRecord: [id: number, name: string] = [101, "Hà"];
const [id, name] = userRecord;

Tránh sửa dữ liệu ngoài ý muốn#

TypeScript
function sum(values: readonly number[]): number {
  // values.push(4); // ❌ Không được chỉnh sửa thông qua tham chiếu này
  return values.reduce((total, n) => total + n, 0);
}

const statusTuple = ["success", 200] as const;
// Kiểu: readonly ["success", 200]

readonly và as const là bảo vệ ở mức kiểu, không tự đóng băng đối tượng tại runtime. Nếu cần chặn sửa đổi khi chạy, hãy cân nhắc cơ chế của JavaScript như Object.freeze() (với giới hạn đóng băng nông).

05 · Object, type, interface và optional property

Dùng object type để mô tả hình dạng dữ liệu. Thuộc tính có dấu ? có thể vắng mặt; readonly không cho gán lại qua hệ thống kiểu.

TypeScript
type Product = {
  id: number;
  name: string;
  price: number;
  description?: string;
  readonly sku: string;
};

const keyboard: Product = {
  id: 1,
  name: "Bàn phím",
  price: 450000,
  sku: "KB-001"
};

console.log(keyboard.description?.toUpperCase() ?? "Chưa mô tả");
// keyboard.sku = "NEW"; // ❌ readonly

interface và kế thừa#

TypeScript
interface Person {
  id: number;
  name: string;
}

interface Employee extends Person {
  department: string;
}

const employee: Employee = {
  id: 7,
  name: "Nhi",
  department: "Engineering"
};

Nên dùng type hay interface? Cả hai đều mô tả object rất tốt. interface phù hợp cho object có tính mở rộng/kế thừa; type linh hoạt hơn khi đặt tên cho union, tuple, primitive hay kiểu được kết hợp. Hãy chọn theo nhu cầu và thống nhất quy ước dự án.

Index signature và Record#

TypeScript
interface Inventory {
  [productId: string]: number;
}

const stock: Inventory = { "A-01": 12, "B-02": 6 };
const points: Record<string, number> = { Lan: 10, Nam: 8 };

06 · Function: tham số, trả về, overload và callback

Nên khai báo rõ kiểu cho tham số. Return type có thể suy luận, nhưng khai báo tường minh hữu ích ở API công khai.

TypeScript
function greet(name: string, title = "Bạn"): string {
  return `Chào ${title} ${name}`;
}

function calculate(price: number, discount?: number): number {
  return price * (1 - (discount ?? 0));
}

const multiply = (a: number, b: number): number => a * b;

type Comparator = (a: number, b: number) => number;
const compareNumbers: Comparator = (a, b) => a - b;

Rest parameter, destructuring, callback#

TypeScript
function average(...values: number[]): number {
  if (values.length === 0) return 0;
  return values.reduce((a, b) => a + b, 0) / values.length;
}

function printUser({ name, age }: { name: string; age: number }) {
  console.log(name, age);
}

function transform(values: number[], fn: (n: number) => string) {
  return values.map(fn); // string[]
}

const labels = transform([1, 2, 3], (n) => `#${n}`);

Overload khi các đầu vào dẫn đến kiểu đầu ra khác nhau#

TypeScript
function format(value: number): string;
function format(value: Date): string;
function format(value: number | Date): string {
  return value instanceof Date
    ? value.toISOString()
    : value.toFixed(2);
}

format(3.14159);      // "3.14"
format(new Date());  // Chuỗi thời gian ISO

Phân biệt: ? làm tham số có thể được bỏ qua; | undefined cho phép truyền undefined nhưng bản thân tham số vẫn có thể là bắt buộc.

07 · Union, intersection và discriminated union

Union (|) nghĩa là một trong các kiểu; intersection (&) nghĩa là phải thỏa các kiểu kết hợp.

TypeScript
type Id = string | number;
type Timestamps = { createdAt: Date; updatedAt: Date };
type Article = { id: Id; title: string } & Timestamps;

const article: Article = {
  id: "post-01",
  title: "Học TypeScript",
  createdAt: new Date(),
  updatedAt: new Date()
};

Discriminated union — mô hình hóa trạng thái đúng cách#

TypeScript
type RequestState<T> =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: T }
  | { status: "error"; message: string };

function display(state: RequestState<string>) {
  switch (state.status) {
    case "idle": return "Chưa bắt đầu";
    case "loading": return "Đang tải...";
    case "success": return state.data.toUpperCase();
    case "error": return `Lỗi: ${state.message}`;
  }
}

Thiết kế này ngăn các trạng thái vô nghĩa kiểu như loading: true nhưng đồng thời có data và error. status là discriminant để trình biên dịch thu hẹp kiểu.

08 · Narrowing và type guard

Narrowing là quá trình thu hẹp union qua các nhánh điều kiện. TypeScript hiểu typeof, in, instanceof, so sánh giá trị và một số điều kiện luồng điều khiển.

TypeScript
function prettyPrint(value: string | number): string {
  if (typeof value === "number") {
    return value.toFixed(2); // value: number
  }
  return value.toUpperCase(); // value: string
}

type Cat = { kind: "cat"; meow: () => void };
type Dog = { kind: "dog"; bark: () => void };

function sound(animal: Cat | Dog): void {
  if (animal.kind === "cat") animal.meow();
  else animal.bark();
}

User-defined type guard#

TypeScript
type Profile = { id: number; name: string };

function isProfile(value: unknown): value is Profile {
  if (typeof value !== "object" || value === null) return false;
  const obj = value as Record<string, unknown>;
  return typeof obj.id === "number" && typeof obj.name === "string";
}

const raw: unknown = JSON.parse('{"id": 5, "name": "Vy"}');
if (isProfile(raw)) {
  console.log(raw.name); // Profile trong nhánh này
}

Exhaustive check với never#

TypeScript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle": return Math.PI * shape.radius ** 2;
    case "square": return shape.side ** 2;
    default: {
      const impossible: never = shape;
      return impossible;
    }
  }
}

Thêm một biến thể vào Shape mà quên xử lý trong switch sẽ khiến nhánh never báo lỗi biên dịch.

09 · Generic: tái sử dụng kiểu mà không mất thông tin

Generic dùng tham số kiểu (T, K, V...) để viết hàm, kiểu và cấu trúc dữ liệu hoạt động với nhiều loại đầu vào mà vẫn giữ được thông tin kiểu.

TypeScript
function identity<T>(value: T): T {
  return value;
}

const a = identity(42);        // number
const b = identity("Xin chào"); // string

function first<T>(items: readonly T[]): T | undefined {
  return items[0];
}

const firstName = first(["An", "Bình"]); // string | undefined

Generic constraint extends#

TypeScript
type HasId = { id: string | number };

function findById<T extends HasId>(items: T[], id: T["id"]): T | undefined {
  return items.find((item) => item.id === id);
}

const users = [{ id: 1, name: "Lan" }, { id: 2, name: "Nam" }];
const found = findById(users, 2); // Có kiểu { id: number; name: string } | undefined

Generic interface và class#

TypeScript
interface ApiResponse<T> {
  data: T;
  success: boolean;
}

class Store<T> {
  private items: T[] = [];
  add(item: T): void { this.items.push(item); }
  list(): readonly T[] { return this.items; }
}

const numberStore = new Store<number>();
numberStore.add(10);

Quy tắc thực hành: Chỉ dùng generic khi cần tạo mối liên hệ giữa các kiểu. Với hàm chỉ nhận một số và trả về boolean, number và boolean thường rõ ràng hơn <T>.

10 · keyof, typeof, indexed access và satisfies

Nhóm công cụ này tạo ra kiểu dựa trên kiểu hoặc giá trị đã có, giúp tránh lặp khai báo.

TypeScript
type User = { id: number; name: string; active: boolean };
type UserKeys = keyof User;    // "id" | "name" | "active"
type UserName = User["name"]; // string

function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { id: 7, name: "Huy", active: true };
const name = getProperty(user, "name"); // string
// getProperty(user, "email"); // ❌ Sai khóa

typeof trong vị trí kiểu#

TypeScript
const appConfig = {
  mode: "production",
  retry: 3
};

type AppConfig = typeof appConfig;
// { mode: string; retry: number }

satisfies: kiểm tra hình dạng mà giữ suy luận hữu ích#

TypeScript
type Palette = Record<"primary" | "danger", string | [number, number, number]>;

const palette = {
  primary: "#2563eb",
  danger: [220, 38, 38]
} satisfies Palette;

palette.primary.toUpperCase(); // Vẫn nhận biết đây là string
// Nếu thiếu 'danger' hoặc kiểu sai, TypeScript sẽ báo lỗi

Phân biệt: : Palette gán kiểu cho biến; satisfies Palette kiểm tra tính tương thích nhưng thường bảo toàn nhiều thông tin suy luận hơn. as Palette là type assertion, không tương đương kiểm chứng dữ liệu.

11 · Utility types và kiểu nâng cao

TypeScript cung cấp các utility types phổ biến để biến đổi kiểu thay vì viết lại từ đầu.

TypeScript
interface User {
  id: number;
  name: string;
  email: string;
  passwordHash: string;
}

type UserPatch = Partial<User>;                 // Tất cả optional
type UserRequired = Required<User>;             // Tất cả bắt buộc
type PublicUser = Omit<User, "passwordHash">;  // Bỏ trường nhạy cảm
type UserSummary = Pick<User, "id" | "name">; // Lấy một số trường
type ReadonlyUser = Readonly<User>;             // Thuộc tính readonly
type EmailLookup = Record<string, PublicUser>;

Exclude, Extract, NonNullable, ReturnType, Parameters#

TypeScript
type Status = "draft" | "published" | "archived";
type ActiveStatus = Exclude<Status, "archived">;
type FinalStatus = Extract<Status, "published" | "archived">;
type SafeName = NonNullable<string | null | undefined>; // string

function createPoint(x: number, y: number) { return { x, y }; }
type Point = ReturnType<typeof createPoint>;       // { x: number; y: number }
type PointArgs = Parameters<typeof createPoint>;   // [x: number, y: number]

Mapped, conditional và template literal types#

TypeScript
type Nullable<T> = { [K in keyof T]: T[K] | null };
type IsString<T> = T extends string ? true : false;

type EventName = "click" | "focus";
type HandlerName = `on${Capitalize<EventName>}`;
// "onClick" | "onFocus"

type ElementType<T> = T extends readonly (infer U)[] ? U : never;
type Item = ElementType<string[]>; // string

Đây là lập trình ở cấp kiểu: chỉ tác động lúc kiểm tra kiểu, không tự sinh hành vi runtime.

12 · Class, access modifier và interface implementation

Class trong TypeScript phát triển từ class JavaScript, có bổ sung mô tả kiểu và các modifier như private, protected, public, readonly.

TypeScript
interface Payable {
  pay(amount: number): string;
}

class Wallet implements Payable {
  constructor(
    public readonly owner: string,
    private balance: number = 0
  ) {}

  deposit(amount: number): void {
    if (amount <= 0) throw new Error("Số tiền không hợp lệ");
    this.balance += amount;
  }

  pay(amount: number): string {
    if (amount > this.balance) throw new Error("Không đủ số dư");
    this.balance -= amount;
    return `Đã thanh toán ${amount}`;
  }

  getBalance(): number { return this.balance; }
}

const wallet = new Wallet("Hà", 100000);
wallet.pay(20000);

Kế thừa và abstract class#

TypeScript
abstract class Animal {
  constructor(public name: string) {}
  abstract speak(): string;
}

class Bird extends Animal {
  speak(): string { return `${this.name}: chip chip`; }
}

Lưu ý: private của TypeScript chủ yếu là ràng buộc ở compile time; muốn quyền riêng tư được JavaScript đảm bảo ở runtime có thể dùng trường #privateField. Hãy ưu tiên composition khi quan hệ kế thừa trở nên phức tạp.

14 · Promise, async/await và xử lý lỗi

Hàm async luôn trả về Promise. TypeScript mô tả kiểu giá trị khi Promise hoàn thành, nhưng không chứng minh yêu cầu mạng sẽ thành công.

TypeScript
type Todo = { id: number; title: string; done: boolean };

async function loadTodo(id: number): Promise<Todo> {
  // Ví dụ giả lập dữ liệu; không thực hiện request mạng
  return { id, title: "Học generic", done: false };
}

async function main(): Promise<void> {
  try {
    const todo = await loadTodo(1);
    console.log(todo.title);
  } catch (error: unknown) {
    const message = error instanceof Error ? error.message : String(error);
    console.error(message);
  }
}

void main();

Chạy đồng thời với Promise.all#

TypeScript
async function loadDashboard() {
  const [userCount, latestMessage] = await Promise.all([
    Promise.resolve(42),
    Promise.resolve("Xin chào")
  ]);
  // userCount: number; latestMessage: string
  return { userCount, latestMessage };
}

Nên xử lý catch như unknown và thu hẹp an toàn. Với tác vụ thực tế, hãy cân nhắc timeout, retry hợp lý và thông báo lỗi có ngữ cảnh.

15 · API, JSON và kiểm tra dữ liệu lúc chạy

Một trong những nhầm lẫn lớn nhất: viết const data = await response.json() as User không kiểm tra JSON có đúng là User hay không. TypeScript không thể bảo đảm nội dung server gửi về.

TypeScript
type ApiUser = { id: number; email: string };

function isApiUser(value: unknown): value is ApiUser {
  if (typeof value !== "object" || value === null) return false;
  const obj = value as Record<string, unknown>;
  return typeof obj.id === "number" && typeof obj.email === "string";
}

async function fetchUser(url: string): Promise<ApiUser> {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);

  const data: unknown = await response.json();
  if (!isApiUser(data)) throw new Error("Dữ liệu API không đúng định dạng");
  return data;
}

Ví dụ là kiểm tra tối thiểu hai thuộc tính; sản phẩm thật nên có schema rõ hơn, ràng buộc chuỗi email, object lồng nhau, mảng, giới hạn số và thông báo lỗi phù hợp. Có thể cân nhắc các thư viện schema validation khi cần.

TypeScript
const button = document.querySelector<HTMLButtonElement>("#submit");

button?.addEventListener("click", () => {
  button.disabled = true;
  button.textContent = "Đã gửi";

16 · tsconfig.json: những tùy chọn quan trọng

tsconfig.json cho compiler biết kiểm tra kiểu ở mức nào, xử lý module ra sao và đưa kết quả đi đâu. Dưới đây là gợi ý cho dự án front-end dùng bundler, không phải cấu hình chung cho mọi trường hợp.

JSON
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "lib": ["ES2022", "DOM"],
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noEmit": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
Tùy chọn Tác dụng
strict Bật nhóm kiểm tra nghiêm ngặt.
target Chọn mức JavaScript phát ra (nếu có emit).
module Quy định dạng module JS.
moduleResolution Cách tìm module khi import.
noEmit Chỉ kiểm tra kiểu; công cụ khác chịu trách nhiệm build.
noUncheckedIndexedAccess Truy cập phần tử theo index có thể nhận thêm undefined.
exactOptionalPropertyTypes Phân biệt thuộc tính vắng mặt và thuộc tính có giá trị undefined trong nhiều phép gán.
types Khai báo những bộ kiểu toàn cục từ @types cần nạp.

Điểm cần chú ý trong TypeScript 7#

  • TypeScript 7 có các mặc định mới; strict bật mặc định, nhưng vẫn nên ghi rõ trong cấu hình nhóm.
  • moduleResolution: "node"/"node10", target: "es5" và một số tuỳ chọn cũ không còn được hỗ trợ. Ưu tiên NodeNext hoặc Bundler theo môi trường.
  • types mặc định là []; với Node.js nên khai báo "types": ["node"] nếu dùng các global/API Node.
  • Công cụ phụ trợ phụ thuộc vào compiler API có thể cần kiểm tra tương thích với TypeScript 7; TypeScript 7.1 đang được phát triển để bổ sung API mới.

Tham khảo chính thức: TSConfig Reference và TypeScript 7.0 release notes.

17 · Mini project: quản lý công việc có kiểu an toàn

Hãy áp dụng type, union, generic và hàm để làm một Todo Manager bằng TypeScript thuần. Tạo src/index.ts và chép ví dụ dưới đây; chạy bằng npx tsc && node dist/index.js trong dự án Node ở chương 02.

TypeScript
type Priority = "low" | "medium" | "high";

type Todo = {
  id: number;
  title: string;
  completed: boolean;
  priority: Priority;
};

type CreateTodo = Pick<Todo, "title" | "priority">;

class TodoManager {
  private tasks: Todo[] = [];
  private nextId = 1;

  add(input: CreateTodo): Todo {
    const todo: Todo = {
      id: this.nextId++,
      title: input.title.trim(),
      priority: input.priority,
      completed: false
    };
    if (!todo.title) throw new Error("Tiêu đề không được trống");
    this.tasks.push(todo);
    return todo;
  }

  complete(id: number): boolean {
    const todo = this.tasks.find((item) => item.id === id);
    if (!todo) return false;
    todo.completed = true;
    return true;
  }

  list(filter: "all" | "done" | "open" = "all"): Todo[] {
    return this.tasks.filter((item) =>
      filter === "all" || (filter === "done" ? item.completed : !item.completed)
    );
  }

  remove(id: number): boolean {
    const index = this.tasks.findIndex((item) => item.id === id);
    if (index === -1) return false;
    this.tasks.splice(index, 1);
    return true;
  }
}

const manager = new TodoManager();
const first = manager.add({ title: "Học union", priority: "high" });
manager.add({ title: "Luyện generic", priority: "medium" });
manager.complete(first.id);
console.log(manager.list("done"));
console.log("Đang làm:", manager.list("open"));

Mở rộng dự án#

  1. Thêm dueDate?: string và sắp xếp theo hạn chót.
  2. Thêm update(id, patch) với Partial<Pick<Todo, "title" | "priority">>.
  3. Tách thành todo.types.ts, todo-manager.ts, index.ts và dùng ESM import .js.
  4. Viết kiểm thử cho tiêu đề rỗng, ID không tồn tại và cập nhật trạng thái.

Gợi ý thiết kế: Kiểu an toàn giúp IDE hỗ trợ tốt hơn, nhưng điều kiện nghiệp vụ như “tiêu đề không được trống” vẫn cần kiểm tra trong hàm add().

function sumPositive(values: readonly number[]): number {
  return values.filter((n) => n > 0).reduce((sum, n) => sum + n, 0);
}

Bài 3 — Generic pluck#

Viết hàm lấy danh sách giá trị của một khóa có thật trên mỗi object, bảo toàn kiểu của phần tử trả về.

function pluck<T, K extends keyof T>(items: readonly T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

const names = pluck([{ id: 1, name: "An" }], "name"); // string[]

Bài 4 — Validate dữ liệu người dùng#

Viết một type guard cho { username: string; age: number }, yêu cầu tuổi là số nguyên không âm.

Hiện gợi ý và lời giải
TypeScript
type PersonInput = { username: string; age: number };

function isPersonInput(value: unknown): value is PersonInput {
  if (typeof value !== "object" || value === null) return false;
  const o = value as Record<string, unknown>;
  return typeof o.username === "string"
    && typeof o.age === "number"
    && Number.isInteger(o.age)
    && o.age >= 0;
}
