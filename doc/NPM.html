01 Tổng quan

npm và Vite có phải là một?

Không. npm giúp quản lý các gói phần mềm và chạy script trong dự án JavaScript. Vite là bộ công cụ chạy môi trường phát triển frontend và tạo bản build để phát hành.

📦

npm — người quản lý gói

Đi kèm với bản cài Node.js thông thường. Dùng để cài/xóa/cập nhật thư viện từ npm registry, đọc package.json và chạy npm run ....

⚡

Vite — công cụ frontend

Cung cấp development server phản hồi nhanh, tự cập nhật nội dung khi sửa mã (HMR), hỗ trợ ES modules, xử lý CSS/tài nguyên và tạo build tối ưu.

Bốn thành phần phối hợp thế nào?

🟢Node.jsMôi trường chạy JS
📦npmCài gói & chạy script
⚡ViteServe & build web
🌐BrowserHiển thị ứng dụng

Ví dụ: bạn gõ npm run dev → npm tìm script tên dev trong package.json → script gọi lệnh vite → Vite mở máy chủ local cho trình duyệt.

Ghi nhớ 1 câuNode.js là nền tảng chạy công cụ, npm là trình quản lý phụ thuộc, Vite là một công cụ được cài vào dự án qua npm. Chúng không thay thế cho nhau.
02 Điều kiện ban đầu

Chuẩn bị môi trường

Bạn cần Node.js, npm, trình biên tập như Visual Studio Code và một trình duyệt hiện đại.

  1. Cài Node.js từ trang chính thức

    Mở nodejs.org/en/download, chọn bản LTS đang được hỗ trợ phù hợp hệ điều hành. Các bản Vite hiện hành yêu cầu Node.js 20.19+ hoặc 22.12+ trên các dòng tương ứng; nên ưu tiên bản LTS mới đáp ứng yêu cầu.

  2. Kiểm tra Node.js và npm

    Mở Terminal (macOS/Linux) hoặc PowerShell/Terminal (Windows), nhập hai lệnh:

    Terminal 
    node -v
npm -v

    Thấy số phiên bản như v24.x.x và 11.x.x là đã nhận diện lệnh (các con số chỉ là ví dụ).

  3. Mở thư mục làm việc bằng VS Code

    Cài VS Code. Mở Terminal tích hợp qua menu Terminal → New Terminal. Dùng pwd (macOS/Linux) hoặc Get-Location (PowerShell) để biết đang ở đâu.

Lưu ý về phiên bảnYêu cầu Node.js có thể thay đổi khi Vite ra phiên bản mới. Nếu báo Unsupported engine hoặc thiếu phiên bản Node.js, hãy kiểm tra lại hướng dẫn chính thức của Vite và nâng cấp Node.js.
03 Hiểu npm

Nền tảng npm và package.json

npm là công cụ dòng lệnh để làm việc với các package. Mỗi dự án npm thường có các tệp/thư mục sau:

Thành phầnÝ nghĩaGit?
package.jsonKhai báo tên dự án, scripts, dependencies, devDependencies, phiên bản...✓ Commit
package-lock.jsonKhóa cây phiên bản phụ thuộc giúp cài đặt có khả năng tái lập.✓ Commit
node_modules/Các package đã tải về trên máy; có thể tạo lại bằng npm install/ci.✕ Không commit
.gitignoreDanh sách file/thư mục Git bỏ qua, thường có node_modules, dist.✓ Commit

Khởi tạo một package npm trống

Terminal 
mkdir demo-npm
cd demo-npm
npm init -y

Lệnh npm init -y sinh package.json với các giá trị mặc định. Với dự án Vite ở phần sau, npm create vite@latest sẽ tạo sẵn file này, nên không cần chạy npm init -y lần nữa.

Đọc một file package.json mẫu

package.json · minh họa, phiên bản chỉ là ví dụ 
{
  "name": "demo-frontend",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "dayjs": "^1.11.0"
  },
  "devDependencies": {
    "vite": "^8.0.0"
  }
}

dependencies dành cho thư viện ứng dụng cần dùng; devDependencies dành cho công cụ phát triển/build như Vite. Ví dụ phiên bản trên chỉ để giải thích cấu trúc, không nên dùng để ghim phiên bản khi tạo dự án mới; hãy để lệnh khởi tạo ghi phiên bản phù hợp.

SemVer: ^, ~ và phiên bản cố định

Khai báoÝ nghĩa gần đúng với phiên bản ổn định ≥ 1.0
"^1.2.3"Chấp nhận cập nhật tương thích trong nhánh 1.x (không lên 2.0.0).
"~1.2.3"Chấp nhận cập nhật bản vá trong nhánh 1.2.x.
"1.2.3"Yêu cầu đúng phiên bản 1.2.3 trong khai báo trực tiếp.

Với phiên bản 0.x, quy tắc dấu ^ chặt hơn; và dù dùng range nào, file package-lock.json vẫn ghi chi tiết các phiên bản đã giải quyết.

npm install hay npm ci?npm install dùng khi phát triển/cài thêm package và có thể cập nhật lockfile. npm ci dùng khi muốn cài sạch, tái lập từ lockfile (thường trong CI/CD); yêu cầu package.json và lockfile khớp nhau.

05 Bắt đầu với Vite

Tạo và chạy dự án Vite đầu tiên

Chọn Vanilla JavaScript trước để hiểu Vite mà không bị phân tán bởi framework.

  1. Tạo dự án

    Mở Terminal tại nơi muốn chứa dự án, sau đó chạy:

    Terminal 
    npm create vite@latest hello-vite -- --template vanilla

    hello-vite là tên thư mục; --template vanilla chọn JavaScript thuần.

  2. Vào thư mục và cài dependencies

    Terminal 
    cd hello-vite
npm install

  3. Khởi động máy chủ phát triển

    Terminal 
    npm run dev

    Mở URL được in trong Terminal, thường là http://localhost:5173. Nếu cổng đã được dùng, Vite có thể chọn cổng khác: hãy đọc chính URL hiển thị.

  4. Sửa file và quan sát

    Mở src/main.js hoặc index.html, sửa một đoạn nội dung và lưu. Trình duyệt thường cập nhật ngay nhờ HMR hoặc reload.

Muốn dùng React, Vue hoặc TypeScript?

Các template thông dụng 
# React + JavaScript
npm create vite@latest web-react -- --template react

# React + TypeScript
npm create vite@latest web-react-ts -- --template react-ts

# Vue + JavaScript
npm create vite@latest web-vue -- --template vue

# JavaScript thuần + TypeScript
npm create vite@latest web-ts -- --template vanilla-ts

Các template còn có thể thay đổi qua các phiên bản. Xem danh sách mới nhất tại Vite Getting Started.

06 Đọc mã dự án

Cấu trúc một dự án Vite

Đây là cấu trúc tối giản minh họa sau khi bạn đã xóa các file demo không cần thiết của template. Mẫu được tạo thực tế có thể có thêm src/counter.js, biểu tượng, v.v.

Hai nơi đặt tài nguyên: public/ và src/

public/

Dành cho ảnh/tệp cần được phục vụ nguyên dạng, có thể truy cập bằng đường dẫn gốc như /logo.png. Không phải nguồn import để Vite xử lý asset như trong src/.

src/

Chứa mã và tài nguyên được Vite xử lý. Ví dụ import logo from './logo.svg', Vite đưa asset vào đồ thị module và xử lý URL khi build.

Vì sao index.html ở thư mục gốc?

Trong Vite, index.html là điểm vào của ứng dụng. Thẻ <script type="module" src="/src/main.js"> giúp trình duyệt tải JavaScript theo chuẩn ES modules.

Không chạy ứng dụng Vite chỉ bằng cách nhấp đúp index.htmlHãy sử dụng npm run dev khi phát triển hoặc một máy chủ tĩnh phù hợp để phục vụ thư mục dist sau build. URL dạng file:// có thể làm hỏng module, đường dẫn và các yêu cầu HTTP.
07 Bài thực hành đầy đủ

Xây ứng dụng “Ghi chú nhanh”

Ta sẽ tạo một ứng dụng có thể thêm ghi chú, xóa ghi chú và lưu dữ liệu vào localStorage. Từ đó thấy rõ cách HTML, CSS, JavaScript và Vite phối hợp với nhau.

Chuẩn bịThực hiện trong dự án hello-vite vừa tạo. Xóa nội dung demo cũ trong index.html và thay nội dung các tệp src/main.js, src/style.css theo các ví dụ bên dưới.

Bước 2. Viết JavaScript

Thay toàn bộ file src/main.js. Dòng import './style.css' giúp Vite nạp CSS trực tiếp từ JavaScript. Chúng ta dùng textContent thay vì chèn HTML do người dùng nhập.

src/main.js 
import './style.css';

const KEY = 'vite-notes-demo';
const form = document.querySelector('#note-form');
const input = document.querySelector('#note-input');
const list = document.querySelector('#note-list');
const count = document.querySelector('#count');
const empty = document.querySelector('#empty');

// Đọc dữ liệu cũ nếu có; nếu lỗi, bắt đầu từ mảng rỗng.
let notes;
try {
  const stored = JSON.parse(localStorage.getItem(KEY) || '[]');
  notes = Array.isArray(stored) ? stored : [];
} catch {
  notes = [];
}

function save() {
  localStorage.setItem(KEY, JSON.stringify(notes));
}

function render() {
  list.replaceChildren();
  count.textContent = `${notes.length} ghi chú`;
  empty.hidden = notes.length > 0;

  notes.forEach((note) => {
    const li = document.createElement('li');
    const text = document.createElement('span');
    const remove = document.createElement('button');

    text.textContent = note.text;
    remove.textContent = 'Xóa';
    remove.type = 'button';
    remove.setAttribute('aria-label', `Xóa: ${note.text}`);
    remove.addEventListener('click', () => {
      notes = notes.filter((item) => item.id !== note.id);
      save();
      render();
    });

    li.append(text, remove);
    list.append(li);
  });
}

form.addEventListener('submit', (event) => {
  event.preventDefault(); // Tránh tải lại trang
  const text = input.value.trim();
  if (!text) return;

  notes.unshift({ id: crypto.randomUUID(), text });
  save();
  render();
  form.reset();
  input.focus();
});

render();

    08 Mở rộng

    Cấu hình Vite và biến môi trường

    Vite config: cổng dev server và base path

    Tạo hoặc chỉnh vite.config.js ở gốc dự án nếu cần cấu hình tùy chỉnh:

    vite.config.js 
    import { defineConfig } from 'vite';

export default defineConfig({
  server: {
    port: 3000,
    strictPort: true
  },
  // Dùng '/ten-repo/' nếu triển khai dưới đường dẫn đó.
  base: '/'
});

    strictPort: true khiến Vite báo lỗi nếu cổng 3000 bận, thay vì tự chọn cổng khác. Nếu dùng GitHub Pages kiểu username.github.io/ten-repo/, đổi base thành '/ten-repo/' trước khi build.

    Biến môi trường với .env

    Tạo file .env ở gốc dự án:

    .env 
    VITE_APP_TITLE=Ứng dụng đầu tiên
VITE_API_URL=https://api.example.com

    Đọc giá trị trong JavaScript:

    src/main.js · ví dụ độc lập 
    console.log(import.meta.env.VITE_APP_TITLE);
console.log(import.meta.env.VITE_API_URL);
console.log(import.meta.env.MODE);
console.log(import.meta.env.DEV);
    Cực kỳ quan trọng: biến VITE_ không phải bí mậtBiến có tiền tố VITE_ được đưa vào mã frontend và người dùng cuối có thể xem. Không bao giờ đặt API secret, mật khẩu hay private key tại đây. Khóa bí mật phải ở backend/server an toàn. Sau khi sửa .env, hãy khởi động lại dev server.

    Các mode

    Vite dùng mode development khi chạy dev và production khi build theo mặc định. Có thể tạo .env.production và .env.development để dùng cấu hình khác nhau. import.meta.env.MODE cho biết mode; nó không hoàn toàn đồng nghĩa với NODE_ENV.

    HMR và ES modules

    HMR (Hot Module Replacement) thường cập nhật module thay đổi mà không cần tải lại toàn bộ trang. Với ES modules, bạn có thể chia ứng dụng ra nhiều file và dùng import/export:

    Ví dụ chia module 
    // src/math.js
export const sum = (a, b) => a + b;

// src/main.js
import { sum } from './math.js';
console.log(sum(2, 3)); // 5
    09 Đưa sản phẩm ra ngoài

    Build production và triển khai

    Dev server giúp lập trình thuận tiện; production build tạo ra các file frontend tối ưu để máy chủ tĩnh phục vụ cho người dùng.

    1. Tạo bản build

      Terminal 
      npm run build

      Theo cấu hình mặc định, Vite tạo thư mục dist/, thường chứa index.html và các file trong assets/.

    2. Kiểm tra bản build tại máy

      Terminal 
      npm run preview

      Mở URL Terminal hiển thị (thường http://localhost:4173) để kiểm tra.

    3. Triển khai lên dịch vụ hosting tĩnh

      Đưa code lên GitHub rồi kết nối với Vercel, Netlify, Cloudflare Pages hoặc dùng GitHub Pages có workflow build. Cấu hình phổ biến: Build command = npm run build, Output directory = dist. Thiết lập các biến môi trường không bí mật cần thiết ở nền tảng deploy.

    Lưu ý nếu triển khai GitHub Pages

    Với URL dạng https://USERNAME.github.io/REPO/, cấu hình base: '/REPO/' trong vite.config.js. Với site ở root của domain, thường dùng base: '/'. GitHub Pages cần quy trình build, thường thực hiện bằng GitHub Actions.

    Nếu là SPA (React Router, Vue Router...)Hosting cần được cấu hình fallback về index.html khi người dùng truy cập trực tiếp một route phía client. Vấn đề này khác với lỗi Vite build.

    12 Giải đáp

    Câu hỏi thường gặp

    Không dùng React thì có nên học Vite?

    Có. Vite hỗ trợ JavaScript/TypeScript thuần, React, Vue và nhiều framework khác. Dùng template vanilla là cách tốt để hiểu nền tảng.

    Có cần cài Vite toàn cục bằng npm -g?

    Không cần. Lệnh tạo dự án cài Vite trong devDependencies; script npm run dev có thể gọi binary cục bộ đó. Cách này giúp từng dự án quản lý phiên bản riêng.

    Vite có phải backend hoặc cơ sở dữ liệu không?

    Không. Vite tập trung vào công cụ phát triển/build frontend. Bạn vẫn cần backend hoặc dịch vụ API khi ứng dụng cần đăng nhập, lưu dữ liệu chung hay nghiệp vụ phía server.

    package-lock.json có nên đẩy lên GitHub?

    Với ứng dụng npm thông thường, có. Nó giúp các máy và pipeline cài một tập phiên bản phụ thuộc nhất quán hơn khi dùng npm ci.

    npm run dev và npm start khác nhau thế nào?

    Tên script do dự án định nghĩa trong package.json. Template Vite thường có dev, build, preview; không nhất thiết có start. Xem bằng npm run.

    Có thể dùng pnpm, Yarn, Bun thay npm?

    Có. Vite hỗ trợ nhiều trình quản lý gói. Bài này chọn npm để người mới có một luồng nhất quán. Với mỗi dự án, nên nhất quán lockfile và package manager mà đội ngũ sử dụng.
