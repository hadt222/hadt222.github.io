01NỀN TẢNG

MongoDB là gì?

Hiểu cách MongoDB tổ chức dữ liệu, lúc nào nên sử dụng và khác gì với cơ sở dữ liệu quan hệ.

MongoDB là hệ quản trị cơ sở dữ liệu hướng tài liệu (document database), thuộc nhóm NoSQL. Thay vì lưu dữ liệu thành các hàng với cột cố định, MongoDB lưu những document có cấu trúc gần với JSON.

{ }

Dữ liệu linh hoạt

Document có thể có các trường khác nhau; hỗ trợ đối tượng lồng nhau và mảng.

↗

Mở rộng linh hoạt

Replica set cho tính sẵn sàng cao; sharding giúp phân phối dữ liệu khi có nhu cầu.

⚡

Truy vấn mạnh

Hỗ trợ lọc, sắp xếp, index, aggregation, transaction và nhiều kiểu dữ liệu.

Khi nào nên chọn MongoDB?

Phù hợp với danh mục sản phẩm, hồ sơ người dùng, CMS, nhật ký sự kiện và ứng dụng có cấu trúc dữ liệu phát triển thường xuyên. Với hệ thống quan hệ rất phức tạp, nhiều phép JOIN liên bảng hoặc ràng buộc kiểu SQL, vẫn cần so sánh kỹ với PostgreSQL/MySQL trước khi chọn.

✦
Nguyên tắc quan trọng
MongoDB không có nghĩa là “không cần schema”. Ứng dụng thực tế vẫn cần quy ước trường dữ liệu, validation, index và chiến lược cập nhật rõ ràng.

Document, collection và BSON

Nắm các khái niệm sẽ gặp trong toàn bộ tutorial.

Một document trông như thế nào?

Ví dụ một documentJS
{
  _id: ObjectId("673000000000000000000001"),
  name: "Bàn phím cơ",
  price: 890000,
  active: true,
  tags: ["gaming", "keyboard"],
  specs: { layout: "TKL", switch: "Blue" },
  createdAt: ISODate("2026-11-01T08:00:00Z")
}

BSON (Binary JSON) là định dạng MongoDB dùng để lưu trữ, hỗ trợ thêm các kiểu như ObjectId, Date, Decimal128. Mọi document đều có trường _id; nếu bạn không cung cấp, driver hoặc máy chủ thường sẽ sinh ObjectId.

✦
Chú ý về tiền tệ
Để dễ học, ví dụ dùng số nguyên VND. Với tiền có phần thập phân, nên cân nhắc số nguyên theo đơn vị nhỏ nhất hoặc Decimal128 thay vì lưu trực tiếp bằng số thực nhị phân.

03THIẾT LẬP

Cài đặt và kết nối

Có hai con đường: dùng dịch vụ cloud MongoDB Atlas hoặc chạy MongoDB cục bộ qua Docker.

Cách A · dễ bắt đầu

MongoDB Atlas

  1. Mở MongoDB Atlas và tạo tài khoản.
  2. Tạo cluster thuộc gói miễn phí (nếu khả dụng).
  3. Tạo database user và cho phép địa chỉ IP phù hợp trong Network Access.
  4. Chọn Connect → Shell hoặc Drivers để lấy URI.

Không cần tự cài máy chủ, thuận tiện để học và triển khai.

Cách B · chạy local

Docker

Đã cài Docker? Chạy:

TerminalBASH
docker run -d --name mongo-learning \
  -p 127.0.0.1:27017:27017 mongo:8

docker exec -it mongo-learning mongosh

Chỉ ánh xạ cổng trên máy local; cấu hình demo chưa có xác thực, không dùng làm production.

Kết nối bằng URI

TerminalBASH
# Kết nối local (nếu đã cài mongosh trên máy)
mongosh "mongodb://127.0.0.1:27017"

# Kết nối Atlas: thay URI thật do Atlas cung cấp
mongosh "mongodb+srv://cluster.example.mongodb.net/" --username YOUR_USER

Khi nhập URI của Atlas, hãy dùng URI do Atlas cấp thực tế. Đừng đưa mật khẩu vào Git hoặc ảnh chụp màn hình. MongoDB Compass là công cụ GUI tùy chọn để quan sát collections và thử truy vấn.

✦
Chạy ví dụ ở đâu?
Tất cả lệnh dạng db.products.find(...) trong tutorial chạy trong mongosh. Lệnh bắt đầu bằng docker, npm hoặc node chạy ở terminal.

06CRUD

Create — thêm tài liệu

Thêm một document, thêm nhiều document và tránh trùng khóa định danh.

insertOne / insertManyJS
// Thêm một sản phẩm
db.products.insertOne({
  _id: "p07", name: "Giá đỡ laptop", category: "Phụ kiện",
  price: 320000, stock: 40, rating: 4.2,
  tags: ["office", "desk"], active: true
})

// Thêm nhiều bản ghi
db.products.insertMany([
  { _id: "p08", name: "USB-C Hub", price: 690000, stock: 20 },
  { _id: "p09", name: "Ổ cứng SSD", price: 1590000, stock: 15 }
])

insertOne() trả về acknowledged và insertedId. insertMany() thêm nhiều document trong một lần gọi. _id phải duy nhất; thêm trùng sẽ gặp lỗi E11000 duplicate key.

✦
Nhất quán schema
Ở ví dụ p08 và p09, một số trường được bỏ qua để minh họa schema linh hoạt. Trong ứng dụng thật, nên đảm bảo cấu trúc nhất quán bằng quy ước/validation.

07CRUD

Read — tìm kiếm và lọc dữ liệu

Từ find cơ bản tới toán tử điều kiện, projection, sort và pagination.

Truy vấn cơ bảnJS
db.products.find()                           // Tất cả sản phẩm
db.products.findOne({ _id: "p01" })        // Một document
db.products.find({ category: "Phụ kiện" }) // Lọc theo field

db.products.find({
  category: "Phụ kiện",
  price: { $lt: 1000000 },
  active: true
})

Những toán tử phổ biến

Toán tửÝ nghĩaVí dụ
$eq / $neBằng / khác{ stock: { $ne: 0 } }
$gt / $gteLớn hơn / từ ... trở lên{ price: { $gte: 1000000 } }
$lt / $lteNhỏ hơn / không vượt quá{ stock: { $lt: 20 } }
$in / $ninTrong / ngoài danh sách{ category: { $in: ["Laptop", "Màn hình"] } }
$or / $andĐiều kiện logic{ $or: [{ active: true }, { stock: 0 }] }
$existsField tồn tại{ rating: { $exists: true } }
$regexKhớp mẫu chuỗi{ name: { $regex: "Laptop", $options: "i" } }
Projection · sort · limit · skipJS
// Chỉ trả về name, price; ẩn _id
db.products.find(
  { active: true },
  { _id: 0, name: 1, price: 1 }
)

// Sắp xếp giá tăng dần và giới hạn 3 dòng
db.products.find({}).sort({ price: 1 }).limit(3)

// Trang 2, mỗi trang 3 sản phẩm
db.products.find({}).sort({ _id: 1 }).skip(3).limit(3)

// Mảng tags chứa "office"
db.products.find({ tags: "office" })

// Đếm sản phẩm đang bán
db.products.countDocuments({ active: true })
✦
Về phân trang
skip() thuận tiện với dữ liệu nhỏ, nhưng khi offset lớn có thể tốn chi phí. Với ứng dụng lớn, nên cân nhắc phân trang theo cursor dựa trên trường được index.

Phòng lab: tạo truy vấn bằng bộ lọc

Chọn điều kiện để thấy cú pháp find() và sản phẩm phù hợp với dữ liệu gốc. Demo này chạy ngay trong trình duyệt, không cần kết nối máy chủ.

08CRUD

Update — chỉnh sửa document

Nắm rõ sự khác biệt giữa cập nhật một trường, cập nhật nhiều document và upsert.

Các update operatorsJS
// Đổi giá sản phẩm p01
db.products.updateOne(
  { _id: "p01" },
  { $set: { price: 920000 } }
)

// Tăng tồn kho thêm 5
db.products.updateOne(
  { _id: "p02" },
  { $inc: { stock: 5 } }
)

// Thêm tag mà không lặp giá trị
db.products.updateOne(
  { _id: "p01" },
  { $addToSet: { tags: "hot" } }
)

// Cập nhật nhiều document
db.products.updateMany(
  { category: "Phụ kiện" },
  { $set: { featured: true } }
)
OperatorTác dụng
$setGán hoặc tạo một trường
$unsetXóa một trường
$incCộng/trừ giá trị số
$pushĐẩy phần tử vào mảng
$addToSetThêm vào mảng nếu chưa có
$pullLoại phần tử khỏi mảng
Upsert và $unsetJS
// Nếu chưa có mã p10, MongoDB sẽ insert mới
db.products.updateOne(
  { _id: "p10" },
  { $set: { name: "Balo laptop", price: 550000, stock: 10 } },
  { upsert: true }
)

// Xóa trường featured đã gán ở ví dụ trên
db.products.updateMany({}, { $unset: { featured: "" } })
✦
Phân biệt các kiểu thay đổi
updateOne() với $set chỉ sửa field chỉ định. replaceOne() thay toàn bộ document (trừ _id). Không được nhầm hai thao tác này.

09CRUD

Delete — xóa có kiểm soát

Cách xóa một hoặc nhiều document, cùng quy tắc tránh mất dữ liệu ngoài ý muốn.

deleteOne / deleteManyJS
// Xem trước những gì sẽ bị xóa
db.products.find({ active: false })

// Chỉ xóa một document khớp điều kiện
db.products.deleteOne({ _id: "p06" })

// Xóa toàn bộ sản phẩm tồn kho bằng 0
db.products.deleteMany({ stock: 0 })

// Kiểm tra sau khi xóa
db.products.countDocuments({})
!
Cẩn thận với bộ lọc rỗng
db.products.deleteMany({}) sẽ xóa toàn bộ document trong collection. Hãy luôn chạy find(filter) trước và kiểm tra filter trong ứng dụng thật.

Trong nhiều hệ thống thương mại, thay vì xóa vật lý, bạn có thể dùng soft delete bằng các trường như deletedAt hoặc active: false và điều chỉnh truy vấn tương ứng.

10PHÂN TÍCH

Aggregation pipeline

Biến dữ liệu thô thành thống kê, bảng tổng hợp và kết quả phân tích.

Một pipeline là chuỗi các bước xử lý. Kết quả bước trước đi vào bước sau. Các stage phổ biến gồm $match, $group, $sort, $project, $unwind và $lookup.

$match→$group→$sort→$project
Nhóm và tổng hợp dữ liệuJS
// Thống kê sản phẩm theo danh mục
// Chạy trên dữ liệu gốc để có kết quả dễ kiểm tra
db.products.aggregate([
  { $match: { active: true } },
  { $group: {
      _id: "$category",
      soSanPham: { $sum: 1 },
      giaTrungBinh: { $avg: "$price" },
      giaCaoNhat: { $max: "$price" }
  }},
  { $sort: { giaTrungBinh: -1 } },
  { $project: {
      _id: 0, danhMuc: "$_id", soSanPham: 1,
      giaTrungBinh: { $round: ["$giaTrungBinh", 0] },
      giaCaoNhat: 1
  }}
])

Ví dụ trên: lọc sản phẩm đang bán → nhóm theo category → đếm và tính giá → sắp xếp → định hình kết quả. "$price" là biểu thức tham chiếu tới trường price, khác với chuỗi ký tự "price".

Tách mảng và thống kê doanh thuJS
// Tổng số lượng sản phẩm đã bán (theo từng mã)
db.orders.aggregate([
  { $match: { status: "paid" } },
  { $unwind: "$items" },
  { $group: {
      _id: "$items.productId",
      totalQty: { $sum: "$items.qty" },
      revenue: {
        $sum: { $multiply: ["$items.qty", "$items.unitPrice"] }
      }
  }},
  { $sort: { revenue: -1 } }
])
✦
Tối ưu pipeline
Đặt $match sớm khi có thể giúp giảm dữ liệu đưa qua các stage tiếp theo. Khi lọc theo field đã index, pipeline có thể tận dụng index.

11HIỆU NĂNG

Index và tối ưu truy vấn

Tại sao truy vấn chậm, tạo compound index thế nào và đọc explain ra sao.

Index là cấu trúc giúp MongoDB tìm document mà không phải quét toàn bộ collection. Đổi lại, index chiếm dung lượng và làm tăng chi phí ghi dữ liệu.

createIndex và explainJS
// Index trên một trường
db.products.createIndex({ category: 1 })

// Compound index: lọc category + sắp xếp price
db.products.createIndex({ category: 1, price: 1 })

// Email không được trùng ở customers
db.customers.createIndex({ email: 1 }, { unique: true })

// Xem các index
db.products.getIndexes()

// Xem kế hoạch chạy truy vấn
db.products.find({ category: "Phụ kiện" })
  .sort({ price: 1 })
  .explain("executionStats")

Trong explain, hãy quan sát totalDocsExamined, totalKeysExamined, nReturned và các stage liên quan đến IXSCAN/COLLSCAN. Trên bộ dữ liệu chỉ vài document, MongoDB có thể vẫn chọn collection scan; đừng suy diễn hiệu năng từ demo quá nhỏ.

Không có index phù hợp

MongoDB có thể cần duyệt nhiều document hơn để tìm kết quả.

Index phù hợp

Giảm lượng dữ liệu phải quét với điều kiện và thứ tự truy vấn thích hợp.

✦
ESR cho compound index
Một hướng dẫn hữu ích là Equality → Sort → Range. Thứ tự field trong compound index cần dựa vào truy vấn thực tế, không phải chỉ theo tên field.

12THIẾT KẾ

Thiết kế schema: nhúng hay tham chiếu?

Mô hình dữ liệu hợp lý giúp truy vấn đơn giản, cập nhật an toàn và tránh chi phí thừa.

Embedding

Nhúng dữ liệu

Đơn hàng chứa mảng items vì thường được đọc chung.

Một đơn hàngJS
{
  _id: "o01", customerId: "c01",
  items: [
    { productId: "p01", qty: 2, unitPrice: 890000 },
    { productId: "p02", qty: 1, unitPrice: 450000 }
  ]
}

Ưu điểm: đọc gọn, có tính nguyên tử trong một document. Hạn chế: tài liệu có thể phình to nếu mảng tăng không giới hạn.

Referencing

Tham chiếu dữ liệu

Giữ khách hàng trong customers và lưu customerId vào orders.

Liên kết bằng khóaJS
// customers
{ _id: "c01", name: "An Nguyễn" }

// orders
{ _id: "o01", customerId: "c01", total: 2230000 }

Ưu điểm: giảm lặp dữ liệu thường xuyên cập nhật. Hạn chế: có thể cần thêm truy vấn hoặc $lookup.

Quy tắc thực tiễn: nhúng dữ liệu được đọc cùng nhau và có giới hạn tăng trưởng; tham chiếu dữ liệu dùng chung, thay đổi độc lập hoặc có quan hệ nhiều-nhiều / danh sách tăng mạnh.

✦
Vì sao lưu unitPrice trong order?
Giá sản phẩm có thể thay đổi sau khi khách mua. Lưu unitPrice tại thời điểm đặt hàng giúp giữ chính xác lịch sử đơn hàng; đây là một dạng snapshot có chủ đích.

13THIẾT KẾ

Kết hợp dữ liệu với $lookup

Thực hiện phép nối giữa orders và customers khi cần thêm thông tin khách hàng.

JOIN orders với customersJS
db.orders.aggregate([
  { $lookup: {
      from: "customers",
      localField: "customerId",
      foreignField: "_id",
      as: "customer"
  }},
  { $unwind: "$customer" },
  { $project: {
      _id: 1,
      tenKhach: "$customer.name",
      email: "$customer.email",
      total: 1,
      status: 1
  }}
])

$lookup tạo mảng customer chứa các document khớp khóa. $unwind biến từng phần tử mảng thành một dòng kết quả; nếu không có phần tử khớp, mặc định dòng đó sẽ không được giữ. Muốn giữ đơn hàng không tìm thấy khách hàng, cân nhắc preserveNullAndEmptyArrays: true.

Tổng hợp rồi liên kếtJS
// Phân tích tổng chi tiêu của từng khách hàng
// Chỉ tính các đơn đã thanh toán
db.orders.aggregate([
  { $match: { status: "paid" } },
  { $group: {
      _id: "$customerId",
      tongChiTieu: { $sum: "$total" },
      soDon: { $sum: 1 }
  }},
  { $lookup: {
      from: "customers", localField: "_id",
      foreignField: "_id", as: "customer"
  }},
  { $unwind: "$customer" },
  { $project: { _id: 0, khachHang: "$customer.name",
               tongChiTieu: 1, soDon: 1 } }
])

14CHẤT LƯỢNG DỮ LIỆU

Schema validation

Dữ liệu linh hoạt vẫn có thể được ràng buộc để tránh lỗi kiểu, thiếu trường hoặc giá trị vô lý.

Với MongoDB, $jsonSchema có thể định nghĩa trường bắt buộc và kiểu BSON cho document. Ví dụ tạo collection riêng inventory_checked để không ảnh hưởng dữ liệu mẫu.

Validation với $jsonSchemaJS
db.createCollection("inventory_checked", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["name", "price", "stock"],
      properties: {
        name: { bsonType: "string", minLength: 1 },
        price: { bsonType: ["int", "long", "double", "decimal"], minimum: 0 },
        stock: { bsonType: ["int", "long"], minimum: 0 }
      }
    }
  },
  validationAction: "error"
})

// Hợp lệ
db.inventory_checked.insertOne({ name: "Cáp USB", price: 99000, stock: 10 })

// Không hợp lệ: thiếu stock và price âm
// db.inventory_checked.insertOne({ name: "Cáp lỗi", price: -1000 })

Phân biệt validationAction: "error" (chặn dữ liệu sai) với các chế độ cảnh báo được hỗ trợ. Với collection đã tồn tại, có thể chỉnh quy tắc bằng lệnh collMod. Ngoài server-side validation, ứng dụng vẫn nên xác thực dữ liệu đầu vào.

✦
Lưu ý kiểu số
Khi chạy từ các driver khác nhau, kiểu số thực tế có thể là Int32, Long, Double hoặc Decimal128. Hãy chọn bsonType phù hợp với dữ liệu được ghi.

15ỨNG DỤNG

Kết nối MongoDB từ Node.js

Dùng MongoDB Node.js Driver chính thức để chạy truy vấn từ ứng dụng JavaScript.

Chương này yêu cầu Node.js và MongoDB đang chạy (local hoặc Atlas). Trong một thư mục mới, chạy npm init -y rồi cài thư viện mongodb và dotenv. Tạo file .env để lưu URI:

.env · ví dụ localBASH
MONGODB_URI=mongodb://127.0.0.1:27017
# Với Atlas, dùng URI mongodb+srv://... do Atlas cấp
index.mjs · Node.jsJS
// npm init -y && npm install mongodb dotenv
// Tạo file .env chứa MONGODB_URI=... và không commit lên Git.
// File index.mjs
import "dotenv/config";
import { MongoClient } from "mongodb";

const uri = process.env.MONGODB_URI;
if (!uri) throw new Error("Thiếu MONGODB_URI trong .env");

const client = new MongoClient(uri);

try {
  await client.connect();
  const db = client.db("shop_lab");
  const products = db.collection("products");

  const items = await products
    .find({ active: true, price: { $lt: 2000000 } })
    .project({ _id: 0, name: 1, price: 1 })
    .sort({ price: 1 })
    .toArray();

  console.log(items);
} catch (error) {
  console.error("Lỗi MongoDB:", error.message);
} finally {
  await client.close();
}
TerminalBASH
npm init -y
npm install mongodb dotenv
node index.mjs

MongoClient quản lý kết nối và pool. Trong server thực tế, nên tái sử dụng một MongoClient thay vì tạo kết nối mới cho từng request. Ví dụ đóng kết nối vì đây là script chạy một lần.

!
Không đưa secret lên client
URI có tài khoản/mật khẩu chỉ đặt ở backend hoặc môi trường server tin cậy. Không để URI bí mật trong frontend HTML, JavaScript chạy trên trình duyệt hay kho Git công khai.

16NÂNG CAO

Transactions và tính nguyên tử

Khi nhiều thay đổi dữ liệu cần thành công cùng nhau hoặc cùng thất bại.

Một thao tác ghi trên một document đã có tính nguyên tử. Khi cần giảm tồn kho và tạo đơn hàng trên hai document/collection như một đơn vị công việc, ta dùng transaction.

!
Điều kiện quan trọng
MongoDB standalone không hỗ trợ multi-document transactions. Để chạy ví dụ dưới đây, hãy dùng replica set hoặc sharded cluster phù hợp; Atlas là một lựa chọn. Docker demo ở phần cài đặt là standalone nên không chạy transaction này.
transaction.mjs · minh họa Node.jsJS
// Cần một replica set hoặc sharded cluster (ví dụ Atlas).
// Chạy trong ứng dụng Node.js đã cài mongodb.
import { MongoClient } from "mongodb";

const client = new MongoClient(process.env.MONGODB_URI);
await client.connect();
const db = client.db("shop_lab");
const session = client.startSession();

try {
  await session.withTransaction(async () => {
    const result = await db.collection("products").updateOne(
      { _id: "p01", stock: { $gte: 1 } },
      { $inc: { stock: -1 } },
      { session }
    );
    if (result.matchedCount !== 1) {
      throw new Error("Sản phẩm hết hàng");
    }

    await db.collection("orders").insertOne(
      { _id: "o_tx_01", customerId: "c01", status: "pending",
        items: [{ productId: "p01", qty: 1, unitPrice: 890000 }],
        total: 890000, createdAt: new Date() },
      { session }
    );
  });
  console.log("Transaction thành công");
} finally {
  await session.endSession();
  await client.close();
}

Hàm withTransaction() hỗ trợ quản lý commit/abort và có thể thử lại trong một số tình huống lỗi tạm thời. Trong thực tế, cần xét tính idempotent, khóa đơn hàng trùng, logic kiểm tra tồn kho và cách xử lý lỗi ở tầng ứng dụng.

✦
Đơn hàng mẫu
Mã o_tx_01 là cố định cho mục đích minh họa; chạy lại khi mã đã tồn tại sẽ gây duplicate key và transaction được hủy. Với ứng dụng thật, sử dụng khóa yêu cầu/đơn hàng được thiết kế phù hợp.

17VẬN HÀNH

Bảo mật, sao lưu và triển khai

Checklist cơ bản để một dự án MongoDB không chỉ chạy được mà còn vận hành an toàn.

01Xác thực & phân quyền

Bật authentication, tạo tài khoản ứng dụng với quyền tối thiểu cần thiết; tránh dùng tài khoản quản trị cho API.

02Mạng & TLS

Không mở database trực tiếp ra Internet. Dùng network allowlist/private networking và TLS thích hợp.

03Backup & restore

Thiết lập sao lưu định kỳ, chính sách lưu giữ và kiểm tra khôi phục chứ không chỉ kiểm tra có file backup.

04Replica set

Duy trì tính sẵn sàng bằng nhiều thành viên, bầu primary khi có lỗi; quan sát replication lag.

05Monitoring

Quan sát CPU, RAM, disk, kết nối, truy vấn chậm, index, dung lượng tăng trưởng và cảnh báo.

06Quản lý secret

Không hard-code mật khẩu; dùng environment variables hoặc secret manager và luân chuyển thông tin nhạy cảm.

Replica set và sharding khác nhau thế nào?

Replica set giữ nhiều bản sao dữ liệu nhằm tăng khả năng chịu lỗi và tính sẵn sàng. Sharding chia dữ liệu qua nhiều shard để hỗ trợ quy mô dung lượng/thông lượng lớn hơn. Chúng giải quyết những bài toán khác nhau và thường kết hợp trong kiến trúc lớn.

!
Không triển khai production từ Docker demo
Lệnh Docker ở đầu trang chủ đích chỉ phục vụ local learning. Môi trường thật cần cấu hình authentication, TLS/mạng, backup, monitoring và khả năng chịu lỗi phù hợp.

18GỠ LỖI

Các lỗi thường gặp

Những tình huống dễ gặp nhất khi mới học MongoDB và hướng xử lý nhanh.

ECONNREFUSED 127.0.0.1:27017+

MongoDB chưa chạy, sai cổng hoặc ứng dụng chạy trong container khác. Kiểm tra docker ps, docker logs mongo-learning và URI. Bên trong Docker, 127.0.0.1 trỏ tới chính container đó.

Authentication failed / bad auth+

Kiểm tra username, password, authSource và database user trong Atlas. Nếu mật khẩu chứa ký tự đặc biệt, cần mã hóa ký tự đúng khi đưa vào URI.

MongoServerError: E11000 duplicate key+

Một giá trị vi phạm unique index, thường là _id hoặc email. Đừng chỉ xóa index để xử lý; hãy rà soát quy tắc nghiệp vụ và dữ liệu trùng.

Query trả về mảng rỗng+

Kiểm tra đang dùng đúng database với db, collection name, chữ hoa/chữ thường, kiểu dữ liệu và filter. Thử db.products.findOne() để xác nhận có dữ liệu.

Transaction numbers are only allowed...+

Thường do đang kết nối standalone. Multi-document transaction cần replica set hoặc sharded cluster phù hợp.

Atlas connection timeout+

Kiểm tra URI, Internet/DNS, network access allowlist, firewall và trạng thái cluster. Không dùng mở truy cập mọi IP như giải pháp cố định cho production.
