CHƯƠNG 01

Embedded C++ là gì?

Tư duy đúng trước khi viết dòng code đầu tiên.

Embedded C++ là việc dùng ngôn ngữ C++ để lập trình phần mềm chạy trên phần cứng chuyên dụng như vi điều khiển (MCU), cảm biến thông minh, thiết bị IoT, bộ điều khiển công nghiệp. Khác với chương trình desktop, firmware thường phải đáp ứng ràng buộc RAM, Flash, điện năng, thời gian và độ tin cậy.

Firmware

CHƯƠNG 02

Phần cứng & môi trường

Thiết lập dự án đầu tiên một cách có kiểm soát.

Thiết bị gợi ý

  • Arduino Uno R3 (ATmega328P)
  • Cáp USB phù hợp
  • LED + điện trở 220–330 Ω
  • Nút nhấn, chiết áp 10 kΩ, breadboard
  • Dây nối, máy tính

Phần mềm

  • Arduino IDE 2.x
  • Driver USB nếu board cần
  • Serial Monitor của IDE
  • Trình soạn thảo và Git (khuyến khích)
  • Compiler C++ cho unit test trên PC (tuỳ chọn)

6 bước nạp chương trình

  1. Cài Arduino IDE. Mở Boards Manager và cài gói Arduino AVR Boards nếu cần.
  2. Kết nối board qua USB. Chọn Tools → Board → Arduino Uno và đúng cổng COM/serial.
  3. Tạo sketch. Dán code Blink ở phần 06 vào tệp .ino.
  4. Verify. IDE biên dịch C++ và kiểm tra lỗi.
  5. Upload. Firmware được nạp vào Flash của MCU.
  6. Quan sát. LED tích hợp (thường là D13 trên Uno R3) nhấp nháy.
Phân biệt board. Ví dụ và giá trị ADC/PWM trong tutorial giả định Uno R3 / ATmega328P. Không lấy chân, mức 5 V hay tên thanh ghi của Uno áp lên ESP32, RP2040 hoặc STM32.

Đường đi của một chương trình

main.cpp / sketch.ino→Compiler→Object files→Linker + startup→.elf → .hex/.bin→Flash MCU

File .elf thường chứa symbol/debug information; .hex hoặc .bin chứa dữ liệu phù hợp để nạp thiết bị. Build dùng cross-compiler: compiler chạy trên PC nhưng tạo mã máy cho MCU.

CHƯƠNG 03

C++ cốt lõi cho MCU

Kiểu dữ liệu, tính hằng, enum, tham chiếu và mảng.

Ưu tiên code rõ kiểu, dễ dự đoán và có giới hạn tài nguyên. Hãy dùng <cstdint> cho kiểu số nguyên có kích thước xác định khi công cụ hỗ trợ.

sketch.ino / example.cpp · CPP
#include <cstdint>
#include <array>

constexpr std::uint8_t  kLedPin = 13;
constexpr std::uint32_t kPeriodMs = 500;

enum class Mode : std::uint8_t {
    Off,
    Automatic,
    Manual
};

constexpr std::uint16_t clampAdc(std::uint16_t x) {
    return x > 1023 ? 1023 : x;
}

void setValue(std::uint16_t& value) {  // tham chiếu: không sao chép
    value = clampAdc(value);
}

std::array<std::uint8_t, 4> samples{12, 24, 36, 48};
static_assert(sizeof(std::uint8_t) == 1, "Unexpected byte size");

Thư viện chuẩn không đồng đều. Đoạn code phía trên minh họa C++ có thư viện chuẩn đầy đủ; không nạp nguyên mẫu đó lên Uno R3. AVR thường không có <cstdint> hoặc <array>: với Uno R3, dùng <stdint.h>, các tên uint8_t/uint32_t và mảng tĩnh. Các sketch thực hành ở những phần sau đã theo cách này.

CHƯƠNG 04

Bộ nhớ & vòng đời dữ liệu

Flash, SRAM, stack, heap — nơi mọi byte đều có ý nghĩa.

Trên MCU nhỏ, bộ nhớ được chia thành các vùng có vai trò khác nhau. Tên và vị trí chính xác phụ thuộc kiến trúc và linker script.

FLASH / ROM
.textLệnh máy
.rodataHằng / bảng tra
SRAM
.dataBiến có khởi tạo
.bssBiến zero-init
StackBiến cục bộ / call frames
Heapnew / malloc (nếu dùng)
sketch.ino / example.cpp · CPP
#include <cstdint>

constexpr std::uint16_t kMax = 128; // hằng compile-time
std::uint8_t rxBuffer[64]{};        // vùng lưu trữ tĩnh (.bss)
std::uint16_t samples[4] = {1, 2, 3, 4}; // thường ở .data

void handlePacket() {
    std::uint8_t scratch[16]{};     // thường nằm trên stack
    scratch[0] = rxBuffer[0];
}

Nên ưu tiên

Mảng cố định, buffer tĩnh, stack nhỏ, constexpr, đo stack usage, kiểm tra báo cáo Flash/RAM sau khi build.

Cân nhắc kỹ

new/delete, chuỗi cấp phát động, đệ quy không giới hạn, object quá lớn trên stack, exceptions và RTTI nếu nền tảng hạn chế.

RAII cho phép đối tượng quản lý tài nguyên theo thời gian sống (ví dụ tự nhả mutex trong RTOS). Tuy nhiên constructor của object toàn cục không nên truy cập ngoại vi trước khi clock và phần cứng được khởi tạo.

Không có một quy tắc tuyệt đối “cấm heap”. Heap có thể dùng an toàn trên hệ thống phù hợp nếu cấp phát được kiểm soát. Điều quan trọng là tính xác định, khả năng phục hồi và ngân sách RAM; với MCU rất nhỏ, cấp phát tĩnh thường dễ kiểm chứng hơn.

CHƯƠNG 05

Firmware chạy như thế nào?

Reset, startup, setup/loop và vòng lặp superloop.

Reset→Startup / init RAM→Init C++→main()→Vòng lặp

Thực tế startup còn cấu hình stack, sao chép vùng .data từ Flash sang RAM, zero-init .bss và thực hiện các bước khởi tạo C++ thích hợp. Cụ thể phụ thuộc toolchain và startup code.

sketch.ino / example.cpp · CPP
// Minh hoạ khái niệm bare-metal (không phải sketch Arduino).
int main() {
    initHardware();       // hàm do dự án cung cấp

    while (true) {
        readInputs();     // thu thập input
        updateLogic();    // xử lý state machine
        writeOutputs();   // điều khiển output
    }
}
sketch.ino / example.cpp · CPP
// Trên Arduino, core cung cấp main() và gọi 2 hàm này.
void setup() {
    pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
    digitalWrite(LED_BUILTIN, HIGH);
    delay(500);
    digitalWrite(LED_BUILTIN, LOW);
    delay(500);
}
Ví dụ int main() là mã khung, không biên dịch độc lập vì initHardware/readInputs/... chưa được định nghĩa. Sketch Arduino ngay dưới là ví dụ chạy được với Uno R3.

CHƯƠNG 06

GPIO — bật/tắt LED

Đọc/ghi chân số và mô hình output/input.

GPIO (General Purpose Input/Output) là chân điều khiển số. Ở output, MCU đặt mức logic HIGH/LOW; ở input, MCU đọc mức logic hiện tại. Lưu ý mức điện áp HIGH phụ thuộc board.

sketch.ino / example.cpp · CPP
constexpr uint8_t kLed = LED_BUILTIN;

void setup() {
    pinMode(kLed, OUTPUT);
}

void loop() {
    digitalWrite(kLed, HIGH); // bật LED
    delay(500);              // chặn trong 500 ms
    digitalWrite(kLed, LOW);  // tắt LED
    delay(500);
}
Thử ngay trong trang: công cụ mô phỏng phía dưới chạy trên trình duyệt, không điều khiển phần cứng thật. Kéo thanh thời gian để quan sát chu kỳ bật/tắt.
LED: ON
Mô phỏng Blink500 ms / trạng thái
Chu kỳ đầy đủ = 2 × thời gian mỗi trạng thái.

Input với điện trở kéo lên

sketch.ino / example.cpp · CPP
constexpr uint8_t kButton = 2;

void setup() {
    pinMode(kButton, INPUT_PULLUP);
    Serial.begin(9600);
}

void loop() {
    bool pressed = (digitalRead(kButton) == LOW);
    Serial.println(pressed ? "PRESSED" : "RELEASED");
    delay(100);
}

Với INPUT_PULLUP, đấu nút giữa D2 và GND: nhấn = LOW, thả = HIGH. Tránh để input ở trạng thái floating. Đèn LED rời luôn cần điện trở hạn dòng; không nối tải công suất lớn trực tiếp vào GPIO.

CHƯƠNG 07

Timer & code không chặn

Viết nhiều chức năng chạy song song mà không cần delay.

delay() dễ học nhưng làm logic trong loop() không xử lý nhiệm vụ tiếp theo trong thời gian chờ. Dùng millis() để lập lịch không chặn và so sánh hiệu hai số unsigned để hoạt động qua thời điểm bộ đếm quay vòng.

sketch.ino / example.cpp · CPP
#include <stdint.h>

constexpr uint32_t kIntervalMs = 500;
uint32_t lastToggle = 0;
bool ledOn = false;

void setup() {
    pinMode(LED_BUILTIN, OUTPUT);
    lastToggle = millis();
}

void loop() {
    const uint32_t now = millis();
    if (static_cast<uint32_t>(now - lastToggle) >= kIntervalMs) {
        lastToggle = now;
        ledOn = !ledOn;
        digitalWrite(LED_BUILTIN, ledOn ? HIGH : LOW);
    }

    // Các tác vụ khác vẫn được gọi liên tục.
    // pollButton();
    // readSensor();
}
Thời gian đã trôi quaelapsed = now − lastKiểu nguyên unsigned · khoảng chờ nhỏ hơn chu kỳ tràn
Chi tiết quan trọng: trên Uno R3, millis() dùng giá trị 32-bit và quay vòng sau khoảng 49,7 ngày. So sánh now > last + interval có thể lỗi gần điểm tràn; dạng now - last >= interval là cách thông dụng khi thời gian quan sát nằm trong giới hạn phù hợp.

CHƯƠNG 08

State machine & debounce

Điều khiển hành vi rõ ràng, tránh thao tác lặp do dội phím.

Nút cơ có thể tạo nhiều cạnh điện nhanh khi nhấn. Debounce chỉ chấp nhận trạng thái mới khi tín hiệu giữ ổn định đủ lâu. Mô hình finite state machine (FSM) quản lý các trạng thái rành mạch thay vì nhiều biến boolean khó theo dõi.

sketch.ino / example.cpp · CPP
#include <stdint.h>

constexpr uint8_t kButton = 2;
constexpr uint8_t kLed = LED_BUILTIN;
constexpr uint32_t kDebounceMs = 30;

bool lastReading = false;
bool stablePressed = false;
bool ledOn = false;
uint32_t changedAt = 0;

void setup() {
    pinMode(kButton, INPUT_PULLUP); // nút: D2 -> GND
    pinMode(kLed, OUTPUT);
    lastReading = (digitalRead(kButton) == LOW);
    stablePressed = lastReading;
}

void loop() {
    const uint32_t now = millis();
    const bool reading = (digitalRead(kButton) == LOW);

    if (reading != lastReading) changedAt = now;

    if (static_cast<uint32_t>(now - changedAt) >= kDebounceMs
        && reading != stablePressed) {
        stablePressed = reading;
        if (stablePressed) ledOn = !ledOn; // chỉ đổi khi vừa nhấn
    }
    lastReading = reading;
    digitalWrite(kLed, ledOn ? HIGH : LOW);
}
RELEASEDChờ nút nhấn
nhấn ổn định →
PRESSEDXử lý một sự kiện
thả ổn định →
RELEASEDSẵn sàng lần sau

Khi thiết kế FSM có nhiều trạng thái, dùng enum class State và switch (state). Ưu tiên xử lý sự kiện chuyển trạng thái thay vì thực hiện hành động liên tục mỗi vòng lặp.

CHƯƠNG 09

ADC & PWM

Đọc tín hiệu analog và điều chỉnh độ sáng LED.

ADC biến điện áp analog thành giá trị số; PWM thay đổi tỷ lệ thời gian HIGH/LOW của xung số. Uno R3 có ADC 10-bit mặc định (0..1023), còn analogWrite() mặc định nhận duty value 0..255 tại chân PWM được hỗ trợ.

ADC

A0: đọc chiết áp

0 … 1023 tương ứng điện áp đầu vào so với điện áp tham chiếu ADC.

PWM

D9: điều sáng

0 … 255 tương ứng duty cycle. Trên Uno R3 đây là xung số, không phải DAC thật.

sketch.ino / example.cpp · CPP
constexpr uint8_t kPot = A0;
constexpr uint8_t kPwmLed = 9; // chân PWM Uno R3

void setup() {
    pinMode(kPwmLed, OUTPUT);
}

void loop() {
    const int raw = analogRead(kPot); // 0..1023 trên Uno R3
    const int duty = raw / 4;        // 0..255
    analogWrite(kPwmLed, duty);
    delay(10);
}
Đấu nối: hai đầu chiết áp nối 5V và GND (chỉ với Uno R3), chân giữa nối A0. LED rời nối D9 → điện trở → LED → GND. Chân PWM chính thức của Uno R3: 3, 5, 6, 9, 10, 11. Các board khác có độ phân giải và chân khác nhau.

Ví dụ UART: lệnh ON / OFF qua Serial Monitor

sketch.ino / example.cpp · CPP
#include <string.h>

char command[8]{};
uint8_t length = 0;
bool overflow = false;

void setup() {
    pinMode(LED_BUILTIN, OUTPUT);
    Serial.begin(9600);
}

void loop() {
    while (Serial.available() > 0) {
        const char c = static_cast<char>(Serial.read());
        if (c == '\n' || c == '\r') {
            if (!overflow) {
                command[length] = '\0';
                if (strcmp(command, "ON") == 0)
                    digitalWrite(LED_BUILTIN, HIGH);
                else if (strcmp(command, "OFF") == 0)
                    digitalWrite(LED_BUILTIN, LOW);
            }
            length = 0;
            overflow = false;
        } else if (!overflow) {
            if (length < sizeof(command) - 1)
                command[length++] = c;
            else
                overflow = true; // bỏ cả dòng quá dài
        }
    }
}

Mở Serial Monitor, chọn 9600 baud, bật tùy chọn gửi newline, rồi gửi ON hoặc OFF. Với sản phẩm thực tế, nên thiết kế parser có xử lý lỗi/overflow và timeout rõ ràng.

CHƯƠNG 11 · NÂNG CAO

Interrupt & chia sẻ dữ liệu

Khi ngoại vi cần được phản hồi kịp thời.

Interrupt (ngắt) cho phép MCU tạm chuyển tới hàm phục vụ ngắt (ISR) khi xảy ra sự kiện. ISR nên làm việc ít nhất có thể: đánh dấu sự kiện rồi để loop() xử lý. Vị trí vector ngắt và độ ưu tiên tùy dòng MCU; trên Cortex-M thường quản lý qua NVIC/CMSIS.

sketch.ino / example.cpp · CPP
#include <stdint.h>

constexpr uint8_t kInterruptPin = 2;
volatile uint8_t edgeCount = 0;

void onFallingEdge() {
    if (edgeCount < 255) ++edgeCount; // ISR: rất ngắn
}

void setup() {
    Serial.begin(9600);
    pinMode(kInterruptPin, INPUT_PULLUP);
    attachInterrupt(digitalPinToInterrupt(kInterruptPin),
                    onFallingEdge, FALLING);
}

void loop() {
    noInterrupts();              // bảo vệ thao tác đọc + xóa
    const uint8_t pending = edgeCount;
    edgeCount = 0;
    interrupts();

    if (pending != 0) {
        Serial.print("Edges: ");
        Serial.println(pending);
    }
}

Trong ISR

Đọc dữ liệu tối thiểu, lưu cờ/đếm, xóa cờ ngoại vi theo hướng dẫn của chip; trả quyền điều khiển nhanh.

Ngoài ISR

Log, xử lý dữ liệu, cập nhật màn hình, giao thức và logic có thể mất nhiều thời gian.

volatile không thay thế tính nguyên tử. Nó hữu ích cho truy cập quan sát được/biến chia sẻ với ISR theo quy ước toolchain, nhưng không tự đảm bảo thao tác nhiều bước an toàn, không tạo mutex và không giải quyết đồng bộ đa lõi. Với đa lõi/RTOS cần cơ chế atomics, critical section và quy tắc memory ordering thích hợp. Ví dụ dùng noInterrupts() chỉ minh họa cho Uno R3 một lõi; đồng thời nút cơ cần debounce, nếu không một lần nhấn có thể tạo nhiều cạnh.

Thanh ghi & bare-metal

Đi sâu từ HAL xuống phần cứng, đọc datasheet đúng cách.

Mỗi ngoại vi có các register điều khiển: hướng chân, data output, trạng thái, timer, UART... Với AVR ATmega328P, file header của toolchain đã định nghĩa tên thanh ghi nên không cần tự gõ địa chỉ.

sketch.ino / example.cpp · CPP
// CHỈ dành cho Arduino Uno R3 / ATmega328P.
#include <avr/io.h>

void setup() {
    DDRB |= _BV(DDB5);  // PB5 / D13: output
}

void loop() {
    PORTB |= _BV(PORTB5);   // PB5 = HIGH
    delay(250);
    PORTB &= ~_BV(PORTB5);  // PB5 = LOW
    delay(250);
}

OOP, template & driver

Trừu tượng tốt mà không đánh mất khả năng kiểm soát.

Trong Embedded C++, class giúp đóng gói hành vi và bất biến. Với nhiều thiết kế nhỏ, composition, constexpr và template cố định tại compile-time thường dễ tối ưu; không phải mọi virtual đều xấu, nhưng nên biết chi phí và nhu cầu thực tế.

sketch.ino / example.cpp · CPP
#include <stdint.h>

class Led {
public:
    explicit Led(uint8_t pin) : pin_(pin) {}

    void begin() const { pinMode(pin_, OUTPUT); }
    void set(bool on) const {
        digitalWrite(pin_, on ? HIGH : LOW);
    }

private:
    uint8_t pin_;
};

Led statusLed{LED_BUILTIN}; // constructor chỉ lưu số chân

void setup() {
    statusLed.begin();      // hardware init sau startup
}

void loop() {
    statusLed.set((millis() / 500u) % 2u == 0u);
}

Một template GPIO mức compile-time

sketch.ino / example.cpp · CPP
#include <stdint.h>

template <uint8_t Pin>
struct OutputPin {
    static void init() { pinMode(Pin, OUTPUT); }
    static void write(bool high) {
        digitalWrite(Pin, high ? HIGH : LOW);
    }
};

using StatusLed = OutputPin<LED_BUILTIN>;

void setup() { StatusLed::init(); }
void loop()  { StatusLed::write(true); }

sketch.ino / example.cpp · CPP
#include <stdint.h>

constexpr uint8_t kPot = A0;
constexpr uint8_t kLed = 9;
constexpr uint8_t kButton = 2;
constexpr uint32_t kDebounceMs = 35;
constexpr uint32_t kReportMs = 1000;

bool enabled = true;
bool lastReading = false;
bool stablePressed = false;
uint32_t changedAt = 0;
uint32_t lastReport = 0;
int adc = 0;
int duty = 0;

void serviceButton(uint32_t now) {
    const bool reading = (digitalRead(kButton) == LOW);
    if (reading != lastReading) changedAt = now;

    if (static_cast<uint32_t>(now - changedAt) >= kDebounceMs
        && reading != stablePressed) {
        stablePressed = reading;
        if (stablePressed) enabled = !enabled;
    }
    lastReading = reading;
}

void serviceLed() {
    adc = analogRead(kPot);                 // 0..1023
    duty = enabled ? (adc / 4) : 0;        // 0..255
    analogWrite(kLed, duty);
}

void serviceTelemetry(uint32_t now) {
    if (static_cast<uint32_t>(now - lastReport) < kReportMs)
        return;
    lastReport = now;

    Serial.print("ADC=");
    Serial.print(adc);
    Serial.print(" PWM=");
    Serial.print(duty);
    Serial.print(" Enabled=");
    Serial.println(enabled ? "YES" : "NO");
}

void setup() {
    pinMode(kLed, OUTPUT);
    pinMode(kButton, INPUT_PULLUP);
    lastReading = (digitalRead(kButton) == LOW);
    stablePressed = lastReading;
    Serial.begin(9600);
    lastReport = millis();
}

void loop() {
    const uint32_t now = millis();
    serviceButton(now);
    serviceLed();
    serviceTelemetry(now);
}

  3. Nhấn rồi thả nút: LED tắt; nhấn lần nữa: LED sáng theo chiết áp.
  4. Giữ nút: không liên tục đảo trạng thái.
  5. Log tiếp tục xuất hiện đều khoảng mỗi giây.
  6. Thử cấp nguồn lại khi đang giữ nút; quan sát hành vi khởi tạo.

Tách hàm tính toán thuần C++ khỏi API phần cứng để test nhanh. Ví dụ một hàm ánh xạ ADC sang PWM có thể kiểm tra bằng compiler desktop.

test.cpp · CPP
// test.cpp — chạy với compiler C++17 trên PC.
#include <cassert>
#include <cstdint>

constexpr std::uint8_t adcToPwm(std::uint16_t raw) {
    if (raw > 1023) raw = 1023;
    return static_cast<std::uint8_t>(raw / 4);
}

int main() {
    assert(adcToPwm(0) == 0);
    assert(adcToPwm(512) == 128);
    assert(adcToPwm(1023) == 255);
    assert(adcToPwm(2000) == 255);
}
